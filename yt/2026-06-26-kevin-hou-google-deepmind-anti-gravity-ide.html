TL;DR

구글 딥마인드의 케빈 하우는 에이전트 중심의 AI 개발 플랫폼 Anti-gravity를 소개한다. 이 플랫폼은 에이전트 관리자, AI 에디터, 에이전트 제어 브라우저를 통해 Gemini 3의 지능, 멀티모달성, 도구 사용 능력을 극대화한다. 핵심 혁신은 에이전트의 결과물을 동적이고 시각적으로 표현하는 '아티팩트'로, 개발자와 에이전트가 보다 유연하게 협업하고 병렬적으로 작업을 수행할 수 있게 돕는다.

풀시청 판단

이 영상은 에이전트 기반 AI 개발 도구의 미래와 구글 딥마인드의 제품 개발 철학에 관심 있는 개발자, 제품 관리자, 소프트웨어 엔지니어에게 특히 유용하다. Anti-gravity의 독특한 아키텍처와 '아티팩트' 개념을 통해 차세대 개발 환경이 어떻게 변화할지 엿볼 수 있다. 모델 역량의 발전이 제품 혁신으로 이어지는 과정과 제품-연구 선순환 구조에 대한 통찰을 얻는다.

아쉬운 점:

  • 영상은 Anti-gravity의 제품 개념과 목표에 초점을 맞추며, 기술 스택이나 아키텍처의 깊은 구현 세부 사항은 다루지 않는다.
  • 일부 모델 이름 (Nano Banana, Gemini 3 Pro)은 발표자의 유머러스한 혼동으로 다소 불분명하게 언급되어, 실제 모델 명칭과의 연결이 모호할 수 있다. 이는 발표자의 의도된 유머이기도 하다.
  • 제품이 매우 새롭기 때문에 실제 사용 경험이나 광범위한 채택 사례에 대한 정보는 부족하다.

핵심 내용

Anti-gravity의 세 가지 핵심 기능: 에디터, 브라우저, 에이전트 관리자

Anti-gravity는 AI 개발자 플랫폼으로, 세 가지 주요 인터페이스를 갖춘다. 첫째, [2:32] 개발자가 기존에 익숙한 환경을 제공하는 AI 에디터다. VS Code를 기반으로 하는 이 에디터는 빠른 코드 자동 완성 기능과 에이전트 사이드바를 포함한다. 둘째, [3:11] 에이전트가 웹에 접근하고 조작할 수 있도록 돕는 에이전트 제어 브라우저다. 이 브라우저는 에이전트가 개발자처럼 로그인된 상태로 Google Docs나 GitHub 대시보드에 접근해 문맥을 파악하고, 클릭, 스크롤, JavaScript 실행 등을 통해 애플리케이션을 테스트하며 [4:09] 코드 변경 사항 대신 크롬 녹화 화면을 제공해 검증 가능한 결과를 보여준다. 마지막이자 가장 중요한 기능은 [2:14] 에이전트 관리자로, 에이전트 중심의 중앙 허브 역할을 한다. 이 관리자는 여러 에이전트를 동시에 관리하고, 개발자의 주의가 필요한 터미널 명령 실행과 같은 작업을 [4:49] 인박스에 표시하며 OS 수준 알림을 제공해 여러 작업 간의 멀티태스킹을 돕는다. 미래에는 개발자들이 이 에이전트 관리자에서 더 많은 시간을 보낼 것이라고 예측한다.

모델의 발전이 제품 개발을 이끌다

Anti-gravity의 등장은 [6:11] 기반 모델 역량의 발전 덕분이다. 제품은 모델이 제공하는 기능만큼만 좋다는 원칙 아래, 자동 완성(Copilot), 채팅(RHF), 에이전트로 이어지는 제품 패러다임의 변화는 항상 모델 역량의 도약적 발전(step function)에 의해 촉진됐다. 구글 딥마인드 팀은 [6:39] Gemini 3 모델에 조기 접근하여 제품에 활용할 수 있었다. Gemini 3의 주요 발전 사항은 네 가지다. 첫째, 지능과 추론 능력으로, 지시 이해와 도구 사용에 있어 미묘한 차이를 파악할 정도로 모델이 더 똑똑해졌다. 둘째, [7:31] 더 오래 실행되는 작업을 처리할 수 있게 되어 백그라운드에서 복잡한 작업을 실행할 수 있다. 셋째, 더 긴 사고 시간을 가질 수 있게 되어 문제 해결에 더 많은 시간을 할애한다. 넷째, [7:43] 멀티모달 기능으로, 이미지와 텍스트를 함께 이해하고 생성하는 능력이 대폭 향상됐다. 이러한 모델 역량의 발전은 Anti-gravity와 같은 새로운 에이전트 기반 개발 환경을 가능하게 하는 토대가 된다.

에이전트의 역량 상한선을 높이다

Anti-gravity는 모델의 새로운 역량을 활용하여 에이전트의 가능성을 확장한다. 첫째, 브라우저 사용은 개발 과정에서 [9:27] 코드 외적인 '무엇을 만들지'와 '어떻게 만들지'에 대한 풍부한 문맥과 기관 지식을 에이전트가 얻도록 돕는다. 버그 대시보드, 실험 기록 등에 접근하여 에이전트가 더 깊은 문맥을 이해할 수 있다. 또한, [9:48] 브라우저는 검증 도구로 활용된다. 에이전트는 웹 페이지를 조작하고 DOM을 검색하며, 단순한 코드 변경 내용(diff) 대신 [10:16] 화면 녹화를 제공하여 작업 결과를 시각적으로 검증할 수 있게 한다. 둘째, 이미지 이해 및 생성은 개발자의 멀티모달 경험을 강화한다. 코딩은 텍스트 외에 웹사이트 출력, 아키텍처 다이어그램 등 다양한 시각적 정보를 포함하기 때문이다. [11:15] 디자인 목업 생성 및 반복 작업에서 에이전트와 이미지 공간에서 직접 소통하며 피드백을 주고받을 수 있다. 개발자는 Figma 스타일로 목업에 주석을 달고, 에이전트는 이를 이해하고 [11:47] 디자인을 자동으로 업데이트한다. 이러한 기능은 Nano Banana Pro (발표자가 언급한 이미지 생성 모델)와 같은 기술을 활용해 Anti-gravity 에디터 내에서 구현된다.

동적인 정보 표현 방식 — 아티팩트(Artifacts)

에이전트의 역량이 확장되고 더 길고 복잡한 작업을 수행하게 되면서, 새로운 상호작용 방식의 필요성이 대두되었다. Anti-gravity는 [12:37] 이를 '아티팩트(Artifacts)'라는 개념으로 해결한다. 아티팩트는 [12:51] 에이전트가 생성하는 정보의 동적인 표현으로, 개발자가 에이전트의 작업 과정을 더 쉽게 이해하고 관리할 수 있도록 돕는다. 기존의 긴 대화형 '사고의 사슬(chain of thought)' 방식은 [13:53] 많은 텍스트와 토큰으로 이루어져 파악하기 어려웠지만, 아티팩트는 [14:13] 시각적 표현을 통해 훨씬 직관적인 이해를 가능하게 한다. 발표자는 자신의 발표 자료(PowerPoint)를 아티팩트에 비유한다.

아티팩트의 핵심은 [14:43] 그 동적인 특성이다. 에이전트는 특정 작업에 아티팩트가 필요한지, 그리고 어떤 유형의 아티팩트(예: 마크다운 계획서, 태스크 목록, 아키텍처 다이어그램, 이미지, 화면 녹화, 인어 다이어그램 등)를 생성할지 스스로 결정한다. 예를 들어, [15:10] 작업을 시작할 때 연구를 통해 계획서를 만들고, 미해결 질문을 표면화하여 개발자가 응답하도록 유도한다. 질문이 없다면 에이전트가 스스로 작업을 이어가기도 한다. 이처럼 아티팩트는 에이전트의 자기 조직화 및 사용자 소통을 돕고, [17:03] 에이전트 간의 소통과 장기 기억 저장에도 활용된다.

개발 과정 전반에 걸친 상시적인 피드백 루프

아티팩트 시스템은 개발자가 모델과 보다 유연하게 상호작용하며 피드백을 제공할 수 있게 한다. 구글 독스(Google Docs)나 깃허브(GitHub)에서 영감을 받아, [18:11] 텍스트 기반 아티팩트에 직접 댓글을 달거나 특정 부분을 강조 표시하여 에이전트에게 피드백을 줄 수 있다. 예를 들어, 특정 CSS 프레임워크 대신 바닐라 CSS를 사용하라고 지시하는 식이다. [18:32] 이미지 기반 아티팩트에서는 Figma 스타일로 드래그 앤 드롭 방식을 통해 이미지 내 특정 영역에 주석을 달 수 있다. 이 피드백은 에이전트의 작업 실행 루프를 방해하지 않으면서 자연스럽게 고려된다. 개발자는 작업 진행 중에도 언제든 피드백을 남기고, 에이전트가 이를 반영한 후 완료되면 알림을 받는다.

이러한 상호작용 방식은 [19:30] 병렬 처리 및 오케스트레이션(orchestration)에도 유리하다. 여러 프로젝트를 동시에 진행하거나, 단일 프로젝트 내에서 디자인 목업 반복 작업, API 연구, 앱 개발을 병렬적으로 수행할 수 있다. 아티팩트는 피드백을 제공하는 수단이 되고, 알림은 개발자가 주의를 기울여야 할 때를 알려준다. 물론, [19:57] 에이전트를 완전히 신뢰하지 못하는 경우를 대비해 언제든 에디터로 전환하여 직접 코드를 수정할 수 있는 "탈출구(escape hatch)"도 제공한다.

제품과 연구의 선순환(Flywheel) 구조

Anti-gravity 팀은 [20:51] 스스로 가장 큰 사용자가 되어 제품과 연구 간의 선순환(flywheel) 구조를 만든다. 구글 엔지니어와 딥마인드 연구원들이 Anti-gravity를 내부적으로 사용함으로써, [21:28] 실제 모델 사용 경험을 통해 모델의 약점과 개선점을 즉각적으로 파악할 수 있다. 기존의 평가(eval) 방식으로는 얻기 어려운 심층적인 통찰을 제공하며, 이는 컴퓨터 활용, 이미지 생성, 지시 이해 등 모델의 다양한 측면을 개선하는 데 직접적으로 기여한다.

예를 들어, 컴퓨터 활용 팀과 Anti-gravity 팀은 [22:27] 긴밀하게 협력하여 API 사용상의 격차를 식별하고 데이터 분포 불일치 등을 해결한다. 동시에 Anti-gravity 팀도 에이전트 도구를 개선한다. 이처럼 양측의 조화로운 소통이 없었다면 불가능했을 일이다. 아티팩트 시스템 역시 초기 버전에서는 모델이 제대로 다루지 못하는 개념이었으나, 연구팀과의 협력을 통해 [23:18] 모델이 아티팩트를 효과적으로 처리하는 능력을 점진적으로 향상시켰다. 이러한 순환적 개발 방식이 Anti-gravity가 "중력을 거스르는(defy gravity)" 핵심 동력이라고 케빈 하우는 강조한다.

주요 통찰·논점

"모델 역량이 곧 제품의 한계다"

모델의 발전이 AI 제품 개발의 핵심 동력이라는 철학이 Anti-gravity의 근간을 이룬다. 자동 완성, 채팅, 에이전트로 이어지는 개발 도구의 변화는 모두 기반 모델의 지능, 도구 활용, 멀티모달 능력 등 근본적인 역량 향상에 따라 나타났다. Anti-gravity는 Gemini 3와 같은 최신 모델의 강력한 기능을 최대한 활용하고, 그 한계를 제품 디자인으로 보완하며, 다시 모델 연구를 촉진하는 순환적 관계를 강조한다.

"생성된 정보를 동적이고 시각적으로 표현하는 아티팩트"

아티팩트는 에이전트와의 상호작용 패러다임을 혁신하는 핵심 개념이다. 기존의 길고 복잡한 텍스트 기반 '사고의 사슬' 대신, 아티팩트는 에이전트의 작업 결과물(계획서, 테스트 녹화, 디자인 목업 등)을 동적이고 시각적으로 표현함으로써 개발자가 에이전트의 의도와 진행 상황을 훨씬 직관적으로 이해하고 검증할 수 있게 한다. 이는 에이전트가 단순히 코드를 생성하는 것을 넘어 개발 프로세스 전반에 걸쳐 유능한 협업자로 기능하도록 만든다.

"개발 과정 전반에 걸친 상시적인 피드백 루프"

Anti-gravity는 구글 독스나 Figma와 같은 협업 도구에서 영감을 받아, 아티팩트에 대한 즉각적이고 비방해적인 피드백 시스템을 구축했다. 개발자는 에이전트의 작업 실행을 중단하지 않고도 텍스트나 이미지 위에 직접 주석을 달아 의견을 전달할 수 있다. 이는 에이전트가 개발자의 의도를 실시간으로 반영하며, 여러 에이전트나 작업이 병렬적으로 진행되는 복잡한 개발 환경에서도 개발자가 흐름을 끊지 않고 유연하게 개입하고 조정할 수 있는 핵심 메커니즘이다.

"제품과 연구의 선순환(Flywheel) 구조"

구글 딥마인드의 Anti-gravity 팀은 자신들이 만드는 제품의 가장 큰 사용자가 됨으로써 제품 개발과 모델 연구 간의 강력한 선순환 구조를 만들어낸다. 엔지니어와 연구원들이 매일 Anti-gravity를 사용하며 실제 모델 경험에서 얻는 통찰은 모델의 약점과 개선점을 즉각적으로 식별하고, 이는 다시 모델의 역량 향상으로 이어진다. 이 과정에서 개선된 모델은 Anti-gravity와 같은 제품의 기능적 한계를 높이고 새로운 상호작용 방식을 가능하게 하며, 결과적으로 최첨단 AI 개발 도구를 만들 수 있는 기반이 된다.
