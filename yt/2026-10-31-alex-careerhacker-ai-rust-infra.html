TL;DR

AI가 코딩을 시작하면서 소프트웨어 인프라가 Rust로 빠르게 전환하고 있다. Rust는 C나 C++만큼 빠르면서 메모리 실수를 컴파일러가 미리 막아주는 언어로, 보안 강화와 Python의 GIL(전역 인터프리터 잠금) 한계 극복, 그리고 AI를 통한 코드 전환 비용 절감에 기여한다. 그러나 AI가 변환한 코드는 컴파일러 검사를 넘어 결과 정확성 테스트와 실제 성능 측정의 세 단계를 거쳐야 신뢰할 수 있다.

볼까 말까

이 영상은 AI 시대에 인프라 언어로서 Rust의 중요성이 커지는 이유와 그 실질적인 전환 과정을 심층적으로 다룬다. 특히 AI 에이전트가 Python 코드를 Rust로 옮기는 실험 과정을 생생하게 보여주며, 단순히 속도 향상을 넘어 AI가 생성한 코드의 신뢰성과 검증의 중요성을 깨닫게 한다. 기술적인 깊이와 실용적인 조언을 동시에 제공하여, 새로운 기술 스택 도입을 고민하는 개발자나 기술 리더에게 매우 유용하다.

  • 이런 사람에게: AI 기반 코드 변환, Rust 도입, 또는 기존 Python 인프라의 성능 개선을 고려하는 개발자 및 기술 책임자
  • 아쉬운 점: Rust의 문법이나 구체적인 코드 예시보다는 개념적 설명과 실험 결과에 집중한다.

주제별 정리

Rust는 C/C++만큼 빠르면서 메모리 실수를 미리 막아주는 언어다

Rust는 Mozilla에서 시작하여 2015년에 첫 정식 버전이 나온 프로그래밍 언어로, C나 C++에 버금가는 속도를 내면서도 컴파일러가 메모리 실수를 미리 막아주는 강력한 특성을 지닌다.

  • Rust의 특성: Rust는 코드를 실행하기 전에 기계어로 모두 번역하는 방식을 써서 Python보다 빠르다. C와 C++도 같은 방식이라 빠르지만, Rust는 메모리 실수를 실행 전에 컴파일 에러로 만들어 버그가 아예 실행 파일로 만들어지지 않도록 한다. [1:31]
  • Python과의 관계: Python은 마치 운전대처럼 지시만 내리고, 무거운 계산은 그 밑의 C++와 CUDA 같은 엔진이 수행한다. Rust는 이 엔진 쪽을 대체하는 역할로, PyO3나 maturin 같은 도구를 써서 Rust 라이브러리를 만들면 Python에서 import하여 기존 작업 흐름에 그대로 넣을 수 있다. [2:32]
  • 생태계 내 확산: 이미 OpenAI의 토크나이저 tiktoken과 데이터 검증 도구 Pydantic 등 AI 생태계의 여러 중요한 도구가 핵심 로직에 Rust를 사용한다. Polars는 대규모 데이터 처리에서 pandas를 앞서고, Ruff와 uv는 Python 도구를 더 빠르게 만든다. [2:50]

보안, AI 요구사항, AI 코드 생성 능력이 Rust 전환을 가속한다

소프트웨어 인프라가 Rust로 전환하는 주된 이유는 크게 세 가지다.

  • 보안 취약점 감소: 마이크로소프트는 매년 고치는 보안 버그의 약 70%가 메모리 안전성 문제라고 밝힌다. 구글 Chromium 팀도 비슷한 숫자를 보고했으며, 안드로이드에서 새 코드를 메모리 안전한 언어로 쓰자 2025년에는 메모리 안전 취약점이 전체의 20% 아래로 내려갔다. 구글은 Rust 코드의 메모리 안전 취약점 밀도가 C/C++ 코드의 천분의 일 수준이라고 언급한다. [3:27]
  • Python GIL 회피: Python의 GIL(전역 인터프리터 잠금)은 오랫동안 한 번에 한 스레드만 Python 코드를 실행할 수 있게 하여 병렬 처리 성능을 제한했다. 이 프로젝트의 측정에서도 일반 Python은 스레드를 늘려도 처리량이 크게 늘지 않았다. Rust는 이런 제한이 없어 스레드 간 공유해도 안전한 데이터를 추적하고, 잘못 쓰는 순간 컴파일러가 막아주며 진짜 병렬 코드를 쓸 수 있게 한다. [4:43]
  • AI 번역 비용 절감: 예전에는 수백만 줄의 코드를 다른 언어로 다시 짜는 비용이 너무 커 엄두를 내기 어려웠지만, 이제 AI에게 그 번역을 맡기려는 시도가 시작됐다. DARPA는 2024년에 C 코드를 Rust로 자동 번역하는 TRACTOR 프로그램을 시작했으며, 마이크로소프트의 한 수석 엔지니어는 AI와 알고리즘을 섞어 엔지니어 한 명이 한 달에 100만 줄을 옮기는 것을 연구 목표로 제시했다. [5:17]

AI가 만든 코드도 컴파일러 검사, 결과 테스트, 성능 측정 3단계로 검증해야 한다

AI가 코드를 번역하는 능력이 발전했지만, AI가 생성한 코드의 신뢰성을 확보하기 위해서는 엄격한 검증 절차가 필수적이다.

  • AI 번역 실험: 이 프로젝트는 Claude Code와 Codex 두 AI 에이전트에게 LLM에 들어갈 글을 토큰 번호로 바꾸는 토크나이저 Python 코드를 Rust로 옮기게 했다. 두 에이전트 모두 컴파일 에러 없이 빌드에 성공했고, 원본 Python과 출력이 하나도 다르지 않은지 보는 33개 테스트를 모두 통과했다. [6:20]
  • 성능과 숨겨진 문제: AI가 번역한 Rust 코드는 Python보다 3.8배에서 7.6배까지 빠르게 작동했다. 그러나 스레드 12개가 토크나이저 하나를 함께 쓰자, Codex 버전은 초당 10.7MB로 Python(20.2MB)보다 느려졌다. 이는 코드가 단어 조각 하나를 찾을 때마다 캐시에 자물쇠를 걸었다 푸는 비효율적인 구조 때문이며, 기존 테스트는 결과의 정확성만 보았을 뿐 병렬 처리 성능은 검증하지 않았기 때문이다. [7:32]
  • AI의 수정 능력: 프로젝트는 느려진 성능 숫자와 원인을 Codex에게 그대로 돌려주었고, Codex는 7분 10초 만에 코드를 고쳐 공유 처리량이 초당 146MB로 개선되었다. 이처럼 AI에게 문제점과 구체적인 피드백을 주면 스스로 코드를 개선할 수 있다. [8:12]
  • 컴파일러의 한계와 역할: Rust 컴파일러는 안전하지 않은 데이터 공유를 E0277 에러로 막아주어 빌드를 거부한다. 예를 들어, GIL을 끈 Python이 스레드 병렬 계산에서 에러 없이 틀린 숫자를 내놓는 것과 달리, Rust는 안전한 타입으로 바꾸면 항상 정확한 결과를 낸다. 하지만 컴파일러는 메모리 안전성까지만 검사하므로, 결과의 정확성(테스트)과 실제 성능(측정)은 개발자가 따로 확인해야 한다. [8:29]

순수 Python 반복문이 병목인 곳부터 테스트와 측정 계획을 세워 Rust로 전환하라

Rust는 Python을 대체하는 것이 아니라 C++를 조용히 대체하며 AI 인프라의 기본 선택지가 되고 있다. 따라서 기존 Python 생태계에 Rust를 도입할 때는 전략적인 접근이 필요하다.

  • Rust의 역할 변화: Rust는 AI에서 Python 자체를 대체하기보다, Python 밑에서 무거운 계산을 처리하던 C++를 대체하고 있다. Python으로 일하는 개발자 입장에서는 호출하는 코드에서 import 문 하나만 바꾸는 식으로 Rust의 성능을 활용할 수 있다. [9:32]
  • 전환 가치 판단: Rust로 옮길 가치가 있는 곳은 순수 Python 반복문이 CPU를 붙잡고 있는 곳이다. 예를 들어, 토크나이저 같은 작업이 해당한다. 반대로 이미 NumPy나 C 라이브러리로 돌아가는 계산은 Rust로 옮겨도 얻을 이득이 적거나, 재 측정하기 전에는 효과를 알기 어렵다. NumPy 검색을 Rust로 다시 짰을 때 처음에는 오히려 느려지다가 최적화 후에 빨라지는 경우도 있었다. [10:02]
  • 코드 전환 3단계 기준:
    1. 우선순위: 순수 Python 반복문이 CPU를 많이 쓰는 곳부터 옮기고, 이미 C로 돌아가는 코드는 이득이 있을 때만 수정한다.
    2. 테스트 우선: AI 에이전트에게 작업을 맡기기 전에 원본과 출력을 비교할 테스트를 먼저 만든다.
    3. 반복 측정 및 피드백: 테스트를 통과한 뒤에도 같은 입력으로 다시 측정하고, 성능이 나쁘면 그 숫자를 에이전트에게 돌려주어 개선하게 한다. [10:38]

기억할 것

  1. Rust는 C/C++ 수준의 고성능을 제공하면서도 컴파일러가 메모리 오류를 미리 방지하여 보안 취약점을 획기적으로 줄이는 프로그래밍 언어다.
  2. Python의 전역 인터프리터 잠금(GIL)으로 인한 병렬 처리 한계를 Rust가 해결하며, AI 코드 생성 기술의 발전이 Rust로의 전환 비용을 낮추는 주요 동력이다.
  3. AI가 번역한 코드는 반드시 컴파일러 검사, 결과 정확성 테스트, 실제 성능 측정의 세 단계를 거쳐야 신뢰할 수 있으며, 성능 문제가 발견되면 AI에게 구체적인 피드백을 주어 개선할 수 있다.
  4. Rust 전환은 Python을 대체하는 것이 아니라, Python의 하위 계층에서 C++를 대신하여 핵심 인프라의 성능과 안전성을 강화하는 방향으로 진행된다.
  5. 가장 효율적인 Rust 전환 전략은 CPU 사용량이 높은 순수 Python 반복문부터 시작하고, 전환 전후로 엄격한 테스트 및 성능 측정을 계획하여 실질적인 이점을 확보하는 것이다.

인상적인 대목

  • Python의 비유: Python은 운전대이고, C와 C++, CUDA가 엔진이라는 비유로 Python의 역할과 그 밑단의 고성능 언어의 중요성을 직관적으로 설명한다. [2:20]
  • 마트 비유: Python의 GIL을 계산대가 하나뿐인 마트에 비유하여, 스레드를 늘려도 계산은 한 번에 한 명씩만 하는 상황을 쉽게 이해시킨다. [5:01]
  • 성능 저하의 함정: AI가 번역한 코드가 테스트를 모두 통과했음에도 다중 스레드 환경에서 Python보다 느려질 수 있다는 점은, 단순히 기능적 정확성만으로는 부족하다는 반직관적인 사실을 보여준다. [7:32]
