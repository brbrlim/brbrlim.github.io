이것이 AGI의 시작일까? OpenAI가 공개한 역대급 AI 에이전트! 25분 라이브 데모!

TL;DR

오픈AI(OpenAI)는 기존의 오퍼레이터(Operator)와 딥 리서치(Deep Research) 기능을 통합한 에이전트(agent) 모드를 챗GPT(ChatGPT)에 도입한다. 이 에이전트는 가상 컴퓨터와 다양한 도구(텍스트·시각 브라우저, 터미널, API)를 활용하여 인터넷 검색, UI(User Interface) 상호작용, 코드 실행, 파일 생성 등 복잡한 실제 업무를 스스로 처리한다. 여러 벤치마크에서 기존 모델 대비 뛰어난 성능을 보였지만, 프롬프트 주입 공격과 같은 새로운 보안 위험이 존재하므로 사용자 주의가 필요하다.

풀시청 판단

이 영상은 오픈AI의 새로운 통합 에이전트 기술이 실제 세계의 복잡한 작업을 어떻게 처리하는지 상세한 데모를 통해 보여준다. AI 에이전트 기술의 현재 발전 수준과 오픈AI의 접근 방식을 이해하려는 개발자, 기획자, 혹은 일반 AI 기술 애호가에게 유용하다. AI가 단순 질문 응답을 넘어 스스로 목표를 세우고 다양한 도구를 활용해 문제를 해결하는 과정을 직관적으로 파악할 수 있다.

다만, 기술적인 깊이가 아주 심오하지는 않고 주로 기능 시연과 성과 소개에 집중한다. 모델 훈련 방식(강화 학습(reinforcement learning))에 대한 간략한 언급은 있지만, 구체적인 알고리즘이나 아키텍처 설명은 생략된다. AI 안전성 및 프롬프트 주입 공격에 대한 논의는 중요하지만, 구체적인 기술적 해결책보다는 위험 경고와 사용자 행동 지침에 가깝다.

에이전트가 여러 도구를 통합하여 복합적인 작업을 수행하는 방식과 데모 사례를 확인하고 싶다면 ## 핵심 내용 섹션을, 에이전트의 벤치마크 성능과 잠재적 위험에 대한 오픈AI의 입장을 알고 싶다면 ## 주요 통찰·논점 섹션을 참고하면 된다.

핵심 내용

에이전트 모드: 복잡한 실제 업무를 스스로 처리하는 통합 AI

챗GPT의 에이전트 모드는 이전의 오퍼레이터와 딥 리서치의 개별 기능을 통합하여 사용자의 복잡한 요구사항을 하나의 AI가 처리할 수 있게 한다 [0:43]. 이 에이전트는 스스로 가상 컴퓨터를 사용하고, 다양한 도구를 활용하여 실제 작업을 수행하며, 생각하고 행동하는 과정을 원활하게 전환한다 [0:45]. 예를 들어 터미널을 사용하고 웹을 탐색하며, 스프레드시트나 슬라이드를 생성할 수도 있다 [0:55]. 오픈AI 팀은 이를 "AGI의 순간"을 느끼게 하는 기능이라고 표현한다 [1:14]. 챗GPT 내에서 에이전트 모드를 선택하거나 명령줄에 agent를 입력하면 활성화된다 [1:29].

에이전트의 작동 방식: 가상 컴퓨터와 강화 학습

에이전트는 자신만의 가상 컴퓨터에 접속하여 다양한 도구를 활용한다 [3:00].

  • 두 가지 웹 브라우저: 텍스트 브라우저(text browser)는 딥 리서치처럼 여러 웹 페이지를 효율적으로 읽고 검색하는 데 사용된다 [3:28]. 시각 브라우저(visual browser)는 오퍼레이터처럼 웹 페이지의 UI와 직접 상호작용하며 클릭, 드래그, 폼 작성 등을 수행한다 [3:36].
  • 터미널 및 파일 처리: 터미널(terminal)에 접속하여 코드를 실행하고, 슬라이드 덱이나 스프레드시트와 같은 파일을 생성 및 분석할 수 있다 [3:58].
  • API 연동: 공개 API와 Google Drive, Google Calendar, GitHub, SharePoint 등 사용자가 명시적으로 연결한 사설 API를 호출할 수 있다 [4:08]. 이미지 생성 API(Image Generation API)를 통해 시각 자료도 만든다 [4:22].

에이전트 모델은 강화 학습을 통해 이러한 도구들을 '어떻게' 사용할지뿐만 아니라, 당면한 작업에 따라 '언제' 어떤 도구를 사용할지 학습한다 [4:34]. 훈련 초기에는 여러 도구를 동시다발적으로 사용하려 하지만, 올바르고 효율적인 문제 해결에 대한 보상을 받으면서 시간이 지남에 따라 더 스마트한 도구 선택 능력을 갖추게 된다 [5:02].

협업 능력: 다중 턴 대화, 끼어들기, 사용자 확인

에이전트는 사용자와의 협업에 중점을 두고 설계되었다 [12:29]. 사람에게 복잡한 작업을 맡길 때처럼, 에이전트는 초기 지시를 받은 후 명확한 질문을 하거나 확인을 요청할 수 있다 [12:12]. 장시간이 소요되는 작업 중에도 사용자가 끼어들어 지시를 변경하거나 추가할 수 있으며 [10:39], 에이전트는 이를 인지하고 새로운 지침을 작업 궤적에 반영한다. 또한 중요한 단계(예: 이메일 전송 직전)에서는 최종 확인을 요청하여 잠재적인 실수를 방지하며, 사용자가 직접 에이전트의 환경을 제어(takeover mode)하여 수정할 수도 있다 [12:31].

실시간 시연 1: 결혼식 준비 (의상, 숙소, 선물)

에이전트는 친구의 결혼식 준비를 돕기 위해 복합적인 작업을 수행한다 [1:59]. 구체적으로는 날씨를 고려한 의상 추천, 호텔 검색, 그리고 선물 찾기이다. 에이전트는 먼저 텍스트 브라우저를 사용하여 결혼식 정보를 찾아 날씨를 파악한 다음 [7:57], 시각 브라우저로 정장 이미지를 탐색하고, Booking.com 같은 사이트에서 호텔의 가용성을 확인하며, 선물 아이디어까지 제안한다 [22:03]. 이 모든 과정에서 에이전트는 작업 흐름을 사용자에게 보여주고 최종 구매 단계에서는 사용자의 확인을 요청한다 [21:16].

실시간 시연 2: 팀 스티커 주문 및 신발 검색 추가

에이전트는 팀 마스코트 버니 두들(Bernie Doodle)을 활용한 노트북 스티커 500개 주문을 진행한다 [9:34]. 이 과정에서 이미지 생성 API를 활용하여 버니 두들의 애니메이션 아트를 생성하고, Sticker Mule 웹사이트에서 스티커 주문 절차를 자동화한다 [10:06]. 이와 동시에 진행 중인 작업에 에드워드의 신발 구입 (남자 정장 검은색 구두 9.5 사이즈) 요청을 추가로 받아 처리하는 끼어들기 시연도 성공적으로 보여준다 [10:28].

주요 통찰·논점

에이전트의 자체 평가: 다양한 벤치마크 성능 향상

에이전트는 스스로 자신의 성능을 평가하는 슬라이드를 생성하여 보여준다. 이 슬라이드에는 다음과 같은 벤치마크 결과가 포함된다 [13:20].

  • 인간성 최후의 시험(Humanity's Last Exam): AI의 광범위한 주제 해결 능력을 측정하는 벤치마크이다 [15:20]. 에이전트는 도구 사용 없이도 AI의 원시 지능이 상당하지만, 모든 도구에 접근했을 때 성능이 42%로 거의 두 배 향상된다고 밝힌다 (이전 모델 약 21% 추정) [15:41].
  • 프런티어(Frontiers): 모델의 고급 수학적 추론 능력을 측정하는 벤치마크이다 [16:01]. 오픈AI의 이전 모델(O4 mini, O3)이 파이썬(Python)과 함수 호출을 사용한 것과 달리, 에이전트는 브라우저, 컴퓨터, 터미널 등 모든 도구를 활용하여 27%의 최신 기술(state-of-the-art) 성능을 달성한다 [16:11].
  • 웹 아레나(Web Arena): 웹 에이전트의 실제 웹 작업 해결 능력을 측정하며, 에이전트 모델은 이전 O3 모델보다 향상되었다 [16:30].
  • 브라우즈 컴프(Browse Comp): 찾기 어려운 정보를 검색하고 찾는 브라우징 에이전트 능력을 측정하는 벤치마크이다 [16:44]. 에이전트 모델은 O3 및 딥 리서치를 크게 능가하여 16%의 통과율을 달성한다 [16:56].
  • 스프레드시트 벤치(Spreadsheet Bench): 실제 사용 사례에서 파생된 스프레드시트 편집 능력을 측정한다 [17:10]. LibreOffice와 컴퓨터 도구로 30%의 작업을 해결하며, Excel 파일을 터미널을 통해 직접 접근할 경우 성능이 45%까지 향상된다 [17:21].
  • 내부 뱅킹 벤치마크(internal banking benchmark): 투자 은행 분석가 업무(예: Fortune 500 기업의 3개 재무제표 모델링)를 평가하며, 딥 리서치 및 O3 모델을 크게 능가한다 [17:38].

이러한 결과들을 통해 오픈AI는 에이전트가 벤치마크뿐만 아니라 실제 세상의 복잡한 추론, 브라우징, 문제 해결 능력에서 이전에는 상상하기 어려웠던 수준에 도달했다고 강조한다 [18:06].

새로운 위험: 프롬프트 주입 공격 및 안전 대책

에이전트의 인터넷 사용 능력이 향상됨에 따라 프롬프트 주입 공격(prompt injections)과 같은 새로운 보안 위험이 발생할 수 있다 [18:46]. 예를 들어, 에이전트가 악성 웹사이트에서 신용카드 정보를 입력하라는 지시를 받을 경우, 사용자에게 도움이 되도록 훈련된 에이전트가 이를 따를 가능성이 있다 [18:57]. 오픈AI는 이러한 위험을 완화하기 위해 여러 방어 체계를 구축했다. 의심스러운 웹사이트의 지시를 무시하도록 모델을 훈련하고 [19:15], 에이전트의 활동을 실시간으로 감시하는 다층적인 모니터링 시스템을 운영하여 의심스러운 행동을 감지하면 작업을 중단시킨다 [19:22].

그러나 오픈AI는 이 기술이 최첨단 신기술이며 모든 공격을 막을 수는 없다고 강조한다 [19:38]. 따라서 사용자들에게 에이전트 사용 시의 위험을 인지하고 민감한 정보를 공유할 때 주의할 것을 권고한다. 예를 들어, 신용카드 정보와 같은 민감한 정보는 에이전트에게 직접 주는 대신 테이크오버 모드(takeover mode)를 통해 사용자가 직접 브라우저에 입력할 것을 제안한다 [20:00]. 오픈AI는 이 기술이 AI 역량의 새로운 단계를 보여주지만, 동시에 새로운 유형의 공격과 그에 대한 사회적 적응이 필요하다고 역설한다 [20:20].

AGI를 향한 발걸음: 강력한 신기술이지만 사용자 주의 필요

오픈AI는 이 에이전트가 AGI를 향한 중요한 발걸음이라고 평가한다 [19:16]. 복잡한 작업을 자율적으로 수행하고, 다양한 도구를 통합하며, 실시간으로 사용자와 협업하는 능력은 AI의 잠재력을 크게 확장하는 강력한 기술로 여겨진다 [24:07]. 그러나 이러한 강력한 신기술에는 새로운 위험과 함께 사회 전체의 적응이 요구된다 [24:47]. 오픈AI는 초기에는 강력한 시스템과 많은 경고를 통해 위험을 관리하고, 사용자가 이 기술에 익숙해짐에 따라 점차 규제를 완화해나갈 계획이라고 밝힌다 [24:54].

인상적인 지점

  • "AGI의 순간": 에이전트가 복잡한 작업을 스스로 수행하는 모습을 보며 "AGI의 순간(AGI moments)"을 느낀다는 개발자의 언급 [1:14]은 이 기술에 대한 오픈AI의 높은 기대를 보여준다.
  • 개인적인 고통 해소: 발표자가 "나의 시간을 망치는 일"이라고 표현하며 싫어하는 결혼식 준비와 같은 고통스러운 작업을 에이전트가 대신 해주는 것에 대한 감탄 [7:45]은 에이전트가 실제 사용자의 삶에 어떤 영향을 미칠지 직관적으로 보여준다.
  • AI의 메타(meta) 능력: 에이전트가 스스로 자신의 성능 평가 데이터를 Google Drive에서 가져와 슬라이드를 만드는 시연 [13:10]은 AI가 자신을 분석하고 보고서를 생성하는 메타적인 능력을 보여주는 인상적인 장면이다.
  • 신기술과 위험에 대한 솔직한 접근: 오픈AI는 에이전트가 매우 강력한 기술이지만 프롬프트 주입 공격 같은 새로운 보안 위험을 동반하며, 모든 위험을 막을 수 없으므로 사용자 스스로 경계심을 갖고 조심해야 한다고 솔직하게 경고한다 [19:38]. 이는 AI 기술 개발 기업으로서 책임감 있는 태도를 보여주는 대목이다.
