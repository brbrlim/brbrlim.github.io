TL;DR

커서맛피아 최수민 개발자는 Claude Code를 활용해 100개에 가까운 AI 에이전트를 동시에 운영하며 모든 개발 프로젝트를 진행한다. 그는 Claude Code의 하위 에이전트(sub-agent) 기능을 활용한 효율적인 파이프라인 구축 노하우를 공유하고, 직접 사용할 제품을 만드는 철학을 바탕으로 1인 유니콘 개발자를 목표하며 100개 서비스 출시라는 야심 찬 도전을 이어간다.

핵심 내용

Claude Code가 에이전트 개발에 압도적인 이유 — 맥락 공학과 하위 에이전트

최수민 개발자는 최근 거의 모든 프로젝트를 Claude Code로 진행하며, 이는 다른 도구(Cursor, Anti-gravity)와 비교할 수 없을 정도로 Claude Code의 에이전트 기능이 압도적이기 때문이라고 말한다 [1:14]. 특히 Claude Code는 '맥락 공학(context engineering)'을 극대화하는 데 최적화되어 있다. 기존에는 간단한 프롬프트로 좋은 결과물을 얻는 데 집중했지만, 이제는 제한된 맥락 크기 안에서 다양한 도구를 활용해 더 깊고 복잡한 작업을 지시하는 연구가 중요해졌다 [2:06]. Claude Code는 이러한 맥락 공학을 지원하기 위한 하위 요소(sub-elements)나 기술(skills) 같은 여러 기능을 탁월하게 제공한다 [2:23].

'Moné' 프로젝트 시연: AI 에이전트로 773개 웹 페이지 자동 생성 및 관리

최수민 개발자는 현재 작업 중인 오픈소스 프로젝트 Moné를 시연하며 Claude Code의 활용 방안을 설명한다 [2:42]. Moné는 Mobin과 유사하게 랜딩 페이지의 디자인과 코드를 모두 아카이빙하는 서비스로, 현재 773개의 컨퍼런스 페이지가 등록되어 있다 [3:16]. 이 방대한 양을 혼자 만드는 것은 불가능하므로, Claude Code 에이전트를 활용해 자동화한다.

에이전트 작동 방식은 다음과 같다. 먼저, 모든 지시사항과 에이전트가 작업을 수행할 순서를 MD 파일에 정의한다 [3:51]. 이 에이전트는 웹 페이지에서 이미지를 가져오고, 모든 것을 섹션으로 나누고, 컨벤션을 정리한 다음, 이를 컴포넌트로 변환한다 [3:59]. 여기서 중요한 것은 스크립트(TypeScript 파일)를 활용한다는 점이다. 이미지 파일 등을 직접 생성하면 컨텍스트 소모가 매우 커지므로 [5:04], 스크립트를 통해 스크린샷이나 리소스 추출 로직을 처리하여 불필요한 중간 컨텍스트가 남지 않게 한다 [7:27]. 이 스크립트는 데이터 스크래핑, 분석, 그리고 또 다른 하위 에이전트를 호출하는 역할을 담당한다 [5:19]. 최종적으로 에이전트는 페이지 컴포넌트를 생성하고 레지스트리를 업데이트하여 결과물을 통합하며, 이 모든 과정이 약 한 시간 내외로 완료된다 [5:41].

하위 에이전트(sub-agent) 만드는 법: 프롬프트 아카이빙과 점진적 최적화

하위 에이전트는 Claude Code의 핵심 기능 중 하나로, 컨텍스트 크기 제약 때문에 복잡한 작업을 여러 단계로 분할하는 데 필수적이다 [9:43]. 다른 에이전트 도구에는 이 기능이 없는 경우가 많아 Claude Code가 독보적이라고 한다 [10:08].

하위 에이전트를 만드는 방법은 비교적 간단하다. Claude Code 프로젝트 내 Agents 폴더 안에 마크다운 파일을 생성하고, 이 파일에 Name, Description, Tools, Model 등을 정의하면 된다 [10:45]. 모델은 Opus, Sonnet, Haiku 중 작업의 난이도에 따라 선택할 수 있다 [11:07]. 최수민 개발자는 Sub-Creator라는 스킬을 직접 만들어 하위 에이전트를 자동 생성하는 방식을 주로 사용한다 [11:27]. 이는 Claude Code의 공식 문서를 참고하여 Skill Creator로 만든 스킬이다 [12:24].

그는 프롬프트를 바로 에이전트에 입력하기보다 파일로 작성하여 아카이빙하는 습관을 강조한다 [13:12]. 이렇게 저장된 프롬프트는 나중에 재사용하거나 일부만 변경하여 새로운 작업을 수행할 때 유용하다. 이 프롬프트에 변수를 추가하여 범용성을 높이면 어떤 작업에도 활용할 수 있는 하위 에이전트를 만들 수 있다 [14:19]. 에이전트는 처음부터 완벽하지 않으므로, 결과물을 보고 느리거나 오류가 발생하는 부분을 파악하여 지시를 보강하는 방식으로 점진적으로 최적화해 나간다 [15:26]. 시간이 지날수록 개인에게 완전히 최적화된 에이전트 시스템이 구축된다 [16:16].

다른 에이전트 도구는 흉내 낼 수 없는 Claude Code의 강점

Claude Code가 다른 에이전트 도구와 차별화되는 가장 큰 지점은 바로 에이전트가 다른 에이전트(하위 에이전트)를 호출할 수 있는 기능이다 [18:40]. Cursor 같은 도구는 사용자가 에이전트를 직접 한 번 호출하는 방식이라, 여러 에이전트를 활용하려면 매번 명령을 내려야 한다 [18:46]. 그러나 Claude Code에서는 단일 명령으로 여러 하위 에이전트를 동시에 작동시킬 수 있다 [19:02].

최수민 개발자는 이 기능을 활용해 약 200개의 작업을 한 번에 처리하는 사례를 보여준다 [19:22]. 125개의 이미지에 대한 체크리스트 생성 및 구현 작업을 프롬프트 한 번으로 모두 수행하며 [19:46], 이는 다른 도구로는 절대로 불가능한 일이라고 강조한다 [20:00]. 하나의 명령으로 거대한 트리 구조로 연결된 여러 하위 에이전트가 연쇄적으로 호출되며, 마치 여러 팀이 한 리더 아래서 작동하는 것과 같은 효율을 낸다 [20:11]. 예를 들어, 모든 기능에 대한 브라우저 테스트를 병렬로 진행하거나, 단일 요청의 컨텍스트 부족 문제없이 대규모 작업을 빠르게 처리할 수 있다 [20:43]. 그는 월 200달러짜리 Claude Max 플랜을 한계까지 사용하며 이러한 대규모 작업을 수행하고 있다고 밝힌다 [21:15].

주요 통찰·논점

1인 유니콘 개발자의 야심찬 도전: 100개 서비스 출시 전략

최수민 개발자는 AI를 통한 생산성 극대화의 일환으로 '1인 유니콘 개발자'를 목표하며 100개 서비스 출시라는 야심 찬 도전을 진행 중이다 [26:53]. 이 도전은 "바이브 코딩으로 서비스가 클릭 한 번에 뚝딱 나온다"는 통념의 진정성을 스스로 검증하고 진정한 전문가가 되기 위한 과정이다 [26:47]. 그는 100개 서비스라는 목표가 단순히 개수를 채우는 것을 넘어, 사고방식을 완전히 전환하게 만들었다고 설명한다 [27:32].

5개 서비스를 출시하는 것과 100개 서비스를 출시하는 것은 전략이 완전히 다르다 [27:36]. 100개의 서비스를 한 달에 출시하려면 기존의 일반적인 홍보 전략은 불가능하다 [27:46]. 그는 다음과 같은 자동화 및 확장 전략이 필수적이라고 강조한다. 소셜 미디어 계정 관리를 자동화하거나, 모든 서비스에 검색 엔진 최적화(SEO)를 적용하여 유기적인 트래픽을 모으고, 자동화된 이메일 마케팅 퍼널을 구축해야 한다는 것이다 [27:54]. 이는 미래의 AI 기반 제작자들이 생산량을 극대화할 때 직면할 딜레마를 미리 고민하는 과정이며, 단순 명함 제작 서비스 같은 저품질이 아니라 품질을 타협하지 않으면서도 100개 서비스를 만들겠다는 목표는 매우 도전적이지만 의미 있는 통찰을 줄 것이라고 기대한다 [28:32].

"내가 쓸 제품만 만든다" — 최수민의 제품 개발 철학

최수민 개발자는 "내가 직접 쓰지 않으면 만들지 않는다"는 확고한 제품 개발 철학을 가지고 있다 [30:05]. 이 철학은 두 가지 중요한 이유에 기반한다.

첫째, 1인 개발자로서 기획, 개발, 디자인 등 다양한 역할을 혼자 수행해야 하는 상황에서 [30:17], 자신이 직접 사용하지 않는 제품에 깊이 몰입하고 기획에 많은 시간을 투자하기는 어렵다. 그러나 자신이 사용할 제품이라면, 직접 사용하면서 불편한 점을 빠르고 직관적으로 파악하여 개선할 수 있기 때문에 현재와 같은 1인 개발 환경에서 가장 효율적인 선택이라고 본다 [30:34]. Moné 프로젝트 역시 디자인 레퍼런스나 컴포넌트를 언제든 참고할 수 있도록 본인 필요에 의해 만든 것이다 [31:27].

둘째, 과거 사업 실패 경험에서 얻은 교훈이다 [30:52]. 자신이 만든 패션 쇼핑몰을 직접 이용하지 않고 다른 쇼핑몰(무신사)을 사용했던 경험을 나쁜 신호로 받아들였다 [30:59]. 자신이 직접 사용하는 제품을 만들면, 문제점을 즉시 파악할 수 있어 개발 과정에서 '가드레일' 역할을 해준다는 것이다 [31:11]. 그는 자신이 만든 모든 제품을 실제로 유용하게 사용하고 있으며, Moné에도 사용 중 불편함을 느껴 직접 기능을 추가하기도 했다 [32:01].

AI를 활용한 1인 개발자의 지속 가능한 성장 모델

최수민 개발자는 현재 100개 서비스 도전을 위해 다른 외부 활동(컨설팅, 강연 등)을 최소화하고 프로젝트에 집중하며 '내실을 다지는 기간'을 보내고 있다 [34:03]. 이러한 집중이 가능한 것은 'Booster'라는 SaaS에서 발생하는 꾸준하고 안정적인 자동 수입 덕분이다 [35:32]. 그는 이 수입으로 생활비를 충당하며, 현재 시기를 일종의 R&D 투자 단계로 보고 미래를 위한 전문성 구축에 몰두한다 [35:11].

그는 팀을 꾸려 일하는 것보다 '솔로 아티스트(Solo artist)'로서 활동하는 것에 익숙하며 [37:00], 팀원이 필요하다는 강한 이유를 느끼지 못한다 [37:34]. 위임하는 방식에도 익숙하지 않은 자신의 성향을 고려해, AI를 핵심 무기로 최대한 활용하여 팀 없이도 대규모로 확장(scale up)하는 전략을 추구한다 [38:04]. 그는 개인이 AI를 활용해 프로젝트를 빠르게 만들고 수익화하는 과정을 최대한 자동화하는 데 관심을 가지며, 이러한 방향으로 지속적인 도전을 이어나갈 것이라고 강조한다 [38:37].

인상적인 지점

  • 최수민 개발자는 1인 개발자임에도 불구하고 "AI 에이전트 100개를 한 번에 관리한다"는 초인적인 생산성을 보여준다. 이는 AI를 통해 개인의 역량을 폭발적으로 확장할 수 있다는 것을 증명하는 동시에, 미래의 작업 방식에 대한 청사진을 제시하는 듯하다 [0:29].
  • 그가 현재 진행 중인 '100개 서비스 출시' 도전은 단순히 수치적 목표를 넘어, "5개 서비스를 출시할 때와 100개 서비스를 출시할 때의 고민과 전략은 완전히 다르다"는 말에서 프로젝트 규모에 따른 사고방식의 전환이 얼마나 중요한지 역설한다 [27:36]. 이는 성장을 위한 의도적인 '생각의 확장'이다.
  • "내가 만들었으니 내가 쓴다"는 그의 제품 철학은 직관적이고 단순하지만, 제품 개발의 본질과 직결되는 강력한 원칙이다. 특히 과거 사업 실패 경험과 연결 지어 설명하는 부분에서 그 철학의 진정성과 중요성이 더욱 와닿는다 [30:52].
