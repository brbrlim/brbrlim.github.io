TL;DR

이승민 에어프레미아 랩스 팀 리더는 퇴근 후 1인 개발로 서비스 '티켓탁코'를 만들며 AI 활용법을 단계적으로 발전시켰다. 초기에는 ChatGPT로 기획하고 무료 Claude로 코드를 받던 방식에서, IDE 연동 Cursor를 거쳐, 스스로 컨텍스트를 파악하고 웹 검색까지 하는 Claude Code Max를 사용했다. 궁극적으로는 AI를 '협업 팀원'처럼 인식하고 목표만 공유한 후 대화하며 기획부터 개발까지 전 과정을 함께하는 방식으로 생산성을 극대화했다.

풀시청 판단

AI를 활용한 개발 생산성 극대화에 관심 있는 개발자, 특히 1인 개발자나 사이드 프로젝트를 진행하는 사람에게 유익하다. AI 코딩 도구의 발전 과정과 그에 따른 개발 워크플로우 변화를 구체적인 사례와 함께 제시하며, AI를 단순 코딩 보조 도구가 아닌 '협업 팀원'으로 활용하는 통찰을 얻을 수 있다.

이 영상을 보면 얻을 수 있는 것:

  • AI 활용법의 단계적 진화: 초기 ChatGPT/무료 Claude의 한계부터 Cursor, 그리고 Claude Code Max를 통한 고도화된 AI 활용법까지, AI 코딩 도구의 발전과 함께 개발 프로세스가 어떻게 변화했는지 이해할 수 있다.
  • Claude Code의 강력한 기능: CLI 기반의 Claude Code가 어떻게 파일 시스템 접근, 웹 검색, 서브 에이전트 활용을 통해 개발자의 상상력을 뛰어넘는 결과물을 도출하는지 배울 수 있다.
  • 대화형 협업 방식: AI에게 '목표'를 공유하고 대화하며 기획, 설계, 개발을 함께하는 새로운 협업 패러다임을 접할 수 있다.
  • 실용적인 팁과 워크플로우: AI 사용 시 행동을 명확히 지정하거나 프롬프트 수정 대신 덮어쓰는 팁, Git Worktree를 활용한 병렬 작업, MD 템플릿 사용 등 실제 개발에 적용할 수 있는 노하우를 얻을 수 있다.

이 영상의 약점과 한계:

  • 주관적 생산성 측정: '3배', '10배', '5000배'와 같은 생산성 향상 수치는 화자의 주관적인 체감에 기반하며, 정량적인 측정 지표는 아니다.
  • 특정 AI 도구에 집중: Claude Code 중심의 설명이므로, 다른 AI 코딩 도구 사용자에게는 직접적인 적용이 어려울 수 있다.
  • 일부 기술적 배경 지식 요구: CLI, Worktree, Headless Browser 등 일부 기술 용어에 대한 사전 지식이 없으면 설명 이해가 다소 어려울 수 있다.
  • 초기 AI 활용법의 한계: ChatGPT와 무료 Claude를 사용하던 초기 단계의 제약사항은 현재 시점에서 다소 오래된 정보일 수 있다.
  • MD 업데이트 문제 해결의 추상성: MD 문서를 통한 컨텍스트 제공 방식의 한계(코드 변경 반영 어려움)를 지적했지만, 이를 '대화'로 해결하는 구체적인 메커니즘(AI가 최신 코드 변경을 스스로 파악하는 방식 등)에 대한 설명은 다소 추상적으로 느껴질 수 있다.

핵심 내용

'티켓탁코' 개발 — AI를 활용한 1인 개발 프로젝트

이승민 발표자는 에어프레미아 랩스에서 프런트엔드 팀 리더로 일하며 [0:11] '티켓탁코(Ticketco)'라는 사이드 프로젝트를 혼자서 개발했다. 퇴근 후 작업한 이 서비스는 약 6개월 만에 누적 거래액 1억 원을 달성했으며 [0:42], [36:12] 발표의 주요 내용은 이 프로젝트를 만들면서 AI를 어떻게 활용했는지에 대한 경험 공유다. 프런트엔드나 계약 등 기술적, 사업적 측면보다 AI를 통한 생산성 향상에 초점을 맞춘다.

AI 활용법 1단계: GPT(기획) + 무료 Claude(개발)의 한계

초기에는 ChatGPT(월 20달러)로 기획하고 [1:24], 무료 Claude로 개발하는 방식을 사용했다 [2:33]. ChatGPT에는 구글 문서에 작성한 핵심 요소들만 전달하여 개발자 친화적인 기획 문서를 생성하게 했고 [3:04], 이 문서를 Claude에 넣어 코드 구현을 지시했다 [4:44]. Claude를 사용한 이유는 GPT와 달리 파일 형태로 코드를 제공했기 때문이다 [6:46].

그러나 이 초기 방식은 여러 단점을 안고 있었다. 프롬프트 작성 방식에 따라 결과가 크게 달라지는 '프롬프트 의존성'이 높았고 [7:30], AI가 개발자의 전체 코드 베이스를 모르기 때문에 기존 코드나 유틸리티 클래스를 참조하도록 지시하기 어려웠다 [7:51]. 또한 웹 기반 AI는 IDE와 직접 연동되지 않아 코드를 복사-붙여넣기하고 변수명을 수동으로 수정하는 번거로운 작업이 많았다 [8:33]. 무료 Claude는 5~10회 질의응답 후 5시간을 기다려야 하는 제약도 있었다 [6:55]. 이 단계에서는 반복적인 코딩 작업은 줄었지만, AI가 만든 코드를 프로젝트에 맞춰 수정하는 수작업이 여전히 필요했다 [9:46]. 이때 체감 생산성은 약 3배 정도였다고 한다 [10:14].

AI 활용법 2단계: Cursor Pro — IDE 연동으로 컨텍스트 제공 개선

다음 단계로 개발 환경(IDE)에 직접 연동되는 AI 도구인 Cursor Pro를 사용했다 [10:27]. 여전히 ChatGPT로 기획하고 Cursor로 개발하는 큰 틀은 유지했지만 [10:43], Cursor는 여러 이점을 제공했다. 이전에 일일이 입력해야 했던 컨텍스트를 코드 파일이나 특정 라인을 지정하여 제공할 수 있게 되었고 [11:02], IDE 내에서 직접 코드를 수정해주므로 복사-붙여넣기 과정이 사라져 작업 시간이 단축됐다 [11:13]. 특히 코드 자동 완성 기능을 제공하는 '탭' 기능이 매우 유용했다고 강조했다 [11:23].

그러나 여전히 한계는 있었다. 컨텍스트를 매번 수동으로 지정해야 하는 번거로움이 있었고 [11:43], AI가 개발자의 능력이나 상상력을 뛰어넘는 결과물을 내놓지는 못했다 [12:20]. 개발자의 상상력 범위 내에서 수동 코딩을 대체하는 수준에 머물렀기 때문에, 생산성은 3.5배 정도로 소폭 향상되는 데 그쳤다고 평가했다 [12:53].

AI 활용법 3단계: Claude Code Max — CLI 및 도구 활용으로 AI 능력 확장

다음 단계로 Claude Code Max를 도입하며 AI 활용법이 크게 진화했다. 초기에는 월 200달러 요금제를 사용하다가 현재는 100달러 요금제를 사용한다 [13:02]. Claude Code Max의 핵심은 AI가 스스로 컨텍스트를 찾고 개발자의 상상력을 뛰어넘는 작업을 수행할 수 있게 된 점이다 [13:42].

이는 Claude Code가 CLI(명령줄 인터페이스) 기반으로 작동하기 때문에 가능했다. AI는 터미널 명령어를 통해 프로젝트 내 파일이나 문자열을 직접 검색할 수 있었고 [13:58], 웹 검색 도구(Tools)를 활용하여 외부 정보를 참조하거나 심지어 헤드리스 브라우저를 이용해 인터파크 같은 경쟁 사이트의 UX를 분석하고 최적의 디자인을 스스로 제안하기도 했다 [15:00], [15:20].

이 단계에서는 프롬프트 대신 MD(Markdown) 문서로 컨텍스트를 제공하는 방식을 사용했다 [16:40]. 기술 스택, 디자인 패턴, 백엔드 구성(Superbase), API 함수 구조, DB 도메인 명세 등 프로젝트의 모든 정보를 MD 문서로 작성해두면 [17:06], Claude Code가 이를 읽고 개발자의 패턴을 파악하여 마치 사람과 협업하는 것처럼 개발을 수행했다 [17:33]. 또한 MD 문서로 /chat과 같은 특정 '명령(Commands)'을 정의하거나 [18:10], 역할이 전문화된 '서브 에이전트(Sub-Agents)'(예: UX 에이전트, 프런트엔드 개발자 에이전트)를 MD 문서로 정의하여 [19:26], AI가 작업에 가장 적합한 에이전트를 자동으로 선택하고 여러 에이전트가 협업하여 작업을 진행하게 할 수 있었다 [20:34]. 한 번 작성된 MD 컨텍스트는 계속 재사용할 수 있다는 장점도 있었다 [21:28]. 당시에는 가장 스마트하다고 평가받던 Opus 모델을 활용했으며 [21:45], 이 단계에서의 체감 생산성은 약 10배에 달했다고 밝혔다 [22:25].

AI 활용법 4단계: 대화형 협업 — AI와 목표 공유하는 개발

MD 문서를 통한 컨텍스트 제공 방식은 코드가 변경될 때마다 MD 문서를 업데이트해야 하는 번거로움과 불일치 문제를 야기했다 [22:51]. 이에 대한 해결책으로 발표자는 '대화(Conversation)' 방식을 제안한다 [23:14]. 이는 마치 사람과 대화하듯이 AI와 상호작용하며 개발하는 방식이다.

개발자는 더 이상 자세한 기획 문서 없이 "로또 기능을 개발하고 싶다"처럼 목표만 제시한다 [23:26]. 그러면 AI는 프로젝트를 검토하고 UX, 백엔드, API 등 필요한 사항을 제안하며 [23:46], 개발자는 이에 대해 의견을 주고받으며 세부 사항을 확정한다 [23:50]. 이 대화 과정에서 자연스럽게 컨텍스트가 구축되므로, 별도의 개발 프롬프트 작성이 불필요해진다 [24:43], [24:57]. 결국 '컨텍스트 제공'과 '프롬프트 작성'이라는 AI 활용의 두 가지 큰 부담이 사라지게 된다 [25:16]. AI는 스스로 코드와 파일을 살펴 컨텍스트를 파악하고 [25:50], PR(Pull Request) 단위로 세션을 열어 대화하고 개발한 후 제출하는 방식을 따른다 [25:32].

이러한 변화는 AI에 대한 사고방식 전환으로 이어진다. 개발자는 AI에게 '목표'를 공유하고, AI가 스스로 더 나은 기획과 디자인을 제안하도록 신뢰한다 [26:08], [26:29]. 발표자는 이를 "월 100달러에 기획자, 디자이너, 동료 개발자를 고용한 것 같다"고 비유하며 [26:40], 과장을 섞어 "5000배 정도의 상호작용적 생산성"을 경험했다고 설명했다 [27:04]. 최근에는 Sonnet 4.5 모델이 Opus보다 스마트하면서 토큰 소비가 적게 출시되어 월 200달러에서 100달러 요금제로 낮췄다고 덧붙였다 [27:17].

주요 통찰·논점

AI는 '컨텍스트'를 통해 '협업 팀원'으로 진화한다

AI는 단순 코딩 보조 도구를 넘어선다. CLI 기반의 Claude Code는 파일 시스템 접근, 웹 검색, 서브 에이전트 활용 등 고도화된 기능을 통해 프로젝트 전체의 컨텍스트를 이해하고 능동적으로 문제를 해결하는 '협업 팀원'으로 진화했다. 이러한 AI에게 개발자는 '목표'를 공유하고, AI는 그 목표 달성에 필요한 기획, 설계, 개발 과정을 주도적으로 수행하며 개발자의 상상력을 뛰어넘는 결과물을 제시한다. 이는 AI의 역할을 '단순 지시 수행자'에서 '주체적인 문제 해결 조력자'로 전환하는 핵심적인 통찰을 제공한다.

AI와 함께하는 개발 — 단계별 워크플로우와 주의사항

AI와 효율적으로 협업하기 위한 개발 워크플로우를 제시한다 [31:56].

  1. UX 기획: AI에 목표만 제시하고, AI가 프로젝트를 검토 후 UX, 백엔드 구조 등 필요한 사항을 제안하면 개발자가 대화로 세부 사항을 확정한다 [32:05], [32:42]. AI는 최적의 구조와 리팩토링 용이성을 동시에 고려하여 의견을 제시한다 [32:51].
  2. 프런트엔드 구현: UX 기획에 따라 AI가 화면과 코드를 생성하며, 목(mock) 데이터도 삭제하기 쉬운 형태로 변환해준다 [33:06]. 다만 AI가 생성한 코드라도 개발자의 검토와 리팩토링은 필수적이다 [33:25].
  3. 모델링: DB 테이블, 클래스, 인터페이스 등 핵심 모델링 작업은 중요하므로, 프런트엔드 목업을 보면서 개발자가 직접 수행하는 것이 좋다 [33:38]. DB 조건과 프런트엔드 조건이 다를 수 있기 때문이다 [34:03].
  4. DB 마이그레이션 및 API 연결: 모델링이 완료되면 AI가 DB 스키마 변경을 위한 쿼리 등 스크립트를 생성하고 [34:07], 최종적으로 Jason 데이터를 바탕으로 API를 쉽게 구현할 수 있다 [34:20].

이러한 작업 순서를 지키는 것이 중요한데, 이는 단계별로 문제를 해결하면서 AI가 고려해야 할 경우의 수를 점진적으로 줄여나가 각 단계에서 고품질의 결과물을 얻을 수 있도록 하기 위함이다 [35:11].

인상적인 지점

  • AI가 상상력을 초월하는 순간: AI가 단순히 지시를 따르는 것을 넘어, 웹 검색이나 UX 분석 등 스스로 정보를 찾아 개발자의 상상력을 뛰어넘는 더 나은 기획과 디자인을 제안하는 점이 인상적이다 [13:49], [22:16].
  • AI를 '팀원'으로 인식하는 비유: 월 100달러를 내고 "기획자, 디자이너, 개발자 동료를 고용한 것 같다"는 비유는 AI의 역할을 단순 도구를 넘어선 협업 파트너로 보는 관점의 변화를 극명하게 보여준다 [26:40].
  • 대화형 AI를 오은영 박사에 비유: AI와의 대화형 협업을 "오은영 박사님 같은 답변"에 비유하며 [23:19], 개발자의 목표를 정확히 파악하고 최적의 솔루션을 제시하는 AI의 능력을 직관적으로 표현했다.
  • '목표'에 대한 깊은 고민: AI를 통해 생산성을 극대화하려면 단순히 명령을 내리는 것을 넘어, "목표 달성뿐 아니라 목표에 대해 더 깊이 고민하고, 나머지 작업은 AI에 위임하라"는 조언은 개발자의 역할 변화를 시사한다 [35:53].
  • 사이드 프로젝트의 성공: AI 덕분에 퇴근 후 1인 개발로 시작한 '티켓탁코'가 6개월 만에 누적 거래액 1억 원을 달성할 수 있었다는 점은 AI가 아이디어만 있는 사람도 쉽게 제품을 만들고 수익을 창출할 수 있는 시대를 열었음을 보여준다 [36:06].
