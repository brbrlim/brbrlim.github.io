TL;DR

이 영상은 클로드(Claude)의 MCP(Model Context Protocol) 개념을 설명하고, 사용자가 직접 필요한 MCP를 개발하는 방법을 시연한다. MCP는 LLM(거대 언어 모델)이 다양한 외부 서비스 및 애플리케이션과 소통할 수 있도록 돕는 공통 언어 역할을 하며, 이를 통해 LLM의 한계를 극복하고 맞춤형 AI 비서 에이전트를 구축하는 길이 열린다. 영상은 네이버 학술 정보 검색 MCP를 직접 만드는 과정을 상세히 보여주며, 유튜브 채널 분석 MCP 사례도 함께 소개한다.

풀시청 판단

이 영상은 클로드의 MCP 기능에 관심 있는 개발자 및 비개발자 모두에게 유용하다. MCP의 개념적 가치와 실제 개발 과정을 이해하고 싶은 사람이라면 풀시청할 가치가 충분하다. 특히, LLM을 활용한 개인화된 작업 자동화나 특정 데이터 소스를 기반으로 한 RAG(검색 증강 생성) 시스템 구축에 관심 있다면 많은 통찰을 얻을 수 있다.

얻을 수 있는 것:

  • MCP 개념과 가치 이해: MCP가 LLM과 애플리케이션 간의 공통 언어로서 어떤 역할을 하는지, 그리고 이것이 왜 '판도를 바꾸는' 기술로 여겨지는지 명확하게 이해한다.
  • 맞춤형 MCP 개발 과정 파악: 네이버 학술 정보 검색 MCP를 만드는 과정을 통해 실제 MCP 개발의 전체적인 흐름과 필요한 단계를 파악한다. (특히 [17:54]부터)
  • LLM 활용의 새로운 지평: 기존에 어려웠던 전문 도구 사용이나 특정 데이터 분석 작업을 LLM을 통해 어떻게 자동화하고 효율화할 수 있는지 구체적인 사례(유튜브 분석)를 통해 확인한다. (특히 [36:09]부터)

약점 및 한계:

  • 개발 지식 요구: MCP 개발 시 Git, Node.js, TypeScript, API 문서 이해 등 기본적인 개발 지식을 필요로 한다. 영상은 'Cursor' 같은 AI 개발 도구의 도움을 강조하지만, 완벽한 초보자가 모든 단계를 오류 없이 따라 하기에는 어려움이 있을 수 있다.
  • 빠른 진행 속도: 개발 과정 시연 부분이 빠르게 진행되어, 처음 접하는 사람들은 잠시 영상을 멈추거나 반복해서 봐야 할 수 있다.
  • 클로드 종속성: 소개된 MCP 개발 과정과 활용은 클로드에 특화되어 있으며, 다른 LLM 모델에 적용할 때는 추가적인 학습과 수정이 필요할 수 있다.

일부만 시청한다면:

  • MCP의 개념과 그 가치에 대한 직관적인 이해가 필요하다면 ### MCP: LLM과 앱 사이의 '공통 언어' 역할 [2:35] 및 ### MCP가 제공하는 두 가지 핵심 가치 [9:18] 챕터를 시청한다.
  • 맞춤형 RAG 시스템 구축에 관심 있다면 ### 일반적인 웹 검색 LLM의 한계: ‘원하는 데이터 소스’ 활용의 중요성 [12:23] 및 ### RAG 개념: LLM의 지식 한계를 보완하는 '검색 증강 생성' [15:20] 챕터를 시청한다.
  • 실제 MCP 개발의 전체적인 흐름을 빠르게 보고 싶다면 ### 네이버 학술 정보 검색 MCP 개발 과정 [17:54] 챕터를 통해 개발 환경 설정부터 클로드 연동까지 주요 단계를 확인한다.
  • MCP의 실제 응용 사례와 LLM의 데이터 시각화 능력을 보고 싶다면 ### 유튜브 분석 MCP 사례: 채널 데이터로 인사이트 도출 [36:09] 챕터를 시청한다.

핵심 내용

MCP: LLM과 앱 사이의 '공통 언어' 역할

MCP(Model Context Protocol)는 '모델 컨텍스트 프로토콜'의 약자로, LLM(거대 언어 모델)이 다양한 외부 애플리케이션과 상호작용하기 위한 일종의 공통 규칙 또는 언어를 의미한다 [2:35]. 화자는 이를 사람 간의 소통 방식에 비유해 설명한다. 예를 들어, 일론 머스크와 대화하려면 영어를, 삼성 회장과 대화하려면 한국어를, 손정의 소프트뱅크 CEO와 대화하려면 일본어를 알아야 하듯이 [2:52], 기존에는 Notion, Groc, Gemini, Claude, ChatGPT 같은 각각의 앱이 서로 소통하려면 개별적인 연결 도구가 필요했다 [3:45].

그러나 MCP라는 '공통 언어'가 있다면, Notion이 MCP를 통해 GPT와 연결된 후 이 공통 언어를 사용해 Claude, Gemini, Groc 등 다른 LLM 및 서비스와도 소통할 수 있게 된다 [3:54]. 이는 개발자뿐만 아니라 일반 사용자도 단 몇 줄의 코드를 붙여넣는 방식으로 개발자가 만든 도구를 쉽게 활용할 수 있게 만들며 [4:30], LLM이 특정 전문성을 가진 외부 서비스에 작업을 '위임(delegation)'함으로써 기존의 명확한 한계를 뛰어넘어 성능을 더욱 확장하는 역할을 한다 [4:49]. 결과적으로 MCP는 현재 AI 생태계에서 판도를 바꾸는 역할을 할 잠재력을 가졌다 [5:14].

MCP가 제공하는 두 가지 핵심 가치

MCP는 두 가지 주요 가치를 제공하며 LLM의 활용성을 극대화한다 [9:18].

  1. 다양한 도구와의 통합: MCP는 수많은 커뮤니티에서 개발된 도구들을 LLM과 쉽게 통합할 수 있게 한다. 이는 일반적인 데스크톱 애플리케이션이나 클로드 같은 LLM 서비스에 쉽게 붙여 사용할 수 있어, 사용자들이 각기 다른 서비스들을 단일 LLM 환경에서 활용하도록 돕는다 [6:46]. 예를 들어, 기존 클로드는 웹 검색 기능이 국내에 배포되지 않았지만, Perplexity나 The Brave 같은 웹 검색 도구를 MCP로 연결하여 클로드에서도 웹 검색을 가능하게 한다 [5:38].
  2. 노코드(No Code) AI 에이전트 생성: MCP를 통해 코딩 지식이 없더라도 자신만의 AI 에이전트를 쉽게 만들 수 있다 [9:42]. 이는 개발자가 만든 공통 언어 기반의 도구를 일반 사용자도 쉽게 쓸 수 있게 한다 [4:30]. 화자는 블렌더(Blender)나 피그마(Figma) 같은 전문 툴의 사용법을 배우는 대신 [9:50], LLM에 아이디어를 제시하면 MCP가 해당 툴을 자동 조작하여 모델링이나 편집 작업을 수행할 수 있다고 설명한다 [10:23]. 이는 사람들이 복잡한 툴의 인터페이스나 매뉴얼을 익히는 데 시간을 쓰는 대신, LLM이 그 역할을 대신함으로써 사용자의 아이디어를 바로 현실화하는 생산성 혁신을 가져올 것이라고 강조한다 [11:52]. LLM이 인간과 툴 사이의 MCP가 되는 셈이다 [12:12].

일반적인 웹 검색 LLM의 한계: ‘원하는 데이터 소스’ 활용의 중요성

대부분의 LLM은 자체적인 웹 검색 기능을 제공하지만 [14:17], 이 검색은 개발사에서 제공하는 검색 엔진에 의존하기 때문에 사용자가 원하는 데이터 소스를 직접 지정할 수 없다는 한계가 있다 [16:46]. 예를 들어, ChatGPT나 Perplexity의 웹 검색은 다양한 웹 정보를 가져오지만, 이 과정에서 사용자가 원치 않는 정보가 섞여 결과의 정확성을 떨어뜨릴 수 있다 [14:26].

하지만 MCP를 활용하면 사용자가 직접 원하는 데이터 소스를 지정하여 RAG(검색 증강 생성)를 구축할 수 있다 [13:31]. 영상에서는 위키피디아를 기반으로 RAG를 만드는 사례를 들며, 네이버 스마트스토어, 쿠팡, 혹은 특정 학술 정보 등 '원하는 데이터 소스'로 검색 범위를 제한하여 LLM이 보다 정확하고 오염되지 않은 답변을 생성하도록 만들 수 있다고 설명한다 [14:39]. 이는 LLM이 심층적으로 특정 사이트의 정보를 크롤링하고 검색하여 정확한 정보를 기반으로 답변을 제공하게 함으로써, LLM의 답변 품질을 크게 향상시키는 매우 유용한 기능이다 [15:01].

RAG 개념: LLM의 지식 한계를 보완하는 '검색 증강 생성'

RAG(Retrieval-Augmented Generation)는 '검색 증강 생성'을 의미하며 [15:23], LLM의 고질적인 한계를 해결하기 위해 등장한 기술이다. ChatGPT와 같은 LLM은 특정 시점(예: 2023년 4월)까지의 데이터로 학습되었기 때문에 [15:31], 현재 날씨나 실시간 정보와 같은 최신 지식에 대해서는 정확한 답변을 제공하기 어렵다 [15:40]. RAG는 이러한 LLM의 지식 한계를 보완하기 위해 외부 검색 기능을 활용한다 [16:03].

RAG는 웹 검색(학술 논문, 소셜 검색 등)을 통해 최신 정보를 검색하고 [16:14], 이 검색된 내용을 LLM의 지식에 통합하여 LLM의 성능을 향상시킨다 [16:28]. 이렇게 증강된 LLM은 새로운 지식을 기반으로 더 정확하고 풍부한 응답을 생성할 수 있게 된다 [16:32]. 즉, RAG는 '검색을 통해 LLM의 성능을 개선하고 새로운 결과물을 만들어내는 기술'로 이해할 수 있다 [16:40].

네이버 학술 정보 검색 MCP 개발 과정

영상은 네이버 학술 정보 검색 MCP를 직접 만드는 과정을 상세히 시연한다 [17:54]. 이 MCP를 통해 사용자는 LLM이 네이버 학술 정보라는 특정 데이터 소스에서만 검색하여 더욱 정확하고 특화된 답변을 얻도록 할 수 있다 [17:16].

개발 과정은 다음과 같다.

  1. 개발 환경 설정: 먼저 Git과 Node.js를 다운로드 및 설치한다 [17:59]. Node.js는 제공되는 MCP 템플릿이 TypeScript 환경에서 작동하기 때문에 필요하다 [18:03].
  2. 템플릿 가져오기: PowerShell(Windows) 또는 Terminal(Mac)을 열어 Git Clone 명령어로 미리 만들어진 MCP 템플릿을 가져온다 [18:32].
  3. 코드 편집기 설정: VS Code와 같은 코드 편집기를 다운로드하고, 가져온 템플릿 폴더를 연다 [20:04].
  4. 도구 이름 및 설명 변경: src/const 폴더 내의 파일에서 도구 이름(예: naver doc search)과 설명을 수정한다 [21:03]. 이 이름과 설명은 클로드에서 MCP가 호출될 때 표시된다.
  5. package.json 파일 수정: package.json 파일에서 프로젝트의 이름, 설명, 실행 파일 경로(bin)를 수정하여 전체 프로젝트의 메타데이터를 정의한다 [22:38].
  6. NPM 설치 및 재로드: 터미널에서 npm install 명령어를 실행하여 필요한 의존성 패키지를 설치하고, 코드 편집기를 재로드한다 [24:16].
  7. API 호출자 및 스키마 파일 수정: AI 개발 도구 'Cursor'를 활용하여 제공된 네이버 학술 정보 API 문서를 기반으로 APIcallers.ts, search-schema.ts, main.ts 파일을 수정한다 [25:48]. 이 과정에서 AI가 문서 내용에 맞춰 코드를 자동으로 변경한다.
  8. MCP 실행 확인: npx tsx ./src/main.ts 명령어로 MCP가 정상적으로 실행되는지 확인한다 [29:47]. 이 단계에서 Naver Client ID 및 Secret 설정이 필요하다는 메시지가 나올 수 있다.
  9. 클로드 연동: 클로드 데스크톱 앱의 설정(claude_desktop_config.json)에서 개발자 모드를 활성화하고, MCP 템플릿 폴더의 경로와 main.ts 파일의 정확한 경로를 추가한다 [30:37].
  10. 네이버 API 키 설정: 네이버 개발자 센터에서 애플리케이션을 등록(예: docs-search)하고, 검색 API를 선택한 후, 클라이언트 ID와 Secret을 발급받아 클로드 설정 파일에 추가한다 [32:21]. 이는 네이버 API 요청 시 사용자 인증 및 제한을 위해 필요하다.
  11. MCP 실행 및 테스트: 클로드를 재시작하면 새로 추가된 MCP 도구가 활성화된다 [33:54]. 클로드에 "심리학 분야 학술 논문 10개의 링크를 마크다운 형식으로 정리해달라"고 요청하면, 클로드가 MCP를 호출하여 네이버 학술 정보를 검색하고 결과를 보여준다 [34:15].

유튜브 분석 MCP 사례: 채널 데이터로 인사이트 도출

영상은 네이버 학술 정보 MCP 외에, 개발자가 직접 만든 '유튜브 분석 MCP' 사례를 소개한다 [36:09]. 이 MCP는 유튜브 데이터 API, 유튜브 애널리틱스 API, 유튜브 리포트 API에 연결되어 채널의 상세 데이터를 분석하는 기능을 제공한다 [36:34].

시연에서는 이 MCP를 통해 특정 유튜브 채널의 3개월치 조회수 데이터를 분석하고, 요일별 효과적인 게시 요일, 그리고 다음 콘텐츠 기획에 대한 인사이트를 요청한다 [37:37]. 클로드는 MCP를 호출하여 데이터를 가져온 후, 파이썬 분석 기능을 활용해 요일별 평균 조회수, 평균 참여율, 월별 추이 등을 계산하고 시각화된 보고서 형태로 제공한다 [38:19]. 특히 클로드는 다른 LLM 서비스에 비해 데이터를 다양하고 가독성 높게 시각화하며, 실제 보고서 형식으로 예쁘게 구성하는 강점을 보인다 [39:36].

이 MCP는 단순히 데이터를 나열하는 것을 넘어, 채널 성장률, 시청 시간 추이, 구독자 수 변화 등을 종합적으로 분석하고, 이를 기반으로 '3월 조회수 62.3% 증가', '월요일 조회수 가장 높음', '3월 중순~하순에 조회수 집중 증가'와 같은 핵심 인사이트와 함께 '평균 시청 시간을 계속 늘릴 콘텐츠를 기획해야 한다'는 액션 플랜까지 제시한다 [42:33]. 이를 통해 사용자는 여러 API를 개별적으로 호출하고 분석하는 복잡한 과정 없이도 LLM의 강력한 성능과 MCP의 데이터 통합 능력을 결합하여 깊이 있는 비즈니스 인사이트를 얻고 실행 계획을 세울 수 있다 [44:10].

주요 통찰·논점

LLM의 '위임' 능력: 한계를 넘어 무한한 활용 가능성으로

기존 LLM은 학습 데이터의 한계, 실시간 정보 접근의 어려움 등 명확한 제약을 가졌다 [4:54]. 하지만 MCP를 통해 LLM은 웹 검색(Perplexity), 3D 모델링(Blender), 데이터 분석(YouTube Analytics) 등 특정 전문 분야의 외부 서비스에 작업을 '위임(delegation)'할 수 있게 되었다 [5:05]. 이러한 위임 능력은 LLM이 만능이 아니더라도 마치 만능처럼 보이게 하며, LLM의 잠재력을 무한히 확장하는 핵심적인 변화로 작용한다 [8:38]. 이제 LLM은 단독으로 모든 것을 처리하는 것이 아니라, 필요한 시점에 가장 적합한 외부 도구를 호출하고 활용하는 '지휘자' 역할을 한다.

전문 도구 학습 패러다임의 변화: 인간은 '아이디어'를, LLM은 '사용법'을

MCP의 등장으로 전문 도구를 학습하는 방식 자체가 근본적으로 변하고 있다 [10:51]. 과거에는 사용자가 포토샵, 블렌더, 옵시디언, 노션 같은 복잡한 전문 도구의 인터페이스와 매뉴얼을 익히는 데 많은 시간과 노력을 들여야 했다 [11:01]. 그러나 MCP와 연동된 LLM은 이미 모든 도구의 사용법을 학습했거나, 필요한 매뉴얼을 인간보다 더 효율적으로 감지하여 [11:05], 사용자의 '아이디어'나 '요구사항'만으로 작업을 수행할 수 있게 된다 [11:15]. 이는 사용자가 도구 사용법보다는 무엇을 만들고 싶은지에 대한 창의적인 사고에 집중하게 만들며, 결과적으로 생산성을 크게 향상시킬 것으로 전망한다 [12:00]. LLM이 '인간과 도구 사이의 MCP' 역할을 수행하는 것이다 [12:12].

맞춤형 RAG의 중요성: 오염되지 않은 '원하는 데이터 소스'로 정확성 확보

일반적인 LLM의 웹 검색 기능은 다양한 정보를 제공하지만, 사용자가 원하는 특정 데이터 소스에 한정하여 정보를 얻기 어렵고 원치 않는 정보가 섞여 결과가 '오염'될 수 있다 [14:26]. 반면, MCP를 활용하여 구축하는 맞춤형 RAG는 위키피디아, 네이버 학술 정보, 특정 쇼핑몰 데이터 등 사용자가 명확히 지정한 '오염되지 않은' 데이터 소스에서만 정보를 검색하고 LLM의 답변을 증강시킨다 [13:42]. 이는 LLM이 더욱 정확하고 신뢰할 수 있으며, 사용자의 의도에 완벽하게 부합하는 답변을 제공하게 함으로써, 정보 검색 및 분석의 품질을 한 차원 높이는 중요한 통찰을 제공한다 [14:45].

AI 시대, 개발자의 역설: 코드 없는 세상, 더 중요한 개발 지식

영상은 MCP와 AI 개발 도구 'Cursor'의 도움으로 코딩 부담이 줄어들고 있음을 보여주면서도, 동시에 개발자의 '코딩 지식'과 '개발 지식'이 여전히 매우 중요하다고 강조한다 [45:29]. AI가 자동으로 많은 부분을 처리해 주더라도, 결국 사용자가 무엇을 원하는지 '명확한 의도'를 가지고 '도메인 지식'과 '개발 용어'를 활용하여 AI에 요청하고 [29:04], 그 결과를 이해하고 디버깅하는 능력은 여전히 개발자의 몫이다. 이는 AI가 개발의 진입 장벽을 낮추는 동시에, 더욱 복잡하고 정교한 시스템을 구축하기 위한 개발자의 핵심 역량을 강화해야 하는 역설적인 상황을 제시한다 [45:32].

인상적인 지점

  • MCP의 개념을 일론 머스크, 삼성 회장, 손정의 CEO와 대화하기 위한 '공통 언어' (영어, 한국어, 일본어) 비유로 설명한 점이 매우 직관적이고 인상 깊다 [2:52]. 복잡한 기술 개념을 일상적인 경험에 연결하여 쉽게 이해시킨다.
  • "LLM이 인간과 툴 사이의 MCP가 되었다"는 발언은 LLM의 역할이 단순히 지식 습득을 넘어 도구 사용의 중개자, 나아가 인간의 아이디어를 현실로 구현하는 매개체로 확장되었음을 명확히 보여준다 [12:12]. 이는 미래 작업 방식에 대한 중요한 시사점을 던진다.
  • 클로드의 데이터 시각화 및 보고서 생성 능력을 언급하며, "다른 LLM 서비스들보다 데이터를 훨씬 더 다채롭고 가독성 좋게, 그리고 예쁘게 보고서 형태로 만들어낸다"고 평가한 점은 클로드의 강점을 명확히 보여주는 부분이다 [39:36]. 단순히 정보 제공을 넘어, 정보의 전달 방식까지 고려하는 LLM의 발전상을 엿볼 수 있다.
