How Model Context Protocol (MCP) actually works

Google Cloud Tech7:58게시 2026-06-24브리핑 2026-06-29
AI · 테크#ai#mcp#model-context-protocol#api#google-cloud#developer-tools

TL;DR

Model Context Protocol(MCP)은 Anthropic이 도입한 개방형 표준으로, AI 모델이 외부 도구, 데이터, 컨텍스트와 일관되고 구조화된 방식으로 상호작용하도록 돕는다. 기존 API가 인간이 짠 프로그램을 위해 설계되어 AI 모델의 확률적 추론에 적합하지 않은 문제를 해결하며, 모델이 외부 자원을 동적으로 발견하고 안전하게 사용할 수 있게 하는 추상화 계층 역할을 한다.

풀시청 판단

이 영상은 AI 모델과 외부 시스템의 통합에 어려움을 겪는 개발자나 AI 에이전트 구축에 관심 있는 이들에게 유용하다. MCP의 개념, 필요성, 작동 방식, 그리고 기존 API와의 차이점을 명확하게 설명하며, AI 개발의 복잡성을 줄이는 핵심 패러다임 변화를 이해하는 데 도움을 준다.

영상은 MCP의 도입 배경과 기술적 원리를 체계적으로 설명하고, 구체적인 사례를 들어 개발자 경험이 어떻게 개선되는지 보여준다. 핵심 내용 전반(챕터 3)과 주요 통찰 부분(챕터 4)을 통해 AI 개발 환경의 미래와 MCP의 중요성을 파악할 수 있다. 8분 미만의 짧은 영상이지만, 핵심 내용을 놓치지 않고 밀도 높게 전달하므로 풀 시청하여 흐름을 따라가는 것이 좋다. 이 영상은 MCP의 기본적인 이해를 돕기 위한 소개 영상이며, 심도 있는 기술 구현이나 구체적인 코드 예시보다는 개념 설명에 집중한다는 약점이 있다.

핵심 내용

기존 API의 한계와 MCP의 등장 배경

AI 모델을 기존 도구나 데이터에 연결하려 할 때마다 복잡한 문제가 발생한다 [0:04]. API마다 동작 방식이 다르고, 통합마다 맞춤형 코드가 필요하며, 모델이 변경될 때마다 연결이 끊어지는 일이 흔하다 [0:11]. 이러한 문제들을 해결하기 위해 Model Context Protocol(MCP)이 탄생했다. MCP는 모델이 도구, 데이터, 컨텍스트와 일관되고 구조화된 방식으로 연결되도록 하는 개방형 표준이다 [0:51].

API는 원래 인간이 미리 원하는 것을 정확히 알고 정밀하고 확정적인 요청을 구성할 수 있는 프로그램을 위해 설계되었다 [1:33]. 그러나 언어 모델은 확률적으로 텍스트를 생성하며 [1:45], 불확실한 입력에 대해 추론하고, 무엇을 할지 알기 전에 질문하거나 명확히 하거나 탐색해야 하는 경우가 많다 [1:50]. MCP는 이러한 간극을 메우고, 모델이 사용할 수 있는 자원(함수, 데이터 세트, 문서, 프롬프트 등)을 구조화된 방식으로 발견하고 설명할 수 있도록 한다 [1:59].

MCP의 작동 방식: 클라이언트와 서버의 대화

MCP는 클라이언트와 서버라는 두 가지 측면으로 정의된다 [2:30].

  • 클라이언트: 보통 작업을 수행하려는 언어 모델이나 에이전트 시스템이다. Claude, Gemini 또는 OpenAI나 Google의 체계를 기반으로 구축된 에이전트 등이 해당한다 [2:36].
  • 서버: 모델이 사용할 수 있는 자원을 노출하는 환경이다. 데이터베이스, 파일 시스템, 회사 내부 도구, 문서 검색 엔진 등이 될 수 있다 [2:49].

클라이언트가 서버에 연결하면, 서버는 단순히 데이터를 반환하는 대신 지원하는 기능, 존재하는 자원, 가능한 행동, 필요한 입력 등을 광고한다 [3:03]. 이는 모델이 모든 API나 엔드포인트에 대해 미리 프로그래밍될 필요 없이 동적으로 이를 발견할 수 있게 한다는 의미다 [3:16]. 클라이언트는 '사용 가능한 자원 목록', '이 행동 호출', '이 데이터 검색'과 같은 요청을 보내고 [3:31], 서버는 가능한 것과 발생한 일을 설명하는 구조화된 JSON으로 응답한다 [3:39].

MCP의 핵심 자원 유형

MCP 프로토콜은 모델이 보고 사용할 수 있는 몇 가지 주요 자원 유형을 정의한다 [3:52].

  • 도구(Tools): 모델이 호출할 수 있는 행동이다. 예를 들어 데이터베이스 검색, 이메일 전송, 파일 분석 등이 도구가 될 수 있다 [4:02].
  • 리소스(Resources): 텍스트 문서, 데이터베이스 행, 이미지와 같은 데이터 조각 및 상태 정보이다 [4:12].
  • 프롬프트(Prompts): 특정 작업에 대해 모델이 어떻게 행동해야 하는지를 설명하는 재사용 가능한 템플릿이다 [4:20].
  • 컨텍스트(Context): 모델이 추론 과정에 활용할 수 있는 외부 정보이다. 최근 채팅 기록, 회사 데이터, 사용자 선호도 등이 여기에 포함된다 [4:25].

MCP 클라이언트가 연결될 때 이 모든 자원 목록을 서버에 요청할 수 있다 [4:37]. 각 도구 또는 리소스는 무엇을 하는지, 어떤 입력을 기대하는지, 어떤 출력을 반환하는지 설명하는 메타데이터를 포함한다 [4:42]. 프로토콜은 모든 도구에 걸쳐 일관된 스키마를 강제하여, 모델이 GitHub, CRM, 캘린더 등 어떤 서버를 사용하든 동일한 언어로 소통하게 한다 [4:52].

MCP는 API를 추상화한 상위 계층이다

MCP는 API를 대체하는 것이 아니라, API 위에 존재하는 추상화 계층이다 [5:25]. API는 여전히 존재하지만, MCP가 이를 모델 친화적으로 만든다 [5:29]. MCP 서버는 내부적으로 기존 REST 또는 GraphQL API를 호출할 수 있지만, 모델은 항상 구조화된 MCP 스키마를 통해서만 상호작용한다 [5:32]. 이 스키마는 도구의 발견, 유효성 검사, 실행을 통일된 방식으로 처리하여 MCP를 강력하게 만든다 [5:46]. 덕분에 개발자는 매번 맞춤형 통합 없이도 어떤 준수 모델이든 자신의 시스템을 노출할 수 있다 [5:54].

개인 비서 에이전트 구축 사례로 본 MCP의 이점

개인 비서 에이전트를 구축하여 캘린더 확인, 회의록 정리, 이메일 초안 작성 등의 기능을 구현한다고 가정해보자 [6:02].

  • 기존 방식: Google Calendar, Notion, Gmail API와 개별적으로 통합하고, 각 서비스에 대한 코드를 직접 작성해야 한다 [6:11]. 인증, 호출 제한, 예상치 못한 예외 처리 등을 모두 담당하고, 길고 취약한 시스템 프롬프트를 통해 모델에게 엔드포인트 사용법을 가르쳐야 했다 [6:16].
  • MCP 방식: 각 시스템(캘린더, 노트, 이메일)용 MCP 서버를 구축하거나 설치한다 [6:29]. 각 서버는 자신이 할 수 있는 일을 스스로 광고하고, 모델은 '이벤트 목록 확인', '회의 요약 가져오기', '이메일 보내기'와 같은 사용 가능한 도구들을 자동으로 인식한다 [6:37]. 모델은 어떤 도구를 어떤 순서로 사용할지, 어떤 데이터를 주고받을지 스스로 추론할 수 있다 [6:46]. 개발자는 새로운 도구가 추가될 때마다 연결 코드를 작성할 필요가 없으며 [6:52], 모델은 프로토콜의 일관성 덕분에 상호작용 방법을 알게 된다. 이것이 MCP가 AI 개발에 가져오는 단순성이다 [6:57].

주요 통찰·논점

AI 모델 통합의 패러다임 변화: HTTP가 웹을 통합했듯이

MCP는 AI 모델이 외부 도구 및 데이터와 상호작용하는 방식을 근본적으로 바꿀 잠재력을 가지고 있다. 이는 마치 HTTP가 웹을 통합했듯이 [7:06], MCP가 모델과 도구 간의 소통 방식을 통합할 것이라는 통찰로 이어진다 [7:10]. 이러한 변화는 개발자가 AI 시스템을 구축하는 방식을 표준화하고 단순화하여, 현재의 복잡하고 파편화된 통합 문제를 해결한다. 앞으로 모든 중요한 AI 개발자는 자신의 시스템을 MCP 기반으로 만들 방법을 알아야 할 것이다 [7:17].

모델 중심의 자율적 도구 활용

MCP의 핵심은 AI 모델이 외부 도구를 수동적으로 호출하는 것이 아니라, 능동적으로 탐색하고, 필요에 따라 여러 도구를 연계하여 사용할 수 있는 '지능적인' 능력을 부여한다는 점이다. 서버가 제공하는 기능과 자원 목록을 광고하면, 모델은 각 자원의 메타데이터를 통해 그 기능과 입출력을 이해하고, 자신의 목표 달성에 가장 적합한 도구를 선택하여 실행 순서를 결정한다. 이러한 모델 중심의 자율적인 도구 활용 방식은 기존 API 기반 통합에서는 구현하기 어려웠던 복잡하고 유연한 AI 에이전트의 개발을 가능하게 한다.

인상적인 지점

화자는 MCP의 중요성을 설명하며 "HTTP가 웹을 통합했던 것처럼, MCP는 모델이 도구와 소통하는 방식을 통합하기 시작했다"고 비유한다 [7:06]. 이 비유는 MCP가 AI 개발 분야에서 가져올 변화의 규모와 영향력을 직관적으로 보여주며, 기술 전문가가 아닌 일반인에게도 그 중요성을 쉽게 각인시킨다.
