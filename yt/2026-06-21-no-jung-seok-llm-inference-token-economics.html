EP 96. LLM 추론 인프라와 토큰 경제학

TL;DR

이 영상은 Dwarkesh 팟캐스트의 Reiner Pope 강연을 바탕으로, LLM(대규모 언어 모델) 추론(inference) 인프라의 작동 원리와 비용 경제학을 깊이 분석한다. GPU와 HBM 발전, 트랜스포머 아키텍처, MoE 모델의 희소성(sparsity) 등 하드웨어와 소프트웨어 요소가 추론 시간과 비용에 미치는 영향을 수식과 그래프로 설명하며, GPU 자원 활용을 극대화하기 위한 최적화 전략과 이로 인해 형성되는 토큰 가격 정책의 배경을 탐구한다.

풀시청 판단

이 영상은 LLM 추론 시스템의 기술적, 경제적 깊이를 이해하고자 하는 개발자, 엔지니어, 하드웨어 아키텍트, 그리고 LLM 서비스 사업가들에게 매우 유용하다. 특히 NVIDIA의 최신 GPU(Blackwell, NVL72 등)가 LLM 서빙 아키텍처와 모델 설계에 어떻게 영향을 미치는지, 그리고 DeepSeek V3/V4와 같은 효율적인 모델들이 어떤 방식으로 비용을 절감하는지 궁금하다면 시청할 가치가 크다.

영상은 LLM 추론의 핵심 개념인 prefill과 decode, KV 캐시, t_compute(연산 시간)와 t_memory(메모리 시간)의 관계를 수식과 그래프를 통해 설명한다. MoE(Mixture of Experts)의 희소성(sparsity)이 배치(batch) 처리 효율성에 미치는 영향, drain time 개념을 통한 최적 연산 주기 결정 과정, 그리고 vLLM의 PagedAttention 같은 최적화 기술의 중요성을 다룬다.

다만, 내용은 상당히 전문적이고 어려우므로, AI/ML 및 하드웨어 인프라에 대한 기본적인 지식이 없는 시청자에게는 매우 이해하기 어려울 수 있다 [6:41]. Dwarkesh 강연의 전반부 30분 정도만 다루므로, 더 깊은 내용은 Dwarkesh 원본 강연을 직접 참고해야 한다 [1:33:22]. 수많은 개념과 수식이 빠르게 전개되므로 높은 집중력을 요구한다.

핵심 내용

LLM 추론의 부상과 DeepSeek의 효율성

최근 LLM 발전의 초점은 모델 훈련(training)에서 추론(inference)으로 이동했다 [1:16]. Claude Code, Codex 같은 AI 모델의 활용이 늘면서, 긴 컨텍스트(context)와 많은 추론 토큰(reasoning token)을 처리하는 수요가 급증했기 때문이다 [0:35]. DeepSeek V3/V4 같은 최신 모델은 이러한 추론 효율성을 획기적으로 높였다. 컨텍스트 길이가 길어져도 연산(computation)은 3분의 1, 메모리 사용은 10분의 1로 줄여 대규모 모델 서빙을 효율적으로 만든다 [2:26]. 이러한 기술적 진보는 에이전트(agent) 시대의 중요한 기반이 된다 [2:41].

NVIDIA 하드웨어의 발전이 추론 성능에 미치는 영향

NVIDIA의 GPU는 LLM 추론 인프라의 핵심이다. 젠슨 황(Jensen Huang)이 강조하듯, GPU 칩, HBM(고대역폭 메모리), 그리고 이들을 연결하는 NVLink 및 NVSwitch 같은 인프라스트럭처의 발전은 모델 성능과 직결된다 [3:05]. 특히 Blackwell NVL72는 기존 8개 GPU 연결에서 72개 GPU 연결로 확장되었고 [3:56], 개별 GPU의 메모리 용량(HBM)도 H100의 80~100GB에서 GB200/GB300의 192~288GB로 크게 늘었다 [4:04]. 한 랙(rack)에 20TB에 달하는 HBM이 탑재되며 [4:32], 이러한 하드웨어 구조는 5T, 10T 규모의 초대형 모델을 효율적으로 서빙할 수 있게 한다 [5:41]. AI 모델 아키텍처는 이러한 하드웨어의 발전을 반영하여 함께 진화한다 [9:19].

트랜스포머의 추론 과정: Prefill과 Decode, KV 캐시

트랜스포머 모델의 추론 과정은 크게 두 단계로 나뉜다. 사용자가 긴 프롬프트를 입력하면, 모델은 이를 병렬로 한 번에 처리하는 prefill 단계를 거친다 [11:21]. 이 과정에서 각 토큰에 대한 KV 캐시(Key-Value cache)가 생성된다 [11:31]. 이후 모델은 이전 토큰을 기반으로 다음 토큰을 하나씩 순차적으로 예측하는 decode 단계를 반복한다 [11:56]. KV 캐시는 모델이 이전 컨텍스트를 기억하고 재활용하는 데 필수적이며, 각 트랜스포머 블록(block)마다 존재한다 [13:30].

트랜스포머 블록은 주로 어텐션(attention)과 MLP(다층 퍼셉트론, Multi-Layer Perceptron) 또는 FFN(피드포워드 신경망, Feed-Forward Network)으로 구성되며 [21:06], 이 블록들을 여러 층으로 쌓아 올려 연산을 반복한다. 각 블록을 통과하며 정보가 잔차 연결(residual stream)을 통해 갱신된다 [24:21]. 마지막으로 LM 헤드(LM head)에서 다음 토큰의 확률을 계산하고 가장 높은 확률의 토큰을 출력한다 [25:45]. 출력된 토큰은 다시 입력으로 들어가 다음 decode 단계에 활용되는 자기 회귀(autoregressive) 방식이다 [22:47].

MoE(Mixture of Experts)와 모델의 희소성(Sparsity)

최신 LLM은 MoE 아키텍처를 MLP 블록에 적용하여 효율성을 높인다 [21:46]. MoE는 전체 파라미터(parameter) 규모는 매우 크지만, 특정 토큰을 처리할 때 그중 일부 전문가(expert)만 활성화하여 연산에 참여시키는 방식이다 [26:34]. 예를 들어, DeepSeek V4는 384개의 전문가 중 6개 정도만 활성화한다 [22:01]. 이는 모든 파라미터를 계산하는 밀도 높은(dense) 모델에 비해 연산량을 크게 줄여, 대규모 모델의 t_compute(연산 시간)를 효율적으로 만든다 [21:53]. 동시에 모델의 전체 파라미터 크기를 키워 학습 능력을 향상시키는 효과도 있다 [26:24].

LLM 추론 시간의 제약: 연산(t_compute)과 메모리(t_memory)

LLM이 결과를 생성하는 데 걸리는 총 시간(T)은 t_compute(연산 시간)와 t_memory(메모리 시간) 중 더 오래 걸리는 시간, 즉 max(t_compute, t_memory)에 의해 결정된다 [35:15].

  1. t_compute (연산 시간): 모델의 활성 파라미터 수(N_active)와 배치(batch) 크기(B, 한 번에 처리하는 토큰 수)에 비례하고, GPU의 연산 능력(FLOPs/초)에 반비례한다 [46:02]. MoE의 희소성(sparsity)은 N_active를 줄여 t_compute를 효율적으로 만든다 [46:07].
  2. t_memory (메모리 시간): 모델의 전체 파라미터 수(N_total)와 KV 캐시의 크기(배치 크기 B, 컨텍스트 길이 L)에 비례하고, HBM의 메모리 대역폭에 반비례한다 [48:21]. 모델 가중치를 메모리에 로딩하는 시간과 KV 캐시를 불러오는 시간이 모두 포함된다 [48:21].

추론 시 GPU 자원 활용률을 극대화하려면 t_compute와 t_memory가 균형을 이루는 최적의 배치 크기(B)를 찾아야 한다 [1:11:43].

최적 배치 크기(Batch Size) 결정과 토큰 경제학

t_compute와 t_memory의 관계를 그래프로 그리면, 배치 크기가 작을 때는 메모리 사용량이 연산량을 압도하여 메모리 제약(memory-bound)이 발생하고, 배치 크기가 클 때는 연산량이 메모리 사용량을 압도하여 연산 제약(compute-bound)이 발생한다 [1:05:42]. 이 두 가지 제약이 만나는 지점에서 최적의 처리량(throughput)을 얻을 수 있다 [1:11:47].

대략적인 추정치에 따르면, GPU의 FLOPs / 메모리 대역폭 비율은 하드웨어 발전에도 불구하고 약 300의 배율을 유지하고, 최적 배치 크기(B)는 이 배율에 모델의 희소성(예: 1/8)을 곱한 값으로 결정된다 [1:14:29]. DeepSeek V3의 희소성을 예로 들면, 최적 배치 크기는 약 2400(300 * 8) 토큰이 된다 [1:15:08]. 배치 크기가 커지면 한 번의 연산 사이클에 더 많은 사용자의 워크로드를 태울 수 있어, GPU 자원의 경제성을 극대화하고 토큰당 비용을 절감할 수 있다 [1:16:47].

20밀리초 연산 사이클과 추론 최적화 기술

LLM 추론은 보통 20밀리초(ms) 단위로 한 연산 사이클이 돈다 [1:18:02]. 이 20ms는 최신 GPU의 HBM 메모리가 전체 데이터를 한 번 읽어내는 시간, 즉 드레인 시간(drain time)과 밀접한 관련이 있다 [1:19:50]. GPU는 이 20ms 주기 동안 prefill과 decode 워크로드를 혼합하여 최대한 많은 사용자 요청을 처리하려 노력한다 [1:22:53].

vLLM의 PagedAttention 기술은 사용자마다 다른 길이의 KV 캐시를 효율적으로 관리하여 메모리 낭비를 줄이고 GPU 활용도를 높인다 [52:20]. 또한, chunked prefill과 같은 기술로 긴 prefill 워크로드를 여러 조각으로 나누어 decode 워크로드와 함께 처리함으로써, GPU 자원이 놀지 않도록 최적화한다 [1:24:30]. 이러한 인프라 엔지니어링 능력은 프론티어 랩(frontier lab)들의 핵심적인 해자(moat)가 된다 [1:26:40].

컨텍스트 길이와 토큰 경제학의 연관성

LLM 서비스의 API 가격은 이러한 추론 인프라의 경제성을 반영한다 [1:30:16]. 컨텍스트 길이가 짧은 워크로드(예: "안녕하세요" 같은 간단한 질문)는 한 랙당 더 많은 사용자를 동시에 처리할 수 있어 비용이 저렴하다 [1:27:13]. 그러나 컨텍스트 길이가 200K 토큰을 넘어서면 KV 캐시 때문에 메모리 병목 현상이 심화되고, 메모리 제약(memory-bound) 구간에 진입하여 연산(compute) 자원이 남아돌게 된다 [1:28:06]. 이 경우, 동일한 GPU 자원으로 처리할 수 있는 사용자 수가 현저히 줄어들기 때문에, 코딩 지원과 같이 긴 컨텍스트를 요구하는 워크로드는 API 가격이 더 높아진다 [1:29:21].

주요 통찰·논점

하드웨어는 모델의 그림자이자 가능성이다

하드웨어의 발전은 단순히 모델 훈련 속도를 높이는 것을 넘어, LLM의 아키텍처와 서빙 방식까지 결정하는 중요한 요소다 [9:19]. NVIDIA의 Blackwell NVL72와 같은 최신 GPU 아키텍처는 GPU 간 통신 대역폭과 HBM 용량을 비약적으로 늘려, 과거에는 상상하기 어려웠던 5T, 10T 규모의 모델을 효율적으로 추론할 수 있는 기반을 제공한다 [4:04]. 즉, 모델은 하드웨어가 제공하는 제약과 가능성 위에서 그 형태와 규모를 결정하며 발전한다.

추론 최적화는 LLM 서비스의 핵심 해자(moat)다

이제는 단순히 좋은 모델을 개발하는 것을 넘어, 그 모델을 사용자에게 가장 효율적이고 경제적으로 제공하는 추론 인프라 기술이 LLM 기업의 핵심 경쟁력으로 부상했다 [1:26:40]. vLLM의 PagedAttention이나 chunked prefill 같은 기술들은 GPU 자원(특히 HBM)의 활용률을 극대화하여 토큰당 비용을 절감하고, 더 많은 사용자를 동시에 서빙할 수 있게 한다. 이러한 고도화된 엔지니어링 능력은 오픈소스 모델이나 경쟁사가 쉽게 따라잡기 어려운 진입 장벽, 즉 해자(moat)를 형성한다 [1:27:05].

LLM 서비스의 토큰 가격은 하드웨어 경제학의 결과다

프론티어 랩들이 제시하는 LLM API의 토큰 가격은 단순한 시장 경쟁의 결과가 아니라, 내부적으로 추구하는 토큰 경제학(token economics)을 반영한다 [1:30:16]. GPU 자원의 연산 능력과 메모리 대역폭의 한계, 그리고 모델의 희소성(sparsity)과 컨텍스트 길이에 따른 연산 제약(compute-bound) 또는 메모리 제약(memory-bound) 현상이 가격 정책에 그대로 녹아 있다 [1:29:21]. 예를 들어, 200K 토큰을 기점으로 컨텍스트 길이가 길어질수록 가격이 비싸지는 것은, 긴 컨텍스트 처리가 메모리 병목을 유발하여 GPU 자원 활용 효율을 떨어뜨리기 때문이다 [1:28:46].

인상적인 지점

  • Dwarkesh 팟캐스트가 갑자기 칠판 판서 형태로 포맷을 변경하여 강의하는 방식이 인상적이다 [0:12]. 덕분에 복잡한 수식과 그래프를 시각적으로 이해하는 데 큰 도움이 된다.
  • GPU의 FLOPs와 HBM 메모리 대역폭의 비율이 하드웨어 발전에도 불구하고 약 300으로 유지된다는 어림짐작(guesstimation) [1:14:29]과 이로부터 최적 배치 크기(B)를 계산하는 방식 [1:15:08]이 흥미롭다.
  • NVIDIA의 최신 랙 시스템 NVL72에 총 40TB(HBM 20TB + CPU RAM 20TB)의 메모리가 탑재된다는 사실 [54:33]은 대규모 모델 서빙의 물리적 규모를 짐작하게 한다.
  • DeepSeek V4 모델이 Claude Sonnet보다 뛰어나다고 평가하는 진행자의 사용 경험 [1:16:00]은 실제 모델 선택에 대한 통찰을 제공한다.
  • LLM 추론의 한 사이클이 20밀리초(ms)로 설정된 것이 HBM이 전체 메모리를 한 번 읽어내는 시간(drain time)과 관련되어 있다는 설명 [1:20:50]은 하드웨어와 소프트웨어의 긴밀한 상호작용을 보여준다.
  • Dwarkesh가 스스로 강의 내용을 플래시카드(flashcard)로 만들어 공부하고, 이를 통해 다른 이들이 할 수 없는 질문을 던진다는 점 [1:34:00]이 깊이 있는 콘텐츠 제작 비결을 시사한다.
