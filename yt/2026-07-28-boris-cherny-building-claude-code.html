Boris Cherny: Building Claude Code

TL;DR

앤트로픽의 보리스 체르니는 Claude Code 개발 경험을 공유하며, 최신 모델 Claude Opus 5를 최적으로 활용하는 방법과 AI 에이전트 개발의 새로운 패러다임을 제시한다. 모델의 능력을 온전히 이끌어내기 위해 과거의 방식과 사고방식에서 벗어나 실증적 접근과 검증 중심의 태도를 강조한다.

풀시청 판단

이 영상은 최신 LLM(대규모 언어 모델)을 활용하여 에이전트 제품을 개발하거나 고도화하려는 개발자, 프로덕트 매니저, 스타트업 창업가에게 매우 유용하다. 앤트로픽의 Claude Code 개발 책임자로부터 모델 활용의 핵심 원칙과 구체적인 사례를 배울 수 있다.

특히 다음 부분에 관심 있는 사람에게 추천한다:

  • "### 모델을 가로막는 장애물 제거: '언하블링(unhobbling)'과 '제품 오버행'" 챕터에서 현재 모델이 가진 잠재력을 최대한 끌어내는 방법을 이해한다.
  • "### Opus 5의 새로운 능력 — 장기 실행 태스크와 프롬프트 주입 저항성" 챕터에서 최신 모델의 특징을 파악하고 활용 전략을 고민한다.
  • "### 수천 개의 에이전트를 동원하는 방법 — 다이내믹 워크플로와 루틴" 챕터에서 복잡하고 장기적인 AI 자동화 시스템 구축 아이디어를 얻는다.
  • "### 코딩은 이미 해결됐다? 뛰어난 개발자의 새로운 자질" 챕터에서 AI 시대 개발자의 역할 변화와 필요한 역량을 고민한다.

단, 영상의 내용은 주로 코딩 에이전트 개발에 초점을 맞추고 있으며, 모델 자체의 기술적 작동 원리에 대한 깊이 있는 설명은 부족하다. 또한, 모델의 윤리적 문제나 한계에 대한 논의는 거의 다루지 않는다.

핵심 내용

Opus 5의 새로운 능력 — 장기 실행 태스크와 프롬프트 주입 저항성

앤트로픽은 최근 Opus 5 모델을 출시했으며, 이는 Arc AGI 벤치마크 점수를 3%에서 30%로 끌어올리는 놀라운 성능 향상을 보였다 [0:35]. Opus 5는 특히 장기 실행 태스크에서 독보적인 능력을 보인다. 자동 모드와 결합하면 며칠, 몇 주, 심지어 몇 달 동안 중단 없이 작업을 수행할 수 있다 [1:32]. 또한, 이전 모델들과 달리 프롬프트 주입(prompt injection) 공격에 강한 저항성을 보인다 [2:04]. 이는 3년간의 정렬(alignment) 연구와 모델 내부 뉴런을 분석하여 프롬프트 주입을 감지하는 메커니즘을 통해 달성했다 [2:48].

"삭제하고 다시 만들기" — 시스템 프롬프트 개발의 새로운 패러다임

Claude Code는 매번 새로운 모델이 출시될 때마다 시스템 프롬프트의 80% 이상을 삭제하고 처음부터 다시 구축하는 방식으로 개발한다 [3:30]. 이는 모델마다 작동 방식이 매우 다르기 때문인데, Opus 5처럼 지능이 향상된 모델은 과거에 필요했던 상세한 지시 사항 없이도 스스로 작업을 수행할 수 있다. 오히려 과도한 프롬프트는 모델의 성능을 저해할 수 있어, 모델의 필요에 따라 최소한의 지시만을 다시 추가하는 '절제(ablation)' 방식을 사용한다 [6:01]. 이러한 방식은 기존 소프트웨어 개발 방식과 정반대되는 것으로, 모델을 살아있는 유기체처럼 다루고 끊임없이 탐구하며 적응해야 함을 강조한다 [8:58].

모델을 가로막는 장애물 제거: '언하블링(unhobbling)'과 '제품 오버행'

'하블링(hobbling)'은 모델이 가진 능력을 제품이나 프롬프트가 방해하는 것을 의미한다. 반대로 '언하블링(unhobbling)'은 모델의 잠재력을 최대한 발휘할 수 있도록 장애물을 제거하는 것이다. '제품 오버행(product overhang)'은 현재 모델이 수행할 수 있지만 아직 제품으로 구현되지 않은 기능이나 능력을 말한다 [11:03]. Claude Code의 탄생 자체가 이러한 제품 오버행을 해결한 사례다 [12:08]. 과거의 코딩 제품들이 단일 코드 완성이나 읽기 전용 대화에 머물러 있을 때, Claude Code는 모델이 전체 함수나 파일, 나아가 기능까지 작성할 수 있도록 터미널 접근 권한을 부여함으로써 모델의 잠재력을 완전히 끌어냈다 [14:09].

모델의 잠재력을 이끌어내는 방법 — 어려운 태스크와 철저한 검증

모델의 잠재력을 이끌어내려면 두 가지 원칙을 따라야 한다. 첫째, 모델이 할 수 있다고 생각하는 것보다 약간 더 어려운 태스크를 부여한다 [14:52]. 너무 구체적인 지시 대신 태스크, 안전장치(guardrails), 완료 조건만 명시하고 모델이 스스로 해결하도록 맡긴다 [15:17]. 둘째, 모델이 스스로 작업을 검증할 방법을 제공하는 것이 가장 중요하다 [20:29]. 검증 과정을 통해 모델은 막히지 않고 작업을 계속 진행할 수 있다.

한 예로, Bun JavaScript 런타임을 Zig에서 Rust로 재작성한 사례가 있다 [17:25]. 이는 이전 모델로는 불가능했던 작업이었으나, 테스트 스위트를 기반으로 모델이 스스로 검증하며 11일 동안 전체 코드베이스를 성공적으로 변환했다 [17:40]. 또 다른 사례는 Opus 5가 OpenCV를 사용하여 그림을 그릴 수 있다는 점이다 [18:53]. 모델이 그림을 그리도록 훈련되지 않았음에도 불구하고, 적절한 방식으로 요구하자 인물, 동물, 풍경 등을 꽤 잘 그려냈으며, 이는 놀이를 통해 우연히 발견한 능력이다 [19:15].

수천 개의 에이전트를 동원하는 방법 — 다이내믹 워크플로와 루틴

Claude를 활용해 수천 개의 에이전트를 가동하는 두 가지 주요 방법이 있다. 첫째는 **다이내믹 워크플로(Dynamic Workflows)**다 [25:25]. 이는 Bun 런타임 내에 가상 머신을 시작하고, Claude가 수십, 수백, 수천 개의 에이전트를 오케스트레이션하여 복잡한 태스크를 여러 단계에 걸쳐 수행하게 한다. 예를 들어, 코드베이스 재작성, 심층 데이터 분석, 복합 기능 구축 등 장기간에 걸친 작업을 에이전트들이 순차적, 병렬적으로 처리하고 검증하는 방식이다 [26:10]. 둘째는 **루프(Loops)와 루틴(Routines)**이다 [27:41]. 루프는 로컬에서, 루틴은 클라우드에서 실행되는 반복적인 크론(cron) 작업과 유사하다. 이들은 컨텍스트를 공유하지 않지만, 메모리를 공유하며 반복적인 유지보수 태스크에 적합하다.

앤트로픽은 Claude가 자사 애플리케이션의 코드베이스를 유지보수하도록 루틴을 사용한다 [28:13]. 매일 실행되는 루틴들은 죽은 코드 정리 [28:32], 출시 예정 실험 기능 정리, 테스트 작성, 불필요한 테스트 삭제, 중복된 추상화 통합('추상화 경찰'이라 불린다 [29:15]) 등의 작업을 수행한다. 이처럼 매일 수십 개의 루틴이 수백에서 수천 개의 에이전트를 실행하며 수십 명의 엔지니어 역할을 대체하여, 엔지니어들은 신제품 개발과 사용자 소통에 집중할 수 있다.

코딩은 이미 해결됐다? 뛰어난 개발자의 새로운 자질

화자는 자신이 하는 대부분의 코딩 작업이 이미 AI에 의해 해결되었다고 말한다 [30:40]. 물론 매우 깊이 있는 시스템 코드, 분산 시스템, 픽셀 단위의 UI 검증 등은 여전히 Claude에게 어려운 부분이지만, 많은 종류의 코딩이 AI 에이전트로 해결되는 방향으로 가고 있다. 이 새로운 시대에 뛰어난 개발자는 이전의 지식과 편견을 버리고 '실증적(empirical)' 사고방식을 가져야 한다 [31:39]. 이론에 얽매이지 않고 모델을 직접 사용하며, 실패 지점을 파악하고 끊임없이 개선해나가야 한다. 마치 동료와 협업하듯 모델을 대하는 태도가 중요하다고 강조한다 [24:37].

주요 통찰·논점

AI 모델 개발에 대한 실증적 접근 방식

AI 모델 기반 제품 개발은 전통적인 소프트웨어 공학과 크게 다르다 [8:31]. 미리 완벽한 시스템을 설계하고 단위 테스트를 작성하는 방식이 아니라, 모델을 '살아있는 유기체'처럼 대하며 시행착오를 통해 학습하고 적응하는 실증적인 접근이 필요하다 [9:14]. 새로운 모델이 나올 때마다 기존의 프롬프트와 도구를 삭제하고, 모델의 실제 작동 방식을 관찰하며 필요한 부분만 다시 추가하는 '절제' 방식이 이를 잘 보여준다. 이 접근 방식은 기존의 공학적 사고방식에서 벗어나 유연하고 실험적인 태도를 요구한다.

'검증'이 복잡한 AI 에이전트 태스크의 핵심이다

프롬프트 엔지니어링의 핵심은 이제 얼마나 좋은 프롬프트를 작성하느냐가 아니라, 모델이 어려운 태스크를 수행할 수 있도록 유도하고, 나아가 모델이 스스로 작업 결과를 검증할 수 있는 방법을 제공하는 것이다 [20:29]. 모델이 중간 단계에서 자신의 실수를 파악하고 수정할 수 있는 피드백 루프를 구축하는 것이 장기 실행 및 복잡한 태스크 성공의 결정적인 요소다. 이는 마치 인간 동료에게 작업을 맡기고 진행 상황을 점검하듯이, AI 에이전트에게도 자체적인 확인 과정을 부여해야 한다는 의미다.

실용적 문제 해결을 위한 컴퓨팅 과학 학습의 중요성

화자는 컴퓨터 과학을 실용적인 문제 해결을 위해 독학으로 배웠다고 강조한다 [32:41]. TI-83 계산기로 시험을 "속이기 위해" 코드를 짜고, 더 어려운 문제에 부딪히자 어셈블리 언어를 배운 경험을 공유한다 [33:52]. 이는 단순히 이론을 아는 것을 넘어, 실제로 제품을 만들고, 디자인 감각을 기르고, 비즈니스 감각을 익히고, 사용자와 소통하는 등 다양한 응용 능력을 컴퓨터 과학 지식과 결합할 때 비로소 진정한 가치를 창출할 수 있다는 메시지다 [34:04].

인상적인 지점

  • Electron 앱을 Swift로 재작성하는 태스크를 Claude에게 부여하고, 모델이 GitHub의 Mac OS 러너에서 Electron 앱을 실행하여 스크린샷을 찍은 뒤, Swift 버전과 픽셀 단위로 비교하며 완료될 때까지 작업을 멈추지 않도록 지시한 일화 [21:34]. 이 작업은 2주 넘게 실행 중이며, Claude는 내부 슬랙 채널에 몇 분마다 진행 상황 스크린샷을 올리는 방식으로 작업 상황을 '라이브 블로그'까지 했다 [22:50].
  • Claude가 앤트로픽의 다양한 코드베이스(CLI, iOS, Android, 데스크톱 앱)를 매일 유지보수하는 루틴을 실행한다는 점 [28:22]. 특히 '추상화 경찰(abstraction police)'이라는 루틴이 중복되거나 유사한 추상화를 찾아 통합하는 작업을 수행하는 부분이 인상적이다 [29:15]. 이는 AI가 단순한 코딩을 넘어 소프트웨어 아키텍처 개선에도 기여함을 보여준다.
  • 화자가 중학생 때 TI-83 계산기에 BASIC과 어셈블리 언어로 프로그램을 짜서 수학 시험에서 "부정행위를 했다"는 솔직한 일화는 실용적 문제 해결 동기가 학습에 얼마나 큰 영향을 미치는지 보여주는 좋은 비유다 [33:15].
