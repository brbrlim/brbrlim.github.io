TL;DR

AI 에이전트의 장기 기억 시스템은 사실, 이해, 원시 인지 데이터 세 가지 유형으로 구분하여 설계해야 한다. 사실은 SQL 데이터베이스에, 이해는 벡터 저장소에 저장하여 각각의 장점을 활용하고, 원시 데이터는 에이전트의 직접 기억에서 제외한다. 이를 통해 에이전트가 사용자 정보를 정확하게 기억하고 맥락을 이해하며, 실시간 상호작용의 지연을 최소화한다.

볼까 말까

이 영상은 멀티모달 AI 에이전트의 장기 기억 아키텍처를 효과적으로 설계하는 실용적인 방법을 제시한다. 에이전트가 대화 세션 이후에도 사용자를 기억하고 맥락을 이해하도록 돕는 핵심 원칙들을 간결하고 명확하게 설명한다. 에이전트의 기억을 사실, 이해, 원시 인지 데이터 세 가지 유형으로 나누어 각기 다른 저장 방식과 처리 전략을 제안하며, 특히 실시간 에이전트 시스템에서 지연을 방지하기 위한 비동기 처리의 중요성을 강조한다.

주제별 정리

AI 에이전트의 장기 기억은 단기 기억과 구분되며, 유형별로 저장해야 한다

멀티모달 AI 에이전트가 사용자와의 대화 세션 이후에도 정보를 기억하고 활용하려면 단기 기억을 넘어선 장기 기억 설계가 필수적이며, 이때 기억의 종류를 정확히 구분해야 한다.

  • 단기 기억의 한계: 에이전트가 대화 중 사용자의 이전 발화를 기억하는 것은 주로 RAM(랜덤 액세스 메모리)과 같은 단기 기억이며, 세션이 끝나면 사라진다. 진정한 장기 기억은 다음 세션으로 연기되어야 할 정보를 보관하는 것이다.
  • 사실(Facts): 정확하고 구조화된 정보로, 테이블의 행과 열처럼 식별자, 날짜 등을 가지고 생성, 업데이트, 삭제가 가능하다. 예를 들어, 목요일 저녁 약속, 구매한 파란색 재킷, 위시리스트 등이 이에 해당한다. [1:29]
  • 이해(Understanding): 사용자의 개인적인 의미나 패턴을 담은 비구조화된 정보이다. 단순히 데이터베이스에 있는 사실이 아니라, 사용자의 선호도(간결한 스타일 선호, 어두운 색상으로 자신감 표현)와 같은 맥락적 지식이다. 이는 사용자의 달력을 아는 것과 사용자를 아는 것의 차이에 비유할 수 있다. [1:50]
  • 원시 인지 데이터 제외: 카메라 영상, 오디오 등 에이전트가 실시간으로 인지하는 원시 데이터 자체는 에이전트의 직접적인 기억이 아니다. 에이전트는 이 데이터에서 추출된 의미(예: "검은색 모자를 다시 썼다", "이 저녁 식사는 공식적인 자리다")를 기억해야 한다. 원시 데이터는 감사, 디버깅, 훈련 데이터 등의 목적으로 별도로 저장할 수 있다. [5:26]

메모리 유형별로 최적의 저장소를 분리하여 사용한다

사실과 이해는 서로 다른 특성을 가지므로, 이 두 가지 기억 유형을 같은 저장소에 두지 않고 각각에 최적화된 시스템을 사용해야 한다.

  • 사실은 구조화된 데이터베이스에: 정확한 사실 정보는 SQL, Postgres, MySQL, Cloud SQL과 같은 구조화된 데이터베이스에 저장한다. "목요일 일정이 무엇인가요?"와 같이 정확한 답변이 필요한 질문에 대해 실제 행을 반환하는 데 가장 적합하다. [2:37]
  • 이해는 벡터 저장소에: 사용자의 선호도나 스타일과 같은 추상적인 이해는 벡터 저장소에 보관한다. 이 저장소는 임베딩과 벡터 검색을 통해 의미론적으로 관련된 기억을 찾아내는 데 유리하며, PG Vector, AlloyDB, Agent Platform Memory Bank 등의 다양한 솔루션이 있다.
  • 모든 것을 벡터 저장소에 넣는 오류: 의미 기억에 대한 이야기를 듣고 모든 정보를 벡터 저장소에 몰아넣는 실수를 범하기도 한다. 그러나 벡터 저장소는 '유사성' 검색에 특화되어 있어, "무엇을 샀나요?"처럼 '정확한' 답변이 필요할 때는 오히려 위험할 수 있다. [4:32]
  • Agent Platform Memory Bank의 역할: 이 시스템은 단순히 벡터를 저장하는 것을 넘어, 지난 세션을 읽고 유용한 기억을 추출하며 시간이 지남에 따라 업데이트하는 기능을 제공하여 의미 기억 관리를 돕는다.

에이전트 메모리 활용은 세션 시작과 끝에 이루어지며, 동기/비동기 처리가 중요하다

에이전트는 대화 세션 전후로 메모리를 로드하고 저장하며, 실시간 상호작용을 위해 각 기억 유형에 맞는 처리 방식을 적용해야 한다.

  • 세션 시작 시 메모리 로드: 에이전트는 대화가 시작되기 전에 데이터베이스에서 구조화된 사실(예: 예정된 이벤트, 위시리스트)과 벡터 저장소에서 관련 통찰(예: 스타일 선호도, 과거 대화의 색상 선호)을 미리 불러온다. 이를 통해 초기 대화부터 사용자의 맥락을 이해하고 시작한다. [6:45]
  • 사실의 즉시 저장: "위시리스트에 재킷을 추가해 주세요"와 같은 사용자의 명확한 요청은 구조화된 사실이므로, 에이전트는 이를 데이터베이스에 즉시 기록해야 한다. 사용자는 이러한 정보가 바로 저장되기를 기대한다.
  • 이해의 신중한 추출 및 저장: 단발적인 문장 하나("오늘은 노란색이 좋을 수도 있어요")로 사용자의 장기적인 선호도를 변경해서는 안 된다. 이해는 더 강력한 신호(사용자가 중요성을 설명하거나 여러 세션에 걸쳐 패턴이 반복될 때)를 기반으로 판단하여 추출하고 저장해야 한다. 이를 통해 '기억 잡음(memory noise)'을 방지한다.
  • 비동기적 추출의 필요성: 의미 추출은 대화 분석과 해석이 필요한 복잡한 과정이므로 시간이 소요된다. 실시간 음성 에이전트는 지연에 매우 민감하므로, 추출 과정이 대화 흐름을 방해하지 않도록 '주요 처리 경로 외에서' 비동기적으로 수행해야 한다. 예를 들어, 사실은 대화 중 동기적으로 기록하고, 이해는 세션 후 비동기적으로 추출하여 의미 기억으로 저장하는 방식이다. [9:15]

기억할 것

  1. AI 에이전트의 장기 기억은 '사실(Facts)'과 '이해(Understanding)'라는 두 가지 핵심 유형으로 구분하여 관리해야 한다. 이는 에이전트가 정확한 정보를 기억하고 사용자의 맥락과 선호도를 이해하는 데 필수적이다.
  2. 정확한 사실 정보는 SQL과 같은 구조화된 데이터베이스에 저장하여 정밀한 검색에 대비하고, 의미론적 이해는 벡터 저장소에 보관하여 유사성 기반의 맥락 검색에 활용해야 한다.
  3. 실시간 에이전트의 성능을 위해, 사실은 사용자의 요청 즉시 동기적으로 저장하고, 이해는 대화 흐름을 방해하지 않도록 세션 후 충분한 맥락을 바탕으로 비동기적으로 추출하여 저장한다.
  4. 카메라 영상이나 오디오 같은 원시 인지 데이터는 에이전트의 직접적인 기억이 아니며, 여기서 추출된 '의미'만이 기억으로 전환되어야 한다.
