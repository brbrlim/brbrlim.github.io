TL;DR

Cursor는 Claude 모델, 특히 Claude 3.5 Sonnet의 성능 향상과 자율 에이전트(agent) 기능에 힘입어 다중 파일 편집을 지원하는 AI 코딩 도구로 빠르게 성장했다. AI가 코드 생성의 대부분을 담당하는 미래에는 개발자가 코드 검증, 아키텍처 설계, 그리고 '취향'(taste)을 발휘하는 역할이 더욱 중요해질 것이며, 비개발직군도 AI의 도움을 받아 소프트웨어를 직접 만들 수 있는 '주문형 소프트웨어' 시대가 올 것으로 예측한다.

핵심 내용

Claude 모델의 발전과 Cursor의 성장

Cursor는 AI 코딩 도구로서 빠른 성장을 경험했으며, 이는 주로 언어 모델의 성능 향상과 Cursor 자체의 혁신적인 기능 개발 덕분이다 [1:14]. 특히 Claude 3.5 Sonnet의 등장은 코딩 능력에서 "단계적 도약(step function)"을 가져왔고, Cursor는 이 모델과 자체 검색(retrieval) 모델을 결합하여 여러 파일에 걸쳐 코드를 편집하는 기능을 제공하기 시작했다 [1:42]. 이전에는 탭 자동 완성이나 단일 파일 편집에 유용했지만, 모델의 지능이 높아지면서 에이전트처럼 작동하는 더 복잡한 코딩 작업이 가능해졌다는 설명이다 [2:54].

Cursor 팀, 자사 제품으로 자사 제품을 개발하다

Cursor 팀은 자신들이 만든 Cursor를 사용하여 Cursor를 개발하는 자가 개선 재귀적 피드백 순환(recursive feedback loop) 방식으로 일한다 [3:14]. 이는 새로운 코드베이스를 시작할 때 에이전트 기능을 사용하거나, 버그를 해결하기 위해 사고(thinking) 모델을 활용하고, 정확한 편집을 위해 탭 자동 완성을 사용하는 등 다양한 방식으로 이루어진다. 이 과정에서 개발자들은 제품의 문제점을 직접 발견하고, 이를 개선하며 빠르게 기능을 반복 개발(iterate)할 수 있다 [4:26]. 이는 신속한 기능 개발과 불필요한 기능 제거에 큰 이점을 제공하며, 내부에서 솔직한 피드백을 통해 효율성을 극대화한다.

AI 코딩 도구 사용의 스펙트럼: 단순 자동 완성부터 전체 PR 처리까지

AI 코딩 도구의 활용은 개발자의 코드베이스 이해도와 작업 성격에 따라 다양한 스펙트럼을 가진다 [5:24]. 가장 기본적인 수준은 코드에 대한 지식이 많을 때 코딩 속도를 높이는 '탭 자동 완성(Tab completion)' 기능이다 [6:21]. 다음으로는 'Command K'를 이용한 단일 파일 또는 특정 영역 편집이 있고, 더 나아가 여러 파일을 동시에 편집하는 '에이전트(Agent)' 기능이 있다. 최종적으로는 풀 리퀘스트(PR) 전체를 처리할 수 있는 '백그라운드 에이전트(Background Agent)'와 같은 기능으로 발전한다.

백그라운드 에이전트: 개발 프로세스의 새로운 원시 기능

백그라운드 에이전트는 AI 모델이 전체 작업을 100% 완벽하게 처리하지 못하는 현실에서, 모델이 90% 정도 작업을 진행한 후 개발자가 개입하여 나머지 10%를 완성하고 제어하는 방식이다 [6:47]. 이 기능을 통해 개발자는 여러 변경 사항을 동시에 처리하고, 백그라운드와 포그라운드를 오가며 효율적으로 작업할 수 있다 [7:27]. 백그라운드 에이전트는 독립적인 가상 환경(VM)에서 개발 환경 유틸리티와 VS Code 확장 기능이 설치된 상태로 작동하여, 에이전트가 테스트를 실행하고 실험을 진행할 수 있게 한다 [8:10].

AI 시대의 코드 작성 병목 현상 — 검증의 중요성

AI가 코드를 빠르고 많이 생성할 수 있게 되면서, 소프트웨어 개발의 다음 병목 현상은 '코드 검증'이 될 것이라고 예측한다 [9:11]. AI가 코드 작성을 완전히 해결한다 해도, 개발자가 코드 검토에 쓰는 시간은 여전히 중요하기 때문에 전체 개발 속도가 3배 이상 빨라지기 어렵다는 것이다 [9:03]. AI가 만든 코드가 단순히 올바른지뿐만 아니라, 개발자가 의도한 바를 정확히 반영하는지 확인하고 신뢰를 구축하는 과정이 매우 중요해진다 [9:33]. 이에 대한 한 가지 아이디어는 코드를 가상 코드(pseudo code)와 같은 다른 표현 방식으로 나타내어 변경 사항을 간결하게 보여주고 검증 시간을 단축하는 것이다 [9:53].

대규모 코드베이스를 다루는 난제: 환경 설정, 맥락 이해, 암묵지

대규모 엔터프라이즈 코드베이스에서 AI 에이전트를 활용하는 것은 여러 난관에 부딪힌다. 특히 에이전트가 테스트를 실행할 수 있는 개발 환경과 의존성(dependency)을 적절히 설정하는 것이 복잡하다 [11:18]. 또한, 수백만 줄의 코드와 자체 도메인 특화 언어(DSL)를 포함하는 방대한 코드베이스 전체를 모델이 깊이 이해하는 것은 여전히 어려운 문제이다 [12:19]. 현재는 검색 모델을 훈련하고 최근 변경 사항이나 팀 동료의 커밋 내역과 같은 추가적인 맥락을 활용하지만, 모델이 코드베이스를 완전히 이해하기에는 부족하다고 말한다 [12:39]. 더 나아가, 대규모 코드베이스에는 코드로 명시되지 않는 조직 내부의 '암묵지(organizational knowledge)'가 존재하며, 이는 개발자가 특정 방식으로 코드를 작성하는 중요한 이유가 되는데, AI는 이러한 암묵지를 알지 못한다는 문제도 있다 [14:11].

LLM에 최적화된 코드 작성 방식

AI 모델의 사용이 보편화되면서 코드를 작성하는 방식도 변화할 것으로 보인다 [15:42]. API 설계가 LLM이 더 잘 이해하도록 조정될 수 있으며, 코드 구조를 단순화하여 모델이 여러 계층의 상호 작용을 거치지 않고도 핵심 로직을 파악하기 쉽게 만들 수 있다 [16:19]. 그러나 궁극적으로 사람과 모델 모두에게 좋은 "깨끗한 소프트웨어(clean software)"의 원칙, 즉 반복을 피하고 불필요한 복잡성을 제거하는 원칙은 변함없이 중요하다고 강조한다 [16:33]. 오히려 AI가 코드를 더 쉽게 작성하게 되므로, 코드를 '맛있게' 구성하는 '취향'(taste)의 중요성이 더욱 커질 것이라고 예측한다.

주요 통찰·논점

AI 코딩이 개발자의 역량을 향상시키는 방법

AI 도구는 개발자에게 교육적으로 매우 유용하며, 위대한 프로그래머가 되는 데 도움을 줄 수 있다 [17:57]. 특정 개념을 설명하거나 코드 작동 방식을 이해하는 데 AI를 활용할 수 있으며, 이는 학습 과정을 가속화한다 [18:04]. 개발자는 AI 덕분에 더 많은 코드를 작성하고 더 많은 일을 할 수 있게 되며, 시행착오를 통해 빠르게 배우고 문제 해결 능력을 향상시킬 수 있다 [18:34]. 화자는 AI가 자신보다 코드를 더 잘 생성하지만, 본인은 AI를 통해 훨씬 더 많은 프로토타입과 데모를 만들 수 있게 되어 오히려 역량이 강화되었다고 말한다 [25:11].

미래 개발자의 역할 변화: 저수준 코딩 대신 '취향'과 UX 설계에 집중

프로그래밍 방식은 앞으로도 계속 진화할 것이며, 오랫동안은 여전히 상세한 부분을 아는 엔지니어가 필요할 것이다 [19:01]. 그러나 시간이 지나면 저수준의 세부 사항을 잘 알지 못해도 효과적으로 작업하는 소프트웨어 엔지니어들이 생겨날 수 있다 [19:22]. 이들은 코드를 직접 작성하는 대신, 사용자 경험(UX)에 대한 '취향'을 바탕으로 시스템의 상호 작용 방식이나 대략적인 작동 방식을 설명하는 등 더 높은 수준에서 프로그래밍하게 될 것이다 [19:27].

Claude 3.5 Sonnet과 Claude 4 모델의 영향

Claude 3.5 Sonnet은 Anthropic에게 코딩 모델로서 중요한 전환점이었다 [22:00]. 이 모델은 여러 파일에 걸쳐 편집하고 도구를 호출하는 등 더 긴 호라이즌의 에이전트형 코딩 작업을 결합할 수 있는 첫 번째 모델이었고, 이는 향후 모델들의 기반을 마련했다. 최근 출시된 Claude 4 Sonnet은 이전 모델에서 나타났던 '과잉 행동' 문제, 즉 테스트를 임의로 변경하거나 지름길을 택하려는 경향을 80% 정도 해결했으며, 지능 면에서도 크게 향상되었다 [20:34]. Claude Opus 4는 백그라운드 에이전트와 같은 복잡한 작업에 매우 유용할 것으로 기대한다 [20:56].

Anthropic의 모델 개발 철학: 코딩 능력과 에이전트적 추론의 상호 전이

Anthropic은 코딩을 모델 개발의 핵심 영역 중 하나로 보지만, 유일한 영역은 아니라고 말한다 [22:43]. 모델이 코딩에 능숙해지면, 여러 행동을 취하고 에이전트처럼 추론하는 능력 전반이 향상되는 좋은 '전이(transfer)' 효과가 나타난다 [22:45]. 이는 코드뿐 아니라 지식을 검색하거나 연구를 수행하는 등 다양한 응용 분야에 도움이 된다. Anthropic은 모델의 성능 한계를 지속적으로 확장하는 동시에, 안전성과 '클로드의 성격'(character)에도 많은 신경을 쓰고 있다 [24:00]. AI가 사용자의 삶에서 중요한 역할을 하는 '신뢰할 수 있는 존재'가 되도록 모델을 훈련하고 설계한다는 설명이다.

AI 생성 코드의 미래 비중과 개발자의 역할

2027년 1월 1일까지 AI가 생성하는 코드의 비율은 거의 100%에 육박할 것으로 예측한다 [26:19]. 이는 마치 워드프로세서가 법률 문서를 거의 100% 생성하는 것과 같다고 비유한다 [26:08]. AI가 모든 코드 작성에 관여하겠지만, 개발자의 역할은 소프트웨어가 무엇을 해야 하는지 이해하고, '취향'을 발휘하며, 개발 방향을 제시하는 것이 될 것이다 [26:36]. Cursor 내부에서는 이미 AI 생성 코드 비율이 90%를 넘는다고 말한다 [26:44].

미래 프로그래밍의 모습: AI의 보편적 활용과 '주문형 소프트웨어'

AI는 비개발직군도 소프트웨어를 직접 만들 수 있게 할 것이다 [27:23]. 예를 들어, 영업 담당자가 자신의 필요에 맞는 대시보드를 직접 구축할 수 있게 되는 식이다 [27:31]. 이처럼 '주문형 소프트웨어(software on demand)' 시대가 도래하면, 소프트웨어는 사용자의 행동에 맞춰 스스로 변화하고 최적화될 수도 있다 [29:05]. 이는 모든 사람이 자신의 필요에 완벽하게 맞는 소프트웨어를 가질 수 있는 잠재력을 의미한다. Anthropic의 소통팀 직원이 Claude.ai의 버그를 직접 수정하는 사례 [28:11]의 중요성**: AI가 코드를 더 쉽게 만들게 되면서, 단순히 작동하는 코드를 넘어 "불필요하게 복잡하지 않은 깨끗한 해결책"을 찾아내는 '취향'의 중요성이 더욱 커질 것이라는 주장이 인상적이다 [16:56].

  • 워드프로세서에 비유한 AI 코드 생성: AI가 생성하는 코드의 비중을 1995년 변호사에게 "미래에 워드프로세서가 법률 문서를 몇 퍼센트나 생성할 것 같냐"고 묻는 것에 비유하며 100% 가까이 될 것이라고 설명한 부분이 매우 직관적이다 [26:08].
  • 비개발직군도 코딩에 참여하는 미래: Anthropic 소통팀의 한 직원이 Claude.ai 웹사이트의 버그를 직접 수정하여 PR(풀 리퀘스트)을 보낸 사례는 AI 도구가 전문 개발자 외의 사람들에게도 소프트웨어 개발의 문턱을 얼마나 낮출 수 있는지를 명확히 보여준다 [28:11].
  • 스타트업의 '인재 밀도'(Talent Density): 스타트업은 대기업보다 훨씬 높은 인재 밀도를 가질 수 있으며, 이는 작은 팀으로도 세상을 바꾸는 강력한 제품과 모델을 만들 수 있는 원동력이 된다는 점이 매력적인 통찰이다 [30:16].
