이게 진짜 HTML이라고?

TL;DR

이 영상은 웹사이트와 비디오 게임의 경계를 허무는 새로운 Chrome API인 HTML in canvas를 소개한다. 이 API는 모든 HTML 요소를 캔버스 안에 실시간으로 그려 다양한 시각 효과를 적용하고 3D 장면에서 상호작용할 수 있게 한다. 이로써 웹 개발자들은 창의적인 웹 인터페이스를 만들 수 있는 새로운 가능성을 얻는다.

풀시청 판단

이 영상은 웹 개발자, 프런트엔드 엔지니어, 웹 디자이너 및 인터랙티브 웹 경험에 관심 있는 모든 사람에게 풀시청할 가치가 있다. 6분 38초의 짧은 분량에도 불구하고, 새로운 기술의 필요성, 작동 방식, 그리고 미래의 잠재력을 명확한 시각 자료와 함께 제공한다.

  • 장점: HTML in canvas API의 개념과 과거 한계를 명쾌하게 설명한다. 다양한 시각 효과 데모를 통해 직관적으로 기술의 가능성을 보여주며, 간단한 코드 예시로 핵심 구현 원리를 파악할 수 있다. 특히, 기존 웹 개발의 복잡성을 해결하고 창의적 표현의 폭을 넓히는 점을 강조한다.
  • 약점: 이 API는 영상 제작 시점(2023년) 기준으로 아직 크롬 카나리(Chrome Canary)에서 플래그를 활성화해야 하는 제안 단계의 기술이었다 [6:03]. 따라서 이 기술의 현재 표준화 진행 상황은 별도로 확인해야 한다. 복잡한 효과의 코드는 "고전적인 캔버스 수학"으로만 설명되어 깊이 있는 코딩 내용은 다루지 않는다.
  • 추천 대상:
    • 프런트엔드 개발자 및 웹 디자이너: 새로운 인터랙티브 웹 기술 동향을 파악하고 창의적인 UI/UX 구현 아이디어를 얻고자 하는 경우.
    • 웹 기반 게임 개발자: HTML 요소와 캔버스 기반 그래픽을 통합하는 방법에 관심 있는 경우.
    • 기술 애호가: 웹 기술이 어떻게 발전하고 있는지 궁금한 경우.

핵심 내용

HTML in canvas: 웹과 게임의 경계를 허물다

HTML in canvas는 크롬 브라우저에 새로 추가된 API로, 모든 HTML 요소를 캔버스 안에 실시간으로 그릴 수 있게 해준다 [0:06]. 이는 버튼, 폼, 심지어 전체 웹페이지까지 캔버스 환경에서 렌더링하고 조작할 수 있다는 의미다. 이 기술을 활용하면 웹사이트가 2D 페이지보다는 비디오 게임이나 예술 설치물처럼 느껴지는 새로운 형태의 웹 경험을 제공할 수 있다 [1:31]. 영상은 3D 장면에서 옷감처럼 반응하는 HTML 폼, 젤리처럼 늘어나는 범위 입력 필드, 페이지가 불타며 전환되는 효과, 액체 유리처럼 움직이는 UI 등 인상적인 데모를 보여준다 [0:22].

기존 캔버스의 한계: HTML과의 분리

기존에는 캔버스가 픽셀을 조작하는 데 매우 강력했지만, 다른 HTML 요소에 대해서는 전혀 알지 못했다 [1:52]. 예를 들어, 캔버스 안에 버튼을 넣으려면 개발자가 직접 사각형과 텍스트를 그리고, 클릭 좌표를 계산하여 클릭 이벤트를 감지해야 했다. 마우스 오버 효과나 키보드 지원, CSS 스타일링, 접근성 기능 등은 전혀 제공되지 않았다. 이러한 제약 때문에 오랫동안 개발자들은 픽셀로 가득 찬 캔버스와 HTML로 가득 찬 웹 페이지 중 하나를 선택해야 했으며, 둘을 동시에 사용하는 것은 사실상 불가능했다 [2:34].

HTML in canvas의 작동 방식: 두 세계의 통합

HTML in canvas API는 HTML 요소가 두 곳에 동시에 존재함으로써 이 문제를 해결한다 [2:51]. 하나는 DOM(Document Object Model)으로, 사용자가 클릭하거나 입력할 수 있는 실제 버튼이나 입력 필드가 존재하는 곳이다. 다른 하나는 캔버스로, HTML 요소가 단순히 픽셀 형태로 그려지는 곳이다 [2:55]. 이 픽셀들은 셰이더(shader)를 통해 비틀거나 왜곡하거나 3D 형태로 매핑하는 등 다양한 조작이 가능하다 [3:05]. 이 API는 layout subtree 속성으로 캔버스가 자식 HTML 요소를 인식하게 하고, draw element image 함수를 사용해 HTML 요소를 캔버스에 실시간 복사본으로 그린다 [3:11]. HTML 내용이 변경되면 캔버스에 paint 이벤트가 발생하며, 개발자는 이 이벤트를 감지해 HTML을 다시 그리거나 셰이더로 왜곡하는 등의 작업을 할 수 있다 [3:37]. WebGL이나 WebGPU 사용 시에는 HTML을 GPU 텍스처로 직접 공급할 수도 있다 [3:33].

간단한 데모: 반영 효과가 있는 버튼 만들기

영상은 반영 효과가 있는 버튼을 만드는 과정을 통해 API의 핵심을 설명한다 [3:52]. 먼저 layout subtree 속성을 가진 캔버스 안에 일반 HTML 버튼을 넣는다. 그리고 JavaScript를 사용하여 캔버스에 버튼의 실제 모습과 함께 뒤집힌 반사 이미지를 그린다. 여기서 중요한 점은 버튼이 캔버스에 그려진 이미지일 뿐 아니라 DOM에 실제 존재하는 '보이지 않는' 클릭 가능한 요소라는 사실이다 [4:57]. draw element image 함수가 반환하는 좌표 정보를 이용해 DOM에 있는 보이지 않는 버튼의 위치를 캔버스에 그려진 버튼과 정확히 일치시켜야 사용자의 클릭이 제대로 작동한다. 이 모든 과정이 약 20줄의 JavaScript 코드로 구현된다 [5:37].

캔버스에 HTML을 올리면 가능한 것들

HTML 요소가 캔버스에 그려지면, 개발자는 해당 요소의 픽셀을 완전히 제어할 수 있게 된다 [5:40]. 이는 클릭 시 물결 효과(ripple effect)와 같은 복잡한 시각 효과를 쉽게 구현할 수 있다는 의미다. 물결 효과 자체는 고전적인 캔버스 수학을 활용하여 픽셀을 샘플링하고 이동시키는 작업이지만, 이 API 덕분에 실제 HTML 요소에 이러한 효과를 바로 적용할 수 있게 된다. AI 도구의 도움을 받아 캔버스 수학을 활용하는 것도 가능하다고 언급한다 [5:54].

주요 통찰·논점

웹 인터페이스의 새로운 패러다임

HTML in canvas는 웹 인터페이스가 더 이상 정적인 2D 페이지에 머무르지 않고, 비디오 게임이나 예술 작품처럼 동적이고 몰입감 있는 경험을 제공할 수 있는 새로운 시대를 연다 [1:31]. 이는 사용자와의 상호작용 방식과 시각적 표현의 가능성을 극대화하여 웹의 사용자 경험을 혁신할 잠재력을 가진다.

개발자 생산성 및 창의성 증대

과거에는 캔버스에 HTML 요소를 넣기 위해 복잡한 수동 코드를 작성하고 접근성과 스타일링을 포기해야 했지만, 이 API를 통해 이러한 제약이 사라진다. 개발자들은 DOM의 강점(접근성, 키보드 지원, CSS)을 유지하면서 캔버스의 강력한 시각적 제어 능력을 활용할 수 있게 되어, 훨씬 적은 노력으로 복잡하고 창의적인 인터페이스를 구현할 수 있게 된다 [5:37].

Flash 시대의 즐거움을 웹으로 되살리다

이 영상은 HTML in canvas가 과거 플래시(Flash) 시대처럼 웹을 다시 재미있게 만들 수 있다고 주장한다 [6:26]. 플래시가 제공했던 자유로운 애니메이션과 상호작용성이라는 강점을 웹 표준 기술로 가져와, 개발자들이 웹에서 상상력을 마음껏 펼칠 수 있는 환경을 만들 것으로 기대한다.

인상적인 지점

  • "HTML in Canvas는 HTML 요소가 DOM과 캔버스 두 곳에 동시에 존재하게 한다. 하나는 만질 수 있고, 다른 하나는 그릴 수 있다." [3:05] 이 문장은 API의 핵심적인 작동 원리와 철학을 간결하게 설명한다.
  • 다양한 데모 영상들이 API의 잠재력을 직관적으로 보여주며, 특히 3D 장면의 옷감처럼 반응하는 HTML 폼이나 액체 유리 효과는 웹 기술의 진화를 체감하게 한다 [0:22].
  • "이 API는 아직 생산 환경에 적용할 준비가 안 됐다. 크롬 카나리 플래그를 통해 활성화해야 하며, 여전히 제안 단계다. 하지만 지금부터 실험해볼 가치는 충분하다." [6:03] 기술의 현실적인 한계를 명확히 밝히면서도 미래 가치를 강조하여 개발자들에게 도전 의식을 부여한다.
