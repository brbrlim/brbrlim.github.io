TL;DR

이 강의는 언어 모델링의 시스템 측면을 다루며, GPU 및 TPU 하드웨어의 작동 방식과 딥러닝 워크로드를 가속화하는 핵심 최적화 기법들을 설명한다. 특히 메모리 병목 현상을 해결하기 위한 저정밀도 연산, 연산자 융합, 재계산, 통합 메모리 접근, 타일링 등 6가지 기법을 상세히 소개하고, 이를 활용해 플래시어텐션(FlashAttention)이 어떻게 혁신적인 성능을 달성했는지 보여준다. 하드웨어의 저수준 이해가 효율적인 모델 설계에 필수적임을 강조한다.

풀시청 판단

이 강의는 GPU와 TPU 기반 딥러닝 모델의 성능을 최적화하고 싶은 개발자, 연구자, 시스템 엔지니어에게 매우 가치 있는 내용이다. 특히 머신러닝 시스템의 작동 원리를 깊이 이해하고 하드웨어의 잠재력을 최대한 활용하려는 사람들에게 필수적이다.

강의는 GPU와 TPU의 기본 하드웨어 및 프로그래밍 모델부터 시작하여 [3:20] 매우 실용적인 6가지 최적화 기법과 그 이론적 배경을 상세히 다룬다 [32:36]. 마지막으로 이 모든 기법이 플래시어텐션(FlashAttention)과 같은 최첨단 모델에 어떻게 적용되는지 보여주며 [1:12:07], 실제 문제 해결에 대한 깊은 통찰을 제공한다.

다만, 몇 가지 약점도 존재한다. CPU-GPU/TPU 비교는 개념적인 수준에 머무르며 [7:31], TPU 관련 내용은 GPU에 비해 상대적으로 적다 [17:22]. 또한, 일부 내용은 GPU 하드웨어에 대한 사전 지식이 없으면 다소 어렵게 느껴질 수 있다. 하지만 강사가 어려운 개념을 쉽게 풀이하고 비유를 활용하므로, 시스템 배경 지식이 적더라도 충분히 따라갈 만하다.

전체 시청을 강력히 추천하지만, 시간이 부족하다면 다음 챕터를 중심으로 볼 수 있다:

  • ### 성능 최적화의 핵심: 메모리 병목 현상과 루프라인 모델 [25:59]부터 ### GPU 가속화를 위한 6가지 핵심 기법 [32:36] 및 그 하위 챕터들은 GPU 최적화의 핵심을 다룬다.
  • ### 플래시어텐션(FlashAttention): 모든 최적화 기법의 집대성 [1:12:07] 챕터는 앞서 배운 기법들이 실제 고성능 모델에 어떻게 적용되는지 보여주는 훌륭한 사례 연구이다.

핵심 내용

GPU와 TPU: 병렬 처리의 시대

지난 몇 년간 언어 모델의 발전은 컴퓨팅 성능의 확장에 크게 의존했다. 과거에는 트랜지스터 크기 축소와 클록 속도 향상(데나드 스케일링)을 통해 CPU의 직렬 처리 속도를 높이는 방식이 주효했다 [5:11]. 그러나 2000년대 이후 데나드 스케일링이 한계에 부딪히면서, 명령어 실행을 병렬로 확장하는 수평적 스케일링 방식, 즉 GPU가 대규모 언어 모델(LLM)의 발전을 이끌었다 [5:50]. 특히 2017년 V100 GPU에 텐서 코어가 도입된 이후 FLOPS(초당 부동소수점 연산) 성능은 초지수적으로 증가했다 [6:39].

CPU와 GPU의 철학적 차이: 지연 시간 vs. 처리량

CPU는 복잡한 분기 논리와 제어 흐름에 최적화되어 빠른 직렬 실행과 낮은 지연 시간(latency)을 목표로 설계되었다 [7:45]. 몇 개의 강력한 연산 장치(ALU)와 큰 제어 장치를 갖는다 [7:56]. 반면, GPU는 수백 개의 경량 코어를 집적하여 대규모 병렬 연산을 수행, 높은 처리량(throughput)을 달성하는 것을 목표로 한다 [8:44]. 개별 작업의 완료 시간은 길어질 수 있지만, 전체적으로는 훨씬 많은 작업을 동시에 처리한다 [8:36].

GPU 하드웨어 모델: 스트리밍 멀티프로세서(SM)와 계층적 메모리

GPU의 기본 계산 단위는 스트리밍 멀티프로세서(SM)이다 [9:29]. A100 GPU에는 128개의 SM이 있으며, 각 SM은 독립적으로 프로그래밍되고 작업을 실행할 수 있다 [10:08]. 각 SM은 자체 스트리밍 프로세서를 내부에 포함하여 여러 스레드를 병렬로 실행한다 [9:52].

GPU의 또 다른 핵심 요소는 계층적 메모리 구조다 [10:43]. 가장 빠른 레지스터, L1 캐시 및 공유 메모리(shared memory)는 SM 내부에 물리적으로 가깝게 위치하여 20~30 사이클 내에 데이터 접근이 가능하다 [11:06]. L2 캐시는 그 다음, 가장 느린 전역 메모리(global memory) 또는 고대역폭 메모리(HBM)는 칩 외부에 위치하며 L1 캐시보다 10배 이상 느리다 [11:17]. 고속 메모리는 비싸고 전력 소모가 커서 모든 칩을 고속 메모리로 만들 수 없기 때문에, 이 계층 구조를 효과적으로 활용하는 것이 중요하다 [12:17].

GPU 프로그래밍 모델: 스레드, 블록, 워프

GPU의 프로그래밍 모델에는 세 가지 핵심 개념이 있다 [13:35]:

  1. 스레드(Thread): 병렬로 실행되는 경량 작업 단위이다 [13:46]. GPU 스레드는 SIMT(Single Instruction Multiple Thread) 모델을 따르는데, 이는 모든 스레드가 동일한 명령어를 실행하지만 다른 입력값을 가질 수 있음을 의미한다 [13:54].
  2. 블록(Block): 스레드 그룹을 의미하며, 하나의 블록은 단일 SM에서 실행된다 [14:26]. 블록 내 스레드들은 공유 메모리 풀에 접근할 수 있어, 스레드 간 데이터 공유 및 재사용이 가능하다 [14:35].
  3. 워프(Warp): GPU 내부의 스케줄링 단위로, 32개의 연속된 스레드 그룹이다 [14:51]. 스케줄러가 워프 단위로 다음 실행 명령을 결정하여 오버헤드를 줄인다 [15:04].

이러한 메모리 계층 구조와 프로그래밍 모델을 고려할 때, 핵심은 공유 메모리 외부(전역 메모리)로 데이터 접근을 최소화하는 것이다 [17:02]. 블록을 그룹화하여 전역 메모리 읽기 횟수를 줄이는 것이 성능 최적화의 핵심이다 [17:08].

TPU와 GPU의 수렴적 진화

TPU는 GPU와 유사하게 머신러닝 워크로드에 최적화된 가속기이며, 이는 일종의 수렴 진화(convergent evolution) 결과이다 [17:51]. TPU는 경량 제어 장치와 훨씬 큰 행렬 곱셈 장치를 가지며 [18:17], GPU와 매우 유사한 메모리 구조(느린 HBM과 빠른 로컬/공유 메모리)를 갖는다 [18:40].

GPU의 텐서 코어(행렬 곱셈 장치)는 TPU의 MXU(행렬 곱셈 장치)에 거의 정확히 대응하며, 둘 다 시스톨릭 배열(systolic array)이라는 동일한 회로를 사용한다 [19:49]. 주요 차이점은 규모와 유연성이다 [20:23]. GPU(예: A100)는 132개의 SM과 528개의 행렬 곱셈 장치를 갖는 반면, TPU는 단 2개의 처리 단위와 8개의 행렬 곱셈 장치를 갖는다 [20:53]. TPU는 적은 수의 매우 큰 행렬 곱셈 장치에 의존하여 대규모 행렬 곱셈에 특화되어 유연성이 떨어지는 반면 [21:43], GPU는 더 많고 작은 장치들로 유연성이 높다. 이처럼 근본적인 아이디어는 유사하므로, GPU 최적화 개념은 TPU에도 적용 가능하다 [22:14].

성능 최적화의 핵심: 메모리 병목 현상과 루프라인 모델

GPU 컴퓨팅 성능이 메모리 대역폭보다 훨씬 빠르게 성장하고 있어 [25:59], 현대 딥러닝 최적화의 대부분은 메모리 이동 최소화에 초점을 맞춘다 [26:31]. 루프라인 모델(roofline model)은 이 현상을 설명하는 틀이다 [31:13]. 연산 집약도(operational intensity, 메모리 읽기당 연산량)가 낮으면 메모리 제약적(memory-bound) 구간에서 성능이 메모리 대역폭에 의해 제한되고, 연산 집약도가 충분히 높으면 계산 제약적(compute-bound) 구간에서 GPU의 최대 계산 능력에 도달한다 [31:22]. 따라서 효율적인 코드 작성을 위해서는 메모리 제약적 구간을 벗어나 연산 장치를 최대한 활용할 수 있도록 연산 집약도를 높여야 한다 [32:18].

GPU 가속화를 위한 6가지 핵심 기법

GPU에서 효율적인 딥러닝 워크로드를 구현하기 위한 6가지 핵심 기법은 대부분 메모리 이동 최소화와 관련이 있다.

제어 발산(Control Divergence) 최소화

GPU의 SIMT 모델에서는 모든 스레드가 동일한 명령어를 실행해야 한다 [33:05]. 만약 if 문과 같은 조건문이 발생하면, 조건을 만족하지 않는 스레드들은 유휴 상태로 대기하며 조건의 모든 분기(if와 else)를 실행해야 한다 [33:31]. 이를 제어 발산(control divergence)이라고 부르는데, 이는 계산에 큰 비효율을 초래한다 [34:10]. 따라서 ReLU와 같은 연산에서 if 문 대신 마스크를 이용한 곱셈을 사용하는 것이 더 빠르다 [34:26].

저정밀도 연산(Low-Precision Computation) 활용

저정밀도 연산은 컴퓨팅 성능 향상의 비결 중 하나이다 [35:05]. FP32(단정밀도)에서 BF16(반정밀도), Int8(정수 8비트) 등으로 정밀도를 낮추면, 이동해야 하는 데이터량이 줄어들어 메모리 병목 현상을 완화하고 계산 속도를 크게 높일 수 있다 [35:26]. 예를 들어, FP32 대신 BF16을 사용하면 연산당 메모리 이동량이 절반으로 줄어든다 [36:01].

현대 GPU는 행렬 곱셈 시 저정밀도로 입력값을 받더라도 부분 합산은 고정밀도로 수행한 후 다시 저정밀도로 출력하는 혼합 정밀도(mixed precision) 방식을 사용한다 [37:00]. FP8과 같은 극도로 낮은 정밀도에서는 스케일링 인자(scaling factor)를 사용하여 오버플로/언더플로를 방지해야 하며 [39:11], MXFP8과 같이 행렬 내에서 여러 스케일링 인자를 사용하는 방식도 등장했다 [39:53]. 이러한 방식은 행렬 전치 시 재양자화를 피하기 위해 행렬의 원본과 전치본을 두 벌로 저장하는 등 복잡한 구현을 필요로 한다 [41:16]. 어떤 연산을 어떤 정밀도로 수행할지 결정하는 것은 여전히 시행착오가 필요한 난해한 기술이다 [42:19].

연산자 융합(Operator Fusion)으로 메모리 왕복 최소화

연산자 융합은 여러 개의 개별 연산을 하나의 GPU 커널 호출로 묶어 실행하는 기법이다 [47:48]. GPU를 공장에 비유하자면, 각 연산마다 원재료(데이터)를 메모리 창고에서 가져와 처리하고 다시 창고에 넣는 대신, 모든 연산을 한 공장 내에서 처리하여 원재료를 한 번만 가져오고 완성품만 한 번 내보내는 것과 같다 [48:02].

예를 들어, sin(x)^2 + cos(x)^2와 같은 간단한 계산도 나이브하게 구현하면 각 sin, cos, square, add 연산마다 전역 메모리 읽기/쓰기가 발생한다 [48:57]. 이를 하나의 GPU 커널에서 수행하도록 융합하면 전역 메모리 접근 횟수를 크게 줄여 성능을 향상시킬 수 있다 [49:17]. PyTorch의 Torch compiler나 JAX compiler 같은 도구들은 이러한 기본적인 연산 융합을 자동으로 수행한다 [49:46].

재계산(Recomputation)으로 메모리 사용량 줄이기

역전파(backpropagation) 시에는 순전파(forward pass)에서 계산된 활성화 값들을 저장해 두었다가 사용한다 [50:15]. 그러나 GPU의 컴퓨팅 자원이 풍부하고 메모리 비용이 비싼 환경에서는, 중간 활성화 값들을 모두 버리고 역전파 과정에서 필요할 때마다 다시 순전파를 수행하여 재계산하는 것이 효율적일 수 있다 [51:38].

예를 들어, 세 개의 시그모이드(sigmoid) 함수를 연속으로 적용하는 경우, 중간 활성화 값을 모두 저장하면 총 8회의 메모리 접근이 필요하다 [51:50]. 반면, 최종 출력값만 저장하고 역전파 시 활성화 값을 재계산하면 총 5회의 메모리 접근으로 줄일 수 있다 [52:25]. 이는 추가 계산 비용을 지불하고 메모리 사용량을 줄이는 절충(tradeoff) 전략이다 [52:33].

메모리 접근 통합(Coalesced Memory Access)으로 효율 높이기

전역 메모리(DRAM)는 내부 구조 때문에 단일 값을 요청하더라도 특정 블록 단위(예: 128바이트)로 데이터를 "무료"로 함께 전송한다 [53:05]. 이를 버스트 섹션(burst section)이라고 한다 [53:46]. 워프 내의 모든 스레드가 이 버스트 섹션 내에서 인접한 메모리 위치에 접근할 때, 메모리 접근이 통합되었다(coalesced)고 말한다 [54:19]. 통합된 접근은 한 번의 메모리 요청으로 여러 스레드에 필요한 데이터를 효율적으로 가져올 수 있어, DRAM 읽기 속도를 크게 높인다 [54:53].

따라서 행렬과 같은 대규모 연속 구조에서 메모리 읽기를 효율적으로 하려면, 스레드들이 주축을 따라 접근할 때 통합이 일어나도록 데이터 저장 순서(행 우선/열 우선)나 접근 패턴을 고려해야 한다 [56:11]. 잘못된 접근 패턴은 하나의 컬럼을 읽으려 해도 여러 버스트 창을 모두 활성화시켜 비효율을 초래할 수 있다 [57:02].

타일링(Tiling)으로 지역성 활용 극대화

타일링은 가장 중요한 최적화 기법 중 하나로, 행렬과 같은 대규모 데이터를 작은 '타일(tile)'로 나누어 빠르게 접근 가능한 공유 메모리(shared memory)에 로드한 후, 해당 타일 내에서 가능한 많은 연산을 수행하는 방식이다 [58:01]. 이렇게 하면 전역 메모리 접근 횟수를 크게 줄이고 고속 공유 메모리를 최대한 활용할 수 있다 [59:50].

예를 들어 N x N 행렬 곱셈에서 각 입력 요소는 나이브하게 N번 읽힌다 [59:21]. 타일 크기 T로 타일링하면, 각 입력 요소는 전역 메모리에서 N/T번만 읽히고, 타일 내에서 T번 접근된다 [1:00:31]. 이는 전역 메모리 접근 횟수를 T배 줄이는 효과를 가져온다 [1:00:48].

타일링은 강력하지만 복잡한데, 행렬 크기, 공유 메모리 크기, 통합 메모리 접근 등을 고려하여 최적의 타일 크기를 찾아야 한다 [1:03:04]. 행렬 크기가 타일 크기에 딱 맞아떨어지지 않으면, 비효율적인 작은 타일이 생기거나 [1:02:52] 메모리 정렬 불량(misalignment)으로 인해 여러 버스트 섹션을 동시에 읽어야 하는 문제가 발생할 수 있다 [1:04:35]. PyTorch의 max-autotune 같은 기능은 다양한 타일 크기를 벤치마킹하여 최적의 설정을 자동으로 찾아낸다 [1:03:39]. 때로는 패딩(padding)을 통해 행렬 크기를 조절하여 정렬을 맞추고 효율을 높이기도 한다 [1:05:01].

행렬 곱셈 성능 그래프 미스터리 해명

강의 초반에 제시된 행렬 곱셈 처리량 그래프의 불규칙한 패턴은 위에서 설명한 최적화 기법들로 설명할 수 있다 [30:29].

  • 우상향하는 추세: 행렬 크기가 커지면 연산 집약도가 높아져 컴퓨팅 유닛을 더 잘 활용할 수 있기 때문이다 [30:47].
  • 가분성에 따른 성능 차이: 행렬 크기가 1, 2와 같은 작은 수로만 나누어떨어지는 경우(파란색, 주황색 선)는 처리량이 매우 낮고, 16 또는 32와 같은 큰 수로 나누어떨어지는 경우(빨간색, 보라색 선)는 처리량이 높다 [1:06:40]. 이는 16 또는 32가 GPU의 버스트 창 크기와 잘 맞아떨어져 메모리 접근 통합(coalescing)이 효율적으로 일어나기 때문이다 [1:07:28].
  • 급격한 성능 하락(Wave Quantization): 1792에서 1793으로 행렬 차원(Dimension)이 1 증가했을 때 처리량이 급격히 떨어지는 현상이 발생한다 [1:08:08]. A100 GPU는 108개의 SM을 갖는데, 1792 차원에서는 98개의 타일이 모든 SM에 딱 맞아떨어져 효율적으로 처리된다 [1:08:46]. 하지만 1793 차원으로 증가하면 120개의 타일이 필요해 SM 수(108개)를 초과하게 되며, 이는 GPU의 대부분이 유휴 상태로 대기하는 비효율을 초래하여 한 주기 더 기다려야 하는 웨이브 양자화(wave quantization) 현상으로 이어진다 [1:08:55].

플래시어텐션(FlashAttention): 모든 최적화 기법의 집대성

플래시어텐션은 어텐션 메커니즘 계산에서 발생하는 메모리 병목 현상을 해결하기 위해 위의 모든 최적화 기법을 적용한 대표적인 사례다 [1:12:07]. PyTorch의 나이브한 어텐션 구현 대비 극적인 성능 향상을 보여준다 [1:12:23]. 핵심은 어텐션 계산에 필요한 K(키), Q(쿼리), V(값) 행렬 곱셈과 소프트맥스(softmax) 연산을 고도로 최적화하는 것이다 [1:13:05].

플래시어텐션은 다음과 같은 기법들을 사용한다:

  1. 타일링(Tiling): K, Q, V 행렬을 작은 타일로 나누어 SRAM(고속 온칩 메모리)에 로드한 후, 타일 내에서 K, Q 내적과 V와의 곱셈을 수행한다 [1:15:41].
  2. 온라인 소프트맥스(Online Softmax): 어텐션 계산에서 소프트맥스 연산은 모든 토큰 간의 상호작용을 필요로 하는 전역 연산이라 타일링하기 어렵다 [1:13:50]. 플래시어텐션은 소프트맥스 계산을 온라인 방식으로 변형하여, 타일별로 부분 소프트맥스를 계산하고 최대값을 누적 업데이트하면서 나중에 정규화하는 방식으로 해결한다 [1:14:28]. 이를 통해 소프트맥스를 타일별로 처리할 수 있게 된다 [1:15:10].
  3. 연산자 융합(Operator Fusion): 여러 단계의 어텐션 계산(행렬 곱셈, 소프트맥스)을 단일 GPU 커널로 융합하여 전역 메모리 읽기/쓰기 횟수를 최소화한다 [1:16:40].
  4. 재계산(Recomputation): 역전파 시 필요한 중간 활성화 값(어텐션 행렬)을 저장하지 않고, 순전파와 마찬가지로 타일별로 다시 계산하여 메모리 사용량을 크게 줄인다 [1:17:07].

이러한 기법들을 통해 플래시어텐션은 HBM(전역 메모리) 접근량을 혁신적으로 줄여 어텐션 계산의 효율성을 극대화한다 [1:17:19].

주요 통찰·논점

메모리 접근 패턴과 정렬이 GPU 성능에 미치는 지대한 영향

강의는 단순히 빠른 GPU를 사용하는 것을 넘어, 메모리 접근 패턴과 데이터 정렬이 GPU 성능에 얼마나 결정적인지 강조한다 [25:59]. 특히 행렬 곱셈 성능 그래프의 불규칙한 패턴을 통해 [1:06:20], 행렬 크기가 GPU 내부의 버스트 창 크기(burst window)나 SM(Streaming Multiprocessor) 개수와 같은 하드웨어 제약과 맞지 않을 때 예측 불가능한 성능 저하가 발생함을 보여준다. 이는 단순히 코드를 작성하는 것을 넘어, 하드웨어의 저수준(low-level) 작동 방식을 이해하고 데이터 구조를 최적화해야만 진정한 고성능을 달성할 수 있음을 시사한다 [1:17:44].

"계산 비용"과 "메모리 비용" 간의 복잡한 절충(Trade-off)

GPU 성능 최적화는 단순히 계산을 빠르게 하는 것을 넘어, 계산 비용과 메모리 비용 사이의 영리한 절충에 달려있다. 재계산(recomputation)은 계산을 두 번 하는 대신 메모리 사용량을 줄이고 [51:11], 저정밀도 연산(low-precision computation)은 정밀도 손실의 위험을 감수하고 데이터 이동량을 줄인다 [35:05]. 이 강의는 현대 딥러닝 시스템 설계에서 이러한 절충을 어떻게 전략적으로 활용하여 전체적인 효율성을 높이는지 구체적인 사례를 통해 보여주며, 메모리 병목 현상 시대에 컴퓨팅 자원을 최대한 활용하는 사고방식을 제시한다 [1:17:56].
