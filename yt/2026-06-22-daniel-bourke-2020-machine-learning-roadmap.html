TL;DR

이 영상은 머신러닝 분야 전체를 아우르는 로드맵을 제시하며, 2020년에 만들어졌지만 2024년에도 87% 유효하다고 주장한다. 머신러닝 문제 유형, 문제 해결 과정, 활용 도구, 기초 수학, 학습 자원 등 다섯 가지 핵심 분야를 '요리사처럼' 넓게 탐색하며 실용적인 관점에서 머신러닝에 접근하는 방법을 다룬다. 특히 머신러닝을 학습할 때 '화학자처럼' 깊이 파고들기보다 '요리사처럼' 전체를 아우르고 직접 경험하며 호기심을 따라가는 것이 중요하다고 강조한다.

풀시청 판단

이 영상은 머신러닝 분야의 광범위한 지형을 탐색하려는 모든 이에게 가치 있는 안내서가 될 수 있다. 특히 다음과 같은 사람들에게 풀시청을 권한다.

  • 머신러닝 입문자: 머신러닝이 무엇인지, 어떤 문제에 적용되는지, 학습에 필요한 단계와 자원은 무엇인지 전반적인 그림을 얻고 싶은 초보자에게 특히 유용하다. 특정 기술 스택에 얽매이지 않고 분야 전체를 이해하는 데 도움이 된다.
  • 학습 방향을 고민하는 개발자/연구자: 머신러닝을 공부하고 있거나 시작하려는 개발자나 연구자가 자신의 학습 경로를 설정하거나 놓치고 있는 부분이 없는지 점검하는 데 도움이 된다. 특히 ### 머신러닝 학습 경로 챕터는 구체적인 학습 코스 구성을 제안한다.
  • 기술의 맥락적 이해가 필요한 비즈니스 리더: 머신러닝 기술 자체보다는 그것이 실제 문제 해결에 어떻게 적용되고 어떤 과정을 거치는지에 대한 실질적인 이해를 돕는다.

약점 및 한계:

  • 시간 경과에 따른 정보의 불확실성: 2020년에 제작된 영상이므로 언급된 특정 도구, 라이브러리 버전, SOTA(State-Of-The-Art) 모델 등은 2024년 현재 기준으로는 일부 업데이트되거나 더 효율적인 대안이 있을 수 있다. 특히 클라우드 서비스, MLOps, 특정 모델 아키텍처 등 빠르게 변화하는 분야에서는 더욱 그러하다.
  • 깊이의 부족: "요리사처럼" 접근한다는 화자의 선언처럼, 각 주제를 깊이 파고들기보다는 넓게 소개하는 데 중점을 둔다. 특정 알고리즘의 작동 원리나 복잡한 수학적 배경에 대한 상세한 설명은 기대하기 어렵다.
  • 영상이 길고 밀도가 높음: 2시간 37분이라는 긴 영상 시간은 진입 장벽이 될 수 있다. 로드맵 자체의 복잡성과 화자의 즉흥적인 설명 방식이 더해져 집중하기 어려울 수도 있다.

핵심 내용

머신러닝이란 무엇인가: 데이터에서 패턴을 찾아 숫자와 규칙을 만드는 기술

머신러닝은 데이터를 숫자로 변환하고, 그 숫자들에서 패턴을 찾아내는 기술이다 [3:22]. 이는 명시적으로 프로그래밍하지 않고도 컴퓨터가 스스로 학습할 수 있는 능력을 부여한다 [3:50]. 전통적인 프로그래밍(소프트웨어 1.0)이 개발자가 직접 규칙을 작성하여 입력값을 처리하고 출력값을 얻는 방식이라면 [5:53], 머신러닝(소프트웨어 2.0)은 입력값과 원하는 출력값을 주고 컴퓨터가 스스로 그 사이에 있는 규칙과 패턴을 찾아내도록 하는 방식이다 [6:41]. 머신러닝은 소프트웨어 1.0 위에 구축되며, 소프트웨어 1.0 없이는 존재할 수 없다 [4:30].

왜 머신러닝을 사용하는가: 복잡한 규칙, 변화하는 환경, 대규모 데이터 속 통찰

머신러닝은 인간이 모든 규칙을 직접 작성하기 어려운 복잡한 문제를 해결하는 데 유용하다. 첫째, 긴 규칙 목록을 가진 문제에 적합하다 [10:58]. 예를 들어, 자율주행차를 프로그래밍한다고 가정할 때, 정지 신호 인식, 보행자 회피, 차선 유지 등 수천 가지 상황에 대한 규칙을 일일이 코딩하는 것은 거의 불가능하다. 머신러닝은 이 복잡한 규칙들을 데이터에서 스스로 학습한다 [8:30]. 둘째, 지속적으로 변화하는 환경에 적응해야 하는 문제에 효과적이다 [11:22]. 특정 지역의 교통 규칙에 맞춰진 자율주행차가 다른 도시나 터널 같은 새로운 환경에 직면했을 때, 머신러닝 모델은 새로운 시나리오를 학습하고 적응하여 예측 능력을 향상할 수 있다 [15:19]. 셋째, 대규모 데이터 집합에서 통찰을 발견하는 데 뛰어나다 [12:01]. 수천만 건의 고객 거래 기록이나 방대한 양의 텍스트 데이터에서 수동으로 패턴을 찾는 것은 비현실적이다. 머신러닝은 이러한 대규모 데이터 속에서 의미 있는 그룹화, 이상 탐지, 추세 분석 등을 수행하여 숨겨진 통찰을 드러낸다 [12:08].

머신러닝 문제 유형: 지도, 비지도, 전이, 강화 학습

머신러닝 문제들은 주로 학습 방식에 따라 분류할 수 있다 [22:26].

  • 지도 학습(Supervised Learning): 데이터와 그에 해당하는 정답(레이블)이 있을 때, 모델이 데이터와 레이블 간의 관계를 학습하여 새로운 데이터의 레이블을 예측하는 방식이다 [23:06]. 예를 들어, 고양이와 개의 사진에 각각 '고양이', '개'라는 레이블이 붙어있을 때, 모델은 이 데이터를 학습하여 새로운 사진이 고양이인지 개인지 분류한다 [24:00].
    • 분류(Classification): 이메일이 스팸인지 아닌지(이진 분류), 사진 속 강아지의 품종이 무엇인지(다중 분류), 사진에 여러 객체가 포함되어 있는지(다중 레이블 분류)와 같이 특정 범주로 분류하는 문제다 [29:36].
    • 회귀(Regression): 주택 가격 예측, 비트코인 시세 예측처럼 연속적인 숫자를 예측하는 문제다 [26:51].
    • 시퀀스-투-시퀀스(Sequence-to-Sequence): 영어 텍스트를 프랑스어로 번역하거나 음성 명령을 텍스트로 변환하는 것처럼, 하나의 시퀀스를 다른 시퀀스로 변환하는 문제다 [37:03].
  • 비지도 학습(Unsupervised Learning): 레이블이 없는 데이터에서 모델이 스스로 패턴이나 구조를 찾아 학습하는 방식이다 [24:46].
    • 군집화(Clustering): 고객의 구매 이력을 분석하여 유사한 구매 패턴을 가진 고객 그룹을 식별하거나, 음악 취향에 따라 사용자들을 묶는 등의 문제다 [27:16].
    • 차원 축소(Dimensionality Reduction): '차원의 저주(curse of dimensionality)'를 피하기 위해 데이터의 양을 줄이면서도 중요한 정보는 유지하는 기술이다 [27:50]. 예를 들어, 심장병 진단 시 나이와 심박수만으로도 충분하다면 다른 불필요한 데이터를 제거한다 [28:09].
  • 전이 학습(Transfer Learning): 한 모델이 특정 데이터셋에서 학습한 지식(패턴)을 가져와 다른 유사한 문제에 활용하는 방식이다 [25:20]. 대규모 데이터와 컴퓨팅 자원이 부족할 때, 이미 대량의 데이터로 훈련된 모델의 성능을 활용하여 자신의 문제를 해결하는 데 매우 유용하다 [25:56].
  • 강화 학습(Reinforcement Learning): 모델이 환경과 상호작용하며 시행착오를 통해 최적의 행동 정책을 학습하는 방식이다. 이 로드맵에서는 연구 영역에서 주로 다뤄지며 실질적인 활용 사례는 언급되지 않는다 [1:12:17].

머신러닝 프로젝트 과정: 데이터 수집부터 모델 재훈련까지

머신러닝 프로젝트는 일련의 연속적인 단계를 거치는 순환적인 과정이다 [41:57].

  1. 데이터 수집(Data Collection): 해결하려는 문제에 필요한 데이터를 수집하는 단계다 [40:16]. 어떤 데이터가 존재하는지, 어디서 얻을 수 있는지, 개인 정보 보호 문제는 없는지 등을 고려한다 [42:11]. 데이터는 엑셀 스프레드시트와 같은 정형 데이터일 수도 있고, 이미지, 비디오, 텍스트, 음성과 같은 비정형 데이터일 수도 있다 [45:09].
  2. 데이터 준비(Data Preparation): 수집된 데이터를 머신러닝 모델이 학습할 수 있는 형태로 가공하는 단계다 [40:23].
    • 탐색적 데이터 분석(EDA): 데이터를 이해하고 숨겨진 패턴, 특성, 문제점(결측치, 이상치) 등을 파악한다 [49:18]. 이를 통해 데이터에 대한 자신만의 '머신러닝 모델'을 머릿속으로 만들어본다 [50:30].
    • 데이터 전처리(Data Pre-processing): 결측치(missing values)를 채우거나 [54:05], 범주형 데이터를 숫자로 변환하는 특성 인코딩(feature encoding)을 수행하고 [54:57], 숫자 특성들의 스케일을 맞추는 정규화(normalization)나 표준화(standardization)를 적용한다 [55:26].
    • 특성 공학(Feature Engineering): 도메인 지식을 활용하여 기존 특성들을 조합하거나 변환하여 모델 성능을 높이는 새로운 특성을 만든다 [56:24].
    • 데이터 분할(Data Splitting): 데이터를 훈련(training), 검증(validation), 테스트(test) 세트로 나눈다 [1:02:38]. 훈련 세트로 모델을 학습시키고, 검증 세트로 하이퍼파라미터를 조정하며, 테스트 세트로 최종 성능을 평가한다. 테스트 세트는 모델 조정에 사용하지 않고 완전히 별개로 두어야 한다 [1:03:49].
  3. 모델 훈련(Train Model): 데이터를 학습할 머신러닝 알고리즘을 선택하고 모델을 훈련시킨다 [40:39].
    • 알고리즘 선택: 문제 유형(분류, 회귀 등)에 따라 선형 회귀, 로지스틱 회귀, 의사 결정 나무, 랜덤 포레스트, 신경망 등 적절한 알고리즘을 선택한다 [1:09:34]. 초기에는 알고리즘의 내부 작동 방식을 깊이 알기보다 실제 적용해보고 효과를 확인하는 것이 중요하다 [1:10:03].
    • 과적합(Overfitting) 해결: 모델이 훈련 데이터에 너무 잘 맞아 새로운 데이터에 대한 일반화 성능이 떨어지는 과적합 현상을 해결하기 위해 정규화(regularization), 드롭아웃(dropout), 조기 종료(early stopping), 데이터 증강(data augmentation) 등의 기법을 사용한다 [1:18:32].
    • 하이퍼파라미터 튜닝(Hyperparameter Tuning): 모델의 성능에 영향을 미치는 학습률, 배치 크기, 레이어 수 등 하이퍼파라미터를 최적화한다 [1:19:39]. 좋은 데이터 수집과 준비가 모델 성능에 가장 큰 영향을 미치며, 하이퍼파라미터 튜닝은 그 다음이다 [1:23:14].
  4. 분석 및 평가(Analysis/Evaluation): 훈련된 모델의 성능을 평가한다 [40:02]. 분류 문제에서는 혼동 행렬(confusion matrix), 정확도(accuracy), 정밀도(precision), 재현율(recall) 등을 사용하고, 회귀 문제에서는 평균 제곱 오차(mean squared error), R-제곱(R-squared) 등을 사용한다 [32:15]. 모델의 예측 정확도뿐만 아니라 훈련 및 추론(inference) 시간, 비용 등 실제 운영 측면의 요소들도 함께 고려해야 한다 [1:24:40].
  5. 모델 배포(Serve Model): 훈련되고 검증된 모델을 실제 사용자들이 접근할 수 있도록 API, 웹 애플리케이션 또는 모바일 앱 형태로 배포한다 [41:25]. 주피터 노트북에서 높은 성능을 보인 모델이라 할지라도 실제 환경에서는 예상치 못한 문제가 발생할 수 있으므로, 실제 배포는 모델의 진정한 시험대다 [1:27:38].
  6. 모델 재훈련(Retrain Model): 배포된 모델의 예측 성능이 시간이 지남에 따라 저하(데이터 드리프트)되면, 새로운 데이터로 모델을 재훈련한다 [41:33]. 예를 들어, 자율주행차의 카메라가 업그레이드되어 데이터 해상도가 높아지면, 기존 모델은 새로운 데이터를 제대로 처리하지 못할 수 있으므로 재훈련이 필요하다 [1:29:30].

머신러닝 도구: 라이브러리, 클라우드, AutoML, MLOps

머신러닝 개발에는 다양한 도구들이 사용되며, 이 분야는 빠르게 발전하고 있다 [1:33:35].

  • 주요 라이브러리: Python 기반의 scikit-learn, TensorFlow, PyTorch 등이 모델 개발의 핵심 도구로 사용된다 [1:33:50]. Jupyter Notebook은 코드 작성과 탐색에 주로 활용된다 [1:35:08].
  • 실험 추적: TensorBoard, Weights & Biases 대시보드와 같은 도구는 수많은 모델 훈련 실험의 결과와 하이퍼파라미터, 성능 지표 등을 추적하고 비교하는 데 필수적이다 [1:38:39].
  • 사전 훈련 모델 및 전이 학습: TensorFlow Hub, PyTorch Hub, Hugging Face Transformers, Detectron2 등은 이미 대규모 데이터로 훈련된 모델을 제공하여 전이 학습을 통해 효율적으로 새로운 문제를 해결할 수 있게 돕는다 [1:39:57].

머신러닝의 근간이 되는 수학: 선형 대수, 미적분, 확률

머신러닝은 본질적으로 수학적 문제 해결 과정이며, 다양한 수학 분야가 그 기반을 이룬다 [2:00:01].

  • 선형 대수(Linear Algebra): 데이터(숫자)를 벡터나 행렬과 같은 객체로 표현하고, 이 객체들을 조작하는 규칙(연산)을 다룬다 [2:01:39]. 머신러닝은 데이터를 모델링하는 올바른 객체와 규칙을 찾는 과정이며, 신경망에서는 행렬 곱셈이 핵심적인 역할을 한다.
  • 다변수 미적분(Multivariate Calculus): 여러 변수에 대한 함수의 변화율을 다룬다. 특히 신경망 학습의 핵심인 역전파(backpropagation) 알고리즘은 연쇄 법칙(chain rule)을 활용한 다변수 미적분에 기반한다 [2:00:18].
  • 확률 및 분포(Probability and Distributions): 데이터의 불확실성을 다루고, 예측의 신뢰도를 평가하는 데 사용된다 [2:00:30].
  • 최적화(Optimization): 모델의 예측 오차(손실 함수)를 최소화하는 최적의 패턴을 찾아내는 과정이다 [2:00:36].

화자는 머신러닝을 시작하기 위해 이 모든 수학을 깊이 알 필요는 없다고 강조한다 [2:01:09]. 대신 코드를 작성하며 문제를 해결하는 과정에서 필요할 때마다 수학적 개념을 학습하는 '문제 중심 학습' 방식을 추천한다 [2:03:56].

주요 통찰·논점

머신러닝은 엔지니어링 문제다: 코드보다 데이터와 인프라가 핵심

많은 사람이 머신러닝을 단순히 모델 구축(코드 작성) 문제로 생각하지만 [1:29:02], 실제로는 데이터 수집, 데이터 준비, 인프라 구축, 모델 배포, 모니터링, 재훈련 등 소프트웨어 엔지니어링 문제의 비중이 훨씬 크다 [2:08:10]. 모델 코드가 프로젝트 전체에서 차지하는 비중은 생각보다 작다 [1:29:05]. 따라서 머신러닝 엔지니어는 모델링 능력뿐 아니라 견고한 시스템을 구축하고 유지보수하는 MLOps(Machine Learning Operations) 역량을 갖추는 것이 필수적이다 [1:54:26].

수학은 목적이 아닌 수단이다: 필요에 따라 점진적으로 학습하라

머신러닝의 근간에는 복잡한 수학이 존재하지만, 초기 학습 단계에서 모든 수학적 개념을 완벽하게 이해할 필요는 없다 [1:59:51]. 오히려 특정 문제를 해결하거나 모델 성능을 개선하는 과정에서 수학적 지식이 필요할 때마다 관련 개념을 찾아 학습하는 점진적 학습 방식이 더 효과적이다 [2:03:31]. 코드를 통해 문제를 해결하면서 수학이 실제로 어떻게 적용되는지 경험하면, 수학적 개념에 대한 이해와 흥미를 높일 수 있다 [2:05:56].

학습은 '탐험'과 '실험'의 연속이다: 정해진 정답 대신 호기심을 따르라

머신러닝은 정해진 '로드맵'을 따라가는 것이 아니라, 자신만의 '나침반'을 가지고 끊임없이 탐험하고 실험하는 과정이다 [20:21]. 각 문제에 대한 '정답'이나 '최적의 방법'이 명확하지 않은 경우가 많으므로, 다양한 방법을 시도하고 어떤 것이 효과적인지 직접 경험하며 최적의 해답을 찾아나가는 능력이 중요하다 [57:08]. 이는 새로운 도구나 기술에 대한 호기심을 유지하고, 학습 과정에서 발생하는 불확실성을 수용하는 태도를 요구한다 [2:16:00].
