Beyond Components: Designing Generative UI for MCP Apps — Ruben Casas, Postman

AI Engineer16:58게시 2026-06-03

TL;DR

이 영상은 AI 모델의 UI 생성 능력 발전에도 불구하고 우리가 여전히 정적인 UI 패러다임에 갇혀 있는 이유를 탐구한다. 루벤 카사스(Ruben Casas)는 AI가 고품질 UI 코드를 직접 생성하는 시대에 맞춰, 정적, 선언적, 생성형 UI의 세 가지 방식을 비교하고, 생성형 UI의 보안 문제를 MCP 앱(Multi-Party Computation apps)이 어떻게 해결하는지 설명한다. 나아가 미래의 UI는 단순히 컴포넌트 생성을 넘어 사람과 에이전트 간의 협업을 통해 더욱 개인화되고 역동적인 형태로 진화할 것이라고 전망한다.

풀시청 판단

이 영상은 AI 에이전트와 UI 디자인의 미래에 관심 있는 프런트엔드 개발자, UI/UX 디자이너, AI 엔지니어에게 유익하다. 특히 생성형 UI의 개념, 현재 구현 방식, 그리고 MCP 앱이 가져올 잠재력에 대한 실질적인 인사이트를 얻을 수 있다.

  • 영상에서 얻을 수 있는 것:
    • AI 모델의 UI 코드 생성 능력 발전에 대한 역사적 맥락과 현재 수준.
    • 정적, 선언적, 생성형 UI의 개념과 각 방식의 장단점 및 실제 사례.
    • 생성형 UI가 직면한 보안 문제와 MCP 앱이 그 해결책이 될 수 있는 이유.
    • 미래 UI가 사람-에이전트 협업 방식으로 진화할 것이라는 흥미로운 비전과 'Excalidraw MCP 앱' 같은 구체적인 사례.
    • 안드레이 카파시(Andrej Karpathy)와 앤트로픽(Anthropic)의 사례를 통해 MCP 앱의 중요성을 이해한다.
  • 영상이 만족시키지 못하는 것 (한계):
    • 각 UI 생성 방식에 대한 기술적인 깊이 있는 설명은 부족하다. 개념적인 이해에 초점을 맞춘다.
    • 생성형 UI의 윤리적 문제나 모델의 편향성 등 사회적 함의는 다루지 않는다.
    • 발표 시점(2025년 3월로 추정되는 언급이 있음) 이후의 기술 발전은 반영되지 않는다.

따라서 전체 영상을 시청하는 것이 좋지만, 특정 주제에 관심 있다면 다음 챕터들을 집중해서 볼 수 있다.

  • 생성형 UI의 보안 및 MCP 앱의 역할: ### 생성형 UI의 신뢰 문제와 MCP 앱의 샌드박스 역할 챕터.
  • 미래 UI의 비전과 인간-에이전트 협업: ### ‘라디오 쇼에 카메라를 단 시대’ — 우리의 상상력은 아직 UI의 미래를 그리지 못한다 및 ### 미래 UI의 핵심: 컴포넌트를 넘어 사람과 에이전트의 협업으로 챕터.

핵심 내용

AI 모델, 불과 3년 만에 '나보다 나은' UI 코드를 작성한다

2022년 11월 ChatGPT가 처음 등장했을 때, 개발자들은 주로 ChatGPT에게 코드 컴포넌트를 요청하고 복사-붙여넣기 하는 방식으로 AI를 활용했다 [0:32]. 이는 마치 "가난한 사람의 짝 코딩"과 같았다. 하지만 불과 지난 한 해 동안 상황은 급격히 변했다. 특히 GPT 5.2와 Opus 4.5 같은 모델이 출시되면서, AI는 더 이상 간단한 코드 조각을 넘어 고품질의 UI를 매우 빠르게 생성할 수 있게 됐다 [1:32].

발표자는 직접 자신의 블로그를 단일 프롬프트로 다시 작성해달라고 요청했을 때, AI가 요청하지도 않은 멋진 검색 상자, 블러 애니메이션, 접근성 기능까지 자동으로 구현한 것을 보고 놀랐다고 말한다 [2:05]. 이 경험을 통해 그는 3년이라는 짧은 기간 안에 AI가 이제 "나보다 더 나은 프런트엔드 코드를 작성할 수 있다"는 현실을 받아들이게 되었다고 강조한다 [2:45]. 이처럼 모델의 UI 생성 능력이 비약적으로 발전했음에도 불구하고, 우리는 여전히 대부분 정적인 UI 패러다임에 갇혀 있으며, SF 영화에서 보던 "자비스(Jarvis) 같은 떠다니는 UI 창"은 아직 현실이 되지 않았다는 질문을 던진다 [3:01].

우리는 '새로운 컴퓨터'를 얻었지만, 아직 'GUI'가 없다

안드레이 카파시(Andrej Karpathy)가 말했듯이, 우리는 이제 새로운 컴퓨터(AI 모델)를 얻었지만, 아직 그 컴퓨터를 위한 그래픽 사용자 인터페이스(GUI)가 발명되지 않은 상태다 [3:36]. 마치 1970년대처럼 모든 것이 텍스트 기반으로 이루어지는 시대에 초지능을 가지고 있는 것과 같다. 현재 많은 SaaS 기업들이 홈페이지에 챗봇을 추가하는 방식으로 AI 인터페이스를 도입하지만 [4:12], 발표자는 이것이 최종적인 형태는 아닐 것이라고 본다.

다른 한편으로는 ChatGPT, Claude, Gemini와 같은 슈퍼 앱(super app)이 등장하여, 사용자들이 대부분의 UI와 웹사이트와 상호작용하는 하나의 통합된 에이전트 환경을 제공할 것이라는 시각도 있다 [4:44]. 발표자는 이 두 가지 방식 모두 새로운 컴퓨터를 위한 인터페이스를 찾아가는 진화 과정의 일부이며, 어떤 것이 최종 형태가 될지는 소비자들이 결정할 것이라고 설명한다. 그러나 더 중요한 질문은 "모델이 무엇을 생성하는가"이며, 이는 UI 생성 방식에 따라 달라진다고 말한다 [5:43].

세 가지 UI 생성 방식: 정적, 선언적, 생성형

UI 생성 방식은 크게 세 가지로 나눌 수 있다.

  1. 정적 UI (Static UI) [6:02]: 대부분의 에이전트가 현재 사용하는 방식이다. 에이전트는 조정자(orchestrator) 역할을 하며, 도구 호출(tool call)을 통해 개발자가 미리 정의해둔 정적 컴포넌트에 매개변수와 데이터를 전달한다. 클라이언트가 이 컴포넌트를 렌더링하는 방식이다. 이는 지난 20년간 UI 개발 방식과 유사하며, AGUI 프로토콜이나 Goose의 자동 시각화 도구(Auto Visualizer)가 좋은 예시다 [6:47]. Goose는 데이터를 입력하면 미리 정의된 컴포넌트 세트에 맞춰 데이터를 시각화한다.
  2. 선언적 UI (Declarative UI) [7:43]: 정적 컴포넌트를 사용하지만, 에이전트가 데이터와 속성(props)을 직접 전달하는 대신 JSON이나 YAML 같은 기술자(descriptor)를 생성하여 전달한다 [8:00]. 이 기술자는 변환 렌더링 엔진(translation rendering engine)을 통해 최종 UI로 변환된다. 이는 더욱 동적이고 개인화된 UI를 생성할 수 있다. 넷플릭스(Netflix)가 오랫동안 사용자 개인화와 서버 기반 UI(server during UI)를 통해 홈 페이지를 각 사용자에게 맞춰 제공해온 것과 유사하다 [8:41]. Vercel의 JSON Render도 JSON이나 YAML을 사용해 컴포넌트를 매핑하여 동적인 UI를 생성하는 좋은 예시다 [9:04]. 선언적 UI는 유연성과 일관성 사이에서 현재 가장 이상적인 균형을 제공하며, 디자인 시스템을 유지하고 UI 생성의 예측 가능성을 높일 수 있다는 장점이 있다.
  3. 생성형 UI (Generative UI) [10:11]: 모델이 직접 HTML, CSS, JavaScript를 런타임에 즉석으로(on demand at runtime) 생성하는 방식이다 [10:32]. 발표자는 Postman에서 직접 이 실험을 진행했는데, 날씨 에이전트가 날씨 API에서 데이터를 가져와 농담을 만들고, 이 모든 것을 HTML, CSS, JavaScript로 한 번의 도구 호출로 생성하여 완전히 새롭고 독창적인 UI를 만들어내는 것을 보여주었다 [11:00]. 이 방식은 미리 정의된 컴포넌트나 변환 과정 없이 에이전트가 모든 것을 창조한다.

생성형 UI의 신뢰 문제와 MCP 앱의 샌드박스 역할

생성형 UI는 큰 잠재력을 가지고 있지만, 동시에 중요한 문제가 있다. 바로 '신뢰' 문제다 [11:31]. 우리가 타사(third-party) 코드를 쉽게 신뢰하지 않는 것처럼, LLM이 생성한 코드를 검증 없이 사용자에게 바로 제공해서는 안 된다. 생성형 UI는 배포 모델(distribution model)이 필요하며, 이 모델은 경계(boundary), 격리(containment), 그리고 샌드박스(sandbox) 기능을 갖춰야 한다 [11:47].

여기서 MCP 앱(Multi-Party Computation apps)의 역할이 매우 중요해진다 [11:55]. MCP 앱은 인증, 도구 호출, UI와 에이전트 간의 메시지 전달 같은 기능들을 기본으로 제공하며, 무엇보다 이중 iFrame을 통해 기본적으로 샌드박스 환경을 구축한다 [12:14]. 이는 타사 UI 배포를 위한 현재 표준 방식이며, 생성형 UI를 안전하게 전달하기 위한 최적의 메커니즘이 된다. 앤트로픽(Anthropic)이 자체 시각화 기능을 위해 MCP 앱을 사용하는 것을 보면, 이것이 단순한 타사 UI뿐 아니라 자체 UI(first-party UI)에도 적용될 수 있는 강력한 프로토콜임을 알 수 있다 [12:31]. 특히 에이전트가 즉석에서 UI를 생성하는 경우, MCP 앱은 가장 안전하고 효율적인 배포 수단이 된다.

주요 통찰·논점

‘라디오 쇼에 카메라를 단 시대’ — 우리의 상상력은 아직 UI의 미래를 그리지 못한다

우리는 여전히 AI와 새로운 컴퓨터의 최종 형태가 무엇일지 고민하고 있다 [13:33]. "자비스처럼 떠다니는 창" 같은 것은 우리가 상상할 수 있는 '뻔한' 미래일 뿐이다 [13:41]. 발표자는 1930년대 라디오가 대중화된 후 텔레비전이 처음 나왔을 때, 초기 TV 쇼들이 단순히 "카메라를 단 라디오 쇼"에 불과했던 상황을 비유로 든다 [14:02]. 사람들은 새로운 기술이 제공할 수 있는 무한한 가능성을 즉시 상상하지 못했던 것이다.

마찬가지로, 우리는 지금 "라디오 시대"에 있으며, 새로운 컴퓨터(AI)가 가진 잠재력을 제대로 활용할 "새로운 매체(UI)"가 무엇일지 아직 알지 못한다 [14:26]. 현재 우리가 상상하는 AI 기반 UI는 과거의 관성에 갇힌 뻔한 형태일 수 있다. 우리의 상상력은 아직 새로운 미디어의 놀라운 가능성을 온전히 그려내지 못하고 있다.

미래 UI의 핵심: 컴포넌트를 넘어 사람과 에이전트의 협업으로

발표자는 미래의 UI가 컴포넌트를 넘어서 사람-에이전트 협업(human-agent collaboration)의 방향으로 나아갈 것이라고 전망한다 [14:50]. 그는 Excalidraw MCP 앱을 좋은 예시로 든다 [15:00]. 이 앱은 단순히 다이어그램을 시각화하는 것을 넘어, 사람과 에이전트가 공유된 아티팩트(shared artifact)인 캔버스에서 함께 협업할 수 있는 공간을 제공한다 [15:11]. 사용자는 에이전트에게 변경을 요청할 수도 있고, 익숙한 방식대로 직접 UI를 클릭하고 수정할 수도 있다 [15:27].

이러한 협업 방식은 에이전트의 강력한 능력을 단순히 시각화나 전달 메커니즘으로만 활용하는 현재의 제한된 상상력을 넘어선다 [15:48]. 미래의 생성형 UI는 고도로 개인화되고 협업적인 경험이 될 것이다 [16:04]. 우리는 아직 초기 단계에 있으며 최종 답을 알지는 못하지만, 이러한 협업을 통해 새로운 컴퓨터의 미래를 함께 만들어갈 수 있을 것이라고 강조하며 발표를 마친다 [16:28].
