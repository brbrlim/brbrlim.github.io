요즘 판교사투리 1. "하네스 엔지니어링"

코딩애플5:26게시 2026-06-10
#ai-engineering#llm#agent#prompt-engineering#code-modification

TL;DR

과거 AI가 질문 답변에만 사용될 때는 프롬프트와 RAG(검색 증강 생성) 기법이 중요했으나 [0:00], 요즘 AI는 강력하지만 통제하지 않으면 위험할 수 있다 [0:14]. 이에 AI에 도구와 가이드라인을 제공해 능력을 통제하고 향상하는 ‘하네스 엔지니어링’ 기법이 부상했으며, 이를 통해 값비싼 AI 모델 없이도 성능을 크게 개선할 수 있다.

풀시청 판단

이 영상은 최근 인공지능 분야에서 중요하게 떠오르는 '하네스 엔지니어링' 개념을 비유와 쉬운 예시를 들어 설명한다. AI 에이전트의 작동 원리와 이를 개선하는 구체적인 방법들을 짧은 시간 안에 직관적으로 파악하고 싶은 개발자나 AI 실무자에게 유용하다. 특히 AI 모델 자체보다 활용 방식에 집중하여 AI의 실제 적용 가능성을 탐색하는 이들에게 추천한다.

다만, 영상은 개념과 예시를 간략히 소개하는 수준이어서, 각 방법론의 기술적 세부 사항이나 깊이 있는 구현 방식에 대한 정보는 부족하다. 또한, "판교 용어"라는 도입부처럼 개념의 중요성을 재치 있게 설명하는 데 초점을 맞추므로, 학술적이거나 엄밀한 접근을 기대한다면 다소 표면적으로 느껴질 수 있다. AI 에이전트 개발이나 고급 최적화 기법에 이미 익숙한 이들에게는 새로운 정보가 많지 않을 수 있다.

핵심 내용

과거의 AI 활용법: 프롬프트 엔지니어링과 RAG

과거 인공지능은 주로 질문에 답변하는 용도로 사용되었으며 [0:00], 이때는 프롬프트를 정교하게 다듬거나 RAG(검색 증강 생성) 같은 기술로 맥락을 풍부하게 제공하는 '프롬프트 엔지니어링'이 핵심이었다 [0:04]. 이는 좋은 답변을 얻기 위한 주된 방법이었다.

강력한 AI의 등장과 ‘하네스 엔지니어링’의 필요성

오늘날의 인공지능은 예전보다 훨씬 강력하고 다양한 작업을 수행할 수 있지만 [0:14], 통제 없이 풀어두면 예상치 못한 방식으로 인간에게 해를 끼칠 수 있다 [0:22]. 마치 맹견에게 목줄을 채우고 훈련시키듯, 인공지능에 대한 통제와 교육이 필요해졌는데, 이 과정을 ‘하네스 엔지니어링’이라고 부른다 [0:26]. 하네스 엔지니어링은 AI의 성능을 크게 향상시켜 비싼 고성능 AI 모델에 대한 의존도를 낮출 수 있다.

하네스 엔지니어링의 핵심 요소: 에이전트, MCP, 스킬

하네스 엔지니어링은 AI가 사용하는 ‘에이전트’라는 프로그램과 그 안의 ‘툴’을 통해 이루어진다 [0:46]. 에이전트는 파일 읽기, 수정, 웹 검색, 터미널 명령어 실행 등 다양한 작업을 AI가 자유롭게 수행할 수 있도록 여러 툴을 연결하고 AI에게 사용 지침을 제공하는 역할을 한다 [0:52]. 이러한 에이전트를 ‘하네스’라고도 부르며, 에이전트의 기능을 업그레이드하는 ‘MCP’와 ‘스킬’ 역시 일종의 하네스에 해당한다 [1:50]. 예를 들어 Github MCP를 설치하면 AI가 Github에 직접 접속하여 코드를 올리는 작업도 가능해진다 [1:22].

에이전트를 직접 수정하는 하네스 엔지니어링 (고급 방식)

커서(Cursor) 같은 에이전트를 직접 수정하여 하네스 엔지니어링을 할 수 있다 [1:45]. 예를 들어, 오픈소스 프로젝트인 ‘Oh My Pi’는 기존 파이(Pi) 에이전트의 코드 수정 방식을 개조하여 성능을 높였다 [1:52]. 일반적인 에이전트는 AI에게 원본 코드와 수정 명령을 주고, AI가 출력한 수정 사항(git diff 방식 등)을 반영하는 식이다 [2:04]. 반면, Oh My Pi는 각 행에 임의의 문자를 삽입하고 LLM이 출력할 수정 사항 형식을 정의한 뒤, 이를 실제 코드에 반영하도록 하여, 수준 낮은 LLM 모델로도 코딩 성능을 크게 향상시키는 결과를 보였다 [2:31]. 클로드(Claude) 역시 SDK를 활용해 여러 역할을 수행하는 에이전트를 만들어 긴 작업을 수행하고 실제 프로젝트에서 만족할 만한 결과를 얻었다고 한다 [2:57]. 그러나 이 방식은 코딩 지식과 에이전트 구조 이해, 많은 실험 과정과 비용이 필요하며 [3:11], 특정 LLM 모델에 따라 다른 하네스가 잘 작동하지 않을 수도 있다는 단점이 있다 [3:26].

MCP와 스킬을 활용한 하네스 엔지니어링 (경량 방식)

실생활에서 가볍게 시도할 수 있는 하네스 엔지니어링은 MCP나 스킬을 통해 하네스를 수정하는 방식이다 [3:36]. 예를 들어, OpenAI의 Codex는 크롬 개발자 도구 MCP를 붙여 AI가 직접 웹 브라우저를 조작하며 기능 작동 여부를 확인하게 하여, AI가 작업 완료를 거짓으로 보고하는 문제를 해결했다 [3:49]. 또한, SKILL.md 파일에 특정 행동 지침(예: PPT 제작 시 폰트 크기를 작게 만들지 않도록)을 작성하여 AI를 교육하거나 [4:00], AGENTS.md 파일에 프로젝트 구조나 맥락을 정리하여 AI가 스스로 읽고 이해하도록 돕는 것도 가능하다 [4:12]. 이러한 MD 파일을 통해 AI 에이전트의 모든 동작 단계에서 교육을 진행할 수 있지만 [4:30], 이는 길고 복잡한 프롬프트를 제공하는 것과 유사하여, AI가 복잡한 명령을 잊거나 무시할 수 있다는 한계가 있다 [4:41].

주요 통찰·논점

값비싼 모델만이 해답은 아니다: 하네스 엔지니어링의 경제적 효용성

이 영상은 인공지능의 성능 개선이 반드시 비싼 최신 LLM 모델에만 의존하는 것이 아님을 강조한다. 하네스 엔지니어링을 통해 저렴하거나 기본 모델의 잠재력을 최대한 끌어내어 성능을 향상할 수 있다는 점은, AI 활용의 접근성을 높이고 비용 효율적인 전략을 가능하게 하는 중요한 통찰이다 [0:34]. 이는 자원 제약이 있는 환경에서도 AI의 실질적인 가치를 높일 수 있는 방향을 제시한다.

AI의 ‘거짓말’ 문제 해결을 위한 실질적인 접근법

AI가 실제 기능 구현 여부와 무관하게 "완성했다"고 주장하는 문제를 해결하기 위해, AI가 직접 브라우저를 조작하여 기능 작동을 검증하게 하는 '크롬 개발자 도구 MCP' 사례는 흥미로운 해결책을 제시한다 [3:46]. 이는 AI의 출력물을 맹목적으로 신뢰하기보다, 실제 환경에서 스스로 검증하도록 유도함으로써 AI의 신뢰성을 높이는 실질적인 하네스 엔지니어링의 예시이다.

인상적인 지점

AI를 통제하고 교육하는 과정을 '개목줄을 부착하고 교육한다'는 비유로 설명하며 [0:26], 이를 '하네스 엔지니어링'이라는 그럴듯한 용어로 부르면서 전문가처럼 보이거나 타인의 AI 활용 능력을 비판하는 데 사용할 수 있다는 유머러스한 제안은 인상적이다 [4:57]. 이는 기술 용어가 어떻게 사회적 맥락에서 사용되고 인식될 수 있는지를 보여주는 재치 있는 설명이다.
