TL;DR

이 영상에서 인섭 송(Insop Song) 연사는 에이전트 AI(Agentic AI)가 기존 언어 모델(LLM) 활용 방식의 자연스러운 발전 단계임을 설명한다. LLM의 한계(환각, 지식 최신성 부족 등)를 극복하기 위해 검색 증강 생성(RAG)과 도구 사용(Tool Usage) 같은 기법이 등장했으며, 이를 결합하여 추론(Reason)과 행동(Action)을 수행하는 ReAct 패턴을 통해 LLM이 더욱 복잡한 작업을 처리할 수 있게 된다고 강조한다. 연사는 에이전트 AI의 설계 양상과 실제 적용 사례를 제시하며, 개발 초기부터 체계적인 평가 전략을 수립하는 것이 중요하다고 말한다.

풀시청 판단

이 영상은 에이전트 AI의 개념과 활용 방식을 체계적으로 이해하고 싶은 개발자나 기획자에게 유용하다. LLM의 기본 원리부터 시작하여, LLM의 일반적인 한계점과 이를 극복하기 위한 RAG, 도구 사용 등 핵심 기법들을 직관적인 예시와 함께 설명한다. 에이전트 AI의 정의, ReAct 패턴, 그리고 계획(Planning), 자기 성찰(Reflection), 다중 에이전트 협업(Multi-Agent Collaboration)과 같은 주요 설계 양상들을 다루어 에이전트 시스템을 구상하는 데 필요한 기초 지식을 제공한다.

하지만 연사의 발표 스타일이 다소 단조로워 몰입도가 떨어질 수 있다. 또한, 소개되는 내용이 이미 널리 알려진 개념들의 정리 수준에 머물러 있어, 해당 분야에 대한 깊은 이해를 가진 전문가에게는 새로운 통찰을 주지 못할 가능성이 크다. 기술적인 세부 구현보다는 개념적 설명에 집중하므로, 실제 코드나 복잡한 아키텍처를 기대하는 사람에게는 다소 얕게 느껴질 수 있다.

영상을 전체 시청할 시간이 없다면, ### LLM 한계 극복을 위한 두 가지 주요 방법과 ### 에이전트 LLM: 추론(Reason)과 행동(Action)의 결합 (ReAct) 챕터를 집중적으로 보는 것을 추천한다. 이 두 챕터는 에이전트 AI가 기존 LLM의 한계를 어떻게 극복하며 복잡한 작업을 수행하는지 핵심 메커니즘을 설명한다.

핵심 내용

언어 모델(LLM)의 기본 원리 및 훈련 과정

언어 모델은 입력 텍스트가 주어졌을 때 다음에 올 단어를 예측하는 기계 학습 모델이다 [0:45]. 예를 들어, "학생들이 그들의"라는 입력이 주어지면, "책"이나 "노트북"과 같이 다음에 올 가능성이 높은 단어들을 예측한다. 이 모델은 크게 두 가지 단계를 거쳐 훈련된다.

첫 번째는 사전 훈련(Pre-training) 단계로 [1:50], 인터넷, 서적 등 공개된 대규모 텍스트 데이터를 사용하여 다음 단어 예측을 목표로 학습한다. 이 단계를 통해 모델은 방대한 세상 지식을 습득하게 된다 [4:43]. 두 번째는 후처리 훈련(Post-training) 단계로 [2:46], 모델이 특정 명령어에 따르거나 사용자가 기대하는 방식으로 응답하도록 가르친다. 여기에는 명령어 따르기 훈련과 인간 피드백 기반 강화 학습(RLHF)이 포함되며, 이를 통해 모델은 더욱 쉽고 유용하게 사용할 수 있는 형태로 정제된다 [3:22].

LLM 활용의 일반적인 한계점

강력한 언어 모델도 몇 가지 일반적인 한계를 가진다 [21:05]. 첫째, 환각(hallucination) 현상이 발생하여 모델이 부정확하거나 사실과 다른 정보를 생성할 수 있다 [21:11]. 이는 특히 계산이나 특정 전문 분야에서 더욱 두드러진다. 둘째, 모델 훈련에 사용된 데이터셋의 지식 최신성 부족(knowledge cut-off) 문제가 있다 [21:40]. 모델은 훈련 데이터 수집 시점 이후의 최신 정보를 알지 못한다.

셋째, 모델이 답변의 출처를 명확히 표기하지 못한다 [22:06]. 다양한 세상 지식을 활용하여 답변하지만, 특정 데이터 소스를 명시하지는 않는다. 넷째, 모델은 공개된 데이터로 훈련되므로 기업이나 개인의 **사유 데이터셋(proprietary data set)**을 활용할 수 없다 [22:31]. 마지막으로, **제한된 문맥 길이(context length)**는 여전히 모델의 한계로 작용한다 [22:51]. 문맥 길이가 길어질수록 모델에 더 많은 정보를 제공할 수 있지만, 이는 추론 비용 증가와 응답 지연을 초래한다.

LLM 한계 극복을 위한 두 가지 주요 방법

앞서 언급된 LLM의 한계를 극복하기 위해 두 가지 주요 방법이 사용된다.

첫째, **검색 증강 생성(RAG: Retrieval Augmented Generation)**은 모델의 환각을 줄이고, 출처를 명확히 하며, 사유 데이터셋을 활용할 수 있게 한다 [23:32]. 이 방법은 먼저 조직의 데이터셋이나 텍스트를 작은 덩어리로 분할하고, 이를 임베딩 모델을 통해 벡터 공간으로 변환하여 벡터 데이터베이스에 저장한다 [24:20]. 사용자 쿼리가 들어오면, 이 쿼리 역시 벡터로 변환하여 데이터베이스에서 가장 유사한 '상위 K개'의 관련 텍스트 덩어리를 검색한다. 이 검색된 정보를 LLM 프롬프트의 문맥으로 제공하여, 모델이 제공된 정보만을 바탕으로 답변을 생성하도록 유도한다 [25:05]. 이로써 모델은 최신 정보나 사유 데이터에 접근하여 보다 정확하고 신뢰성 있는 답변을 생성할 수 있다.

둘째, 도구 사용(Tool Usage) 또는 함수 호출(Function Calling)은 LLM이 외부 세계와 상호작용하도록 돕는다 [26:48]. LLM은 기본적으로 텍스트를 입력받아 텍스트를 출력하는 형태이므로, 외부에서 실시간 정보를 가져오거나 특정 계산을 직접 수행할 수 없다. 도구 사용은 LLM이 외부 API 호출이나 컴퓨터 코드 생성 등 특정 도구를 사용하는 명령어를 출력하도록 학습시키는 방법이다 [27:16]. 예를 들어, "샌프란시스코의 날씨"를 묻는 쿼리가 들어오면, LLM은 '날씨 정보 가져오기' 함수를 호출하는 코드를 생성하고, 외부 소프트웨어가 이 코드를 실행하여 실제 날씨 API로부터 정보를 얻는다 [28:08]. 이 정보는 다시 LLM에 입력되어 사용자에게 친숙한 형태로 최종 답변을 생성하는 데 활용된다 [28:45]. 이로써 LLM은 실시간 정보 접근, 계산 수행, 외부 시스템 제어 등 더욱 폭넓은 기능을 수행할 수 있게 된다.

에이전트 LLM: 추론(Reason)과 행동(Action)의 결합 (ReAct)

에이전트 LLM은 LLM이 환경과 상호작용하고, 더 복잡한 작업을 수행할 수 있도록 발전한 형태이다 [29:22]. 단순한 LLM이 텍스트 입력과 출력만 하는 것과 달리, 에이전트 LLM은 도구 사용이나 검색 요청을 통해 외부 환경과 소통하고, 그 결과를 '관찰(observation)'로 받아들여 다시 모델에 피드백할 수 있다 [29:52]. 이 과정에서 모델은 대화 기록 등을 '기억(memory)'하여 문맥을 유지한다.

에이전트 LLM의 핵심은 **추론(Reason)과 행동(Action)**을 결합한 ReAct (Reason and Action) 패턴으로 설명할 수 있다 [30:53].

  • 추론: 모델이 작업을 바로 수행하기보다, 사고의 연쇄(Chain of Thought; COT) 기법처럼 작업을 세분화하고 계획을 세우도록 유도하는 부분이다 [32:06].
  • 행동: RAG, 검색 엔진 사용, 계산기 호출, 날씨 API 호출, 파이썬 코드 생성 및 실행 등 외부 도구를 활용하여 실제 작업을 수행하거나 정보를 수집하는 부분이다 [31:18].

이러한 추론과 행동의 결합을 통해 에이전트 LLM은 고객 지원 에이전트가 환불 정책, 고객 정보, 제품 정보를 순차적으로 확인하고 종합하여 답변을 생성하는 것과 같이 [33:18], 복잡한 문제들을 단계적으로 해결할 수 있다. 이는 단순한 질의응답을 넘어 반복적인 호출과 외부 도구 사용을 통해 목표를 달성하는 방식이다 [35:21].

에이전트 LLM의 설계 양상 (Design Patterns)

에이전트 LLM을 구현하는 데 효과적인 몇 가지 설계 양상(design patterns)이 있다 [39:00].

  • 계획(Planning): 모델에게 복잡한 작업을 바로 지시하는 대신, 작업을 더 작고 명확한 하위 작업으로 나누고 이를 수행하기 위한 순서를 계획하도록 요청하는 것이다 [39:13]. 이 계획에 따라 모델은 API 호출이나 도구 사용을 결정한다.
  • 자기 성찰(Reflection): 모델이 자신이 생성한 출력에 대해 비판적인 피드백을 제공하고, 이 피드백을 바탕으로 다음 단계에서 출력을 개선하도록 하는 양상이다 [39:35]. 예를 들어, 코드 리팩토링 요청 시, 모델이 먼저 코드를 검토하고 피드백을 제공한 뒤, 이 피드백을 활용하여 코드를 개선하도록 지시할 수 있다 [40:27].
  • 도구 사용(Tool Usage): 이미 설명했듯이, LLM이 외부 세계의 실시간 정보나 특정 기능을 필요로 할 때, 외부 도구(API, 프로그램 등)를 호출하는 코드를 생성하고 그 결과를 활용하는 것이다 [39:57].
  • 다중 에이전트 협업(Multi-Agent Collaboration): 복잡한 단일 작업을 여러 개의 전문 에이전트로 분할하여 처리하는 방식이다 [42:06]. 각 에이전트는 특정 작업에 특화된 프롬프트나 '페르소나'를 가지며, 같은 LLM 또는 다른 LLM을 사용할 수 있다 [42:21]. 스마트 홈 자동화 시스템에서 기후 제어 에이전트, 조명 제어 에이전트 등이 서로 협력하여 전체 시스템을 운영하는 것이 좋은 예시이다 [43:00].

주요 통찰·논점

에이전트 AI는 LLM 활용의 자연스러운 발전 단계이다

에이전트 AI는 언어 모델 활용의 완전히 새로운 패러다임이 아니라, 기존 LLM 사용 방식의 발전이자 확장이다 [37:18]. 연사는 동일한 모델을 사용하더라도 단순히 직접적인 요청을 하는 대신 에이전트 패턴을 적용하면, 모델이 이전에는 할 수 없었던 더욱 복잡한 작업을 수행할 수 있다고 강조한다 [37:44]. 이는 LLM을 중심으로 소프트웨어 스캐폴딩과 반복적인 호출을 결합하여 모델의 잠재력을 최대한 끌어내는 방법론이다 [44:22].

외부 세계와의 상호작용이 LLM 능력 확장의 핵심이다

LLM은 자체적인 지식과 추론 능력에 한계가 있지만, 검색 증강 생성(RAG)과 도구 사용(Tool Usage)을 통해 외부 세계와 상호작용하면서 그 능력을 확장한다. RAG는 LLM이 최신 정보나 사유 데이터에 접근하여 환각을 줄이고 출처를 명확히 하는 반면 [23:38], 도구 사용은 LLM이 실시간 정보 검색, 계산 수행, 외부 시스템 제어 등 동적인 행동을 가능하게 한다 [27:16]. 이러한 상호작용 메커니즘은 LLM이 단순한 텍스트 생성기를 넘어 실제 문제를 해결하는 유능한 '에이전트'가 되도록 만든다.

체계적인 프롬프트 엔지니어링과 계획 수립이 성공의 기반이다

에이전트 LLM의 효과를 극대화하기 위해서는 체계적인 프롬프트 엔지니어링이 필수적이다 [7:07]. 연사는 명확하고 상세한 지시, 몇 가지 예시(few-shot examples) 제공, 관련 문맥 및 참조 자료 제공, 사고의 연쇄(Chain of Thought; COT)를 통한 '생각할 시간' 부여, 복잡한 작업을 작은 단계로 분할하는 것 등을 좋은 프롬프트 전략으로 제시한다 [7:23]. 특히, 모델이 스스로 작업을 세분화하고 계획을 수립하도록 요청하는 계획(Planning) 양상은 에이전트 시스템의 성능을 결정하는 핵심 요소이다 [39:13].

개발 초기부터 체계적인 평가 전략 수립이 중요하다

LLM 및 에이전트 기술은 매우 빠르게 발전하고 모델 역시 지속적으로 개선되거나 빠르게 단종될 수 있다 [16:20]. 이러한 환경에서 명확한 평가 방법론 없이는 개발 진행 상황을 파악하기 어렵고, 모델이나 프롬프트를 변경했을 때의 영향을 측정할 수 없다 [16:32]. 연사는 개발 초기부터 질문-정답 쌍을 포함한 근거 데이터셋(ground truth)을 준비하고, LLM을 평가자로 활용하거나 자기 성찰(Reflection) 패턴을 적용하여 평가의 질을 높이는 전략을 권장한다 [15:25], [45:19].

인상적인 지점

  • '생각할 시간'을 주는 프롬프트의 효과 [11:40]: LLM에 복잡한 문제를 즉시 해결해 달라고 요청하는 대신, "먼저 문제에 대한 당신의 해결책을 제시한 후 학생의 해결책과 비교하라"와 같이 모델 스스로 사고 과정을 거치게 유도하는 프롬프트가 훨씬 정확한 결과를 도출한다는 점이 인상적이다 [12:45]. 이는 LLM이 단순히 입력에 대한 가장 확률 높은 다음 토큰을 생성하는 것을 넘어, 내부적으로 '추론' 과정을 거치도록 유도할 수 있음을 보여준다.
  • 자기 성찰(Reflection)을 활용한 평가 개선 [46:07]: LLM을 평가자로 활용할 때도 단순히 한 번의 평가로 끝내지 않고, '주니어 엔지니어의 피드백을 시니어 엔지니어의 관점에서 재평가'하는 비유처럼, 모델이 스스로의 초기 평가나 출력을 비판적으로 검토하고 개선하도록 유도하는 자기 성찰 패턴이 더 나은 평가 결과를 가져온다는 점이 흥미롭다. 이는 에이전트 AI의 핵심 양상을 평가 자체에도 적용하여 효율성을 높이는 창의적인 방법이다.
