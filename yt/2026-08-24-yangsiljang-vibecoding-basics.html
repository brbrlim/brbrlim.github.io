풀시청 판단

이 영상은 AI를 활용해 실제 웹 서비스를 구축하고 배포하는 전 과정을 생생하게 보여주므로, AI 기반 개발에 관심 있는 비개발자 또는 개발 초기 단계의 학습자에게 매우 유용하다. 특히 AI 툴(Codex, Claude)을 활용해 PRD 작성부터 기술 스택 결정, 코드 해부, 실제 배포까지 이어지는 흐름은 AI 개발의 현실적인 모습과 난이도를 체감하게 한다.

이런 사람에게 추천한다:

  • Vibe 코딩의 실제 적용 사례를 알고 싶은 비개발자: AI를 이용해 아이디어를 실제 서비스로 구현하는 과정을 처음부터 끝까지 상세히 볼 수 있다.
  • AI 개발의 한계와 비개발자의 역할에 관심 있는 사람: AI가 만능이 아님을 인지하고, AI의 결과물을 검증하고 수정하는 인간의 역할이 얼마나 중요한지 깨달을 수 있다.
  • 웹 서비스 개발에 필요한 기본 기술 개념을 익히고 싶은 사람: 프런트엔드, 백엔드, 데이터베이스, API, CI/CD 등 핵심 기술 용어를 실제 사례와 연동하여 직관적으로 이해할 수 있다.
  • AI와 대화하며 문제를 해결하는 프롬프트 엔지니어링 실력을 키우고 싶은 사람: 강사가 AI와 상호작용하며 55가지 기술을 선택하고 에러를 해결하는 과정을 통해 실질적인 프롬프트 작성 노하우를 얻을 수 있다.

약점 및 한계:

  • 긴 러닝타임과 높은 정보 밀도: 3시간에 달하는 분량과 방대한 기술 스택 설명은 한 번에 소화하기 어려울 수 있다. 실습과 병행하지 않으면 단순히 시청하는 것만으로는 체득하기 어렵다.
  • 실시간 개발의 한계: AI가 코드를 생성하고 수정하는 과정에서 발생하는 대기 시간은 편집으로 줄였지만, 실제 작업 시에는 훨씬 더 많은 시간이 소요될 수 있다.
  • 깊이 있는 기술 설명 부족: 각 기술에 대한 설명은 비개발자 눈높이에 맞춰 직관적으로 이루어지지만, 특정 기술의 작동 원리나 세부적인 구현 방식까지 깊이 있게 다루지는 않는다. 이는 AI에게 지시하기 위한 최소한의 이해를 돕는 데 초점을 맞추기 때문이다.

이 영상은 전체 흐름을 따라가며 비개발자가 Vibe 코딩을 통해 무엇을 할 수 있고, 무엇을 알아야 하는지 파악하는 데 집중한다. 특히 [16:20]부터 시작하는 55가지 기술 스택 의사결정 과정과 [1:55:17]부터의 소스 코드 해부 과정을 면밀히 시청하고 직접 실습하는 것을 추천한다.

핵심 내용

Vibe 코딩의 역할: AI를 통한 잠재력 극대화

Vibe 코딩은 AI의 역량을 지렛대처럼 활용하여 최소한의 노력으로 최대의 결과를 얻는 방법을 의미한다 [0:34]. 지렛대 비유에서, 노력(누르는 힘)을 들이는 만큼 결과물이 커지는 비율은 '지뢰밭의 지뢰 모양'에 따라 달라진다. 이때 지렛대의 길이는 '잠재력의 크기'를, 받침대(지뢰)의 위치는 '결과의 크기'에 직접적인 영향을 미치는 요인이다 [2:04]. Vibe 코딩은 AI가 개발, 디자인, 기획, PM 등의 역할을 대신 수행함으로써 비개발자도 잠재력을 확장하고 직접적인 결과물을 만들어낼 수 있게 돕는 도구다. Claude, Codex 같은 LLM 기반 AI 툴이 대표적이다 [4:52].

LLM의 작동 방식과 한계: 비개발자 지식의 중요성

Vibe 코딩 툴의 핵심은 LLM(거대 언어 모델)이다. LLM은 주어진 문맥에서 다음 단어를 가장 자연스러운 방식으로 생성하는 방식으로 작동한다 [6:05]. 이는 마치 '단 한 장의 A4 용지'에 비유할 수 있는데, 이는 LLM이 무한한 기억력을 가진 만능 도구가 아니라는 한계를 시사한다 [7:06]. 따라서 비개발자가 Vibe 코딩으로 결과물을 만들 때, LLM이 과거 학습 데이터 기반으로 '일반적인 방식'의 결과물을 내놓으므로, 특정 프로젝트의 고유한 요구 사항을 충족하기 어렵거나 오류, 보안, 사용성 문제가 발생하기 쉽다 [7:59]. 이러한 한계를 극복하려면 비개발자는 기획자, 디자이너, 개발자, PM의 '언어와 기억'을 이해하고, AI가 만들어낸 결과물을 정확히 읽고 이해하는 능력(진단 능력)을 길러야 한다 [9:59].

시스템 구현 난이도 분류: 누구/어디에서 사용하는가?

시스템 구현의 난이도는 복잡한 AI 기술이 적용되었는지보다 '누가', '어디서' 사용하는지에 따라 결정된다 [14:44].

  1. 나만 내 컴퓨터에서 사용: 클릭만으로 거의 모든 것이 가능하다.
  2. 다른 사람이 내 컴퓨터에서 사용: 사용성 문제가 발생하기 시작한다 (예: 사용자가 시스템을 '망치로 때려 부수는' 상황) [15:39].
  3. 나만 원격으로 사용: 보안 문제가 즉시 발생한다.
  4. 다른 사람이 원격으로 사용: 가장 어려운 단계로, 사용성과 보안, 에러 처리 등 모든 구현 범위가 확장된다 [15:57]. 따라서 AI 기반 개발 시, 목표하는 서비스의 사용 환경을 명확히 정의하고 그에 맞는 난이도를 고려해야 한다.

정석몰 개발 데모 (1): PRD 작성 및 MD 파일 이해

강의는 '정석몰'이라는 가상의 e-북 쇼핑몰을 구축하는 실전 데모를 진행한다. 첫 단계는 PRD(제품 요구 사항 문서) 작성이다 [16:35]. PRD에는 제품 목표, 핵심 성과 지표, 주요 사용자, P0(필수), P1(권장), P2(후속 개선) 기능 우선순위, 종료 전략 등이 포함된다 [28:36]. AI는 이러한 요구사항을 바탕으로 마크다운(Markdown, .md) 형식의 문서를 생성한다. .md 파일은 AI 개발에서 표준적으로 사용되는 텍스트 파일 형식으로, 가독성을 높여주는 특징이 있다 [29:18]. 강사는 PRD의 상세 내용을 직접 설정하며 AI가 생성한 초안을 수정하고 피드백하여 최종 PRD를 완성한다 [32:01].

정석몰 개발 데모 (2): 55가지 기술 스택 의사결정 과정

PRD를 바탕으로 AI와 대화하며 기술 스택을 결정하는 과정이 이어진다. 이 과정은 연구, 학습, 결정, 최종 검토의 4단계로 진행된다 [37:27]. 강사는 비개발자 관점에서 AI에게 각 기술에 대한 개념적 설명, 장단점, 대안 등을 질의하며 55가지 기술을 하나씩 선택한다 [39:31]. 주요 기술 스택의 개념과 선택 기준은 다음과 같다.

  • 프런트엔드: 웹사이트 화면을 만드는 기술. Next.js 16 (서버와 클라이언트 동시 개발 가능, SEO 최적화, 쉬운 배포) [45:01], React 19 (UI 컴포넌트 담당, Next.js의 기반) [1:01:08], TypeScript (JavaScript에 타입 검사 기능 추가, 오류 발견 용이) [54:54].
  • 백엔드: 데이터베이스와 클라이언트를 연결하는 API 기술. Node.js (JavaScript 서버 실행 환경, Next.js와 호환성 우수) [56:00].
  • 패키지 관리: PNPM (패키지 설치 및 관리, NPM의 대안으로 속도 및 효율성 우수) [58:05].
  • 스타일링/UI: Tailwind CSS (미리 정의된 스타일 유틸리티 클래스 제공, 높은 커스터마이징 자유도) [1:03:06], Shard CN (Tailwind CSS 기반의 재사용 가능한 UI 컴포넌트 세트, 일관된 디자인 유지) [1:07:08].
  • 데이터베이스: PostgreSQL (관계형 데이터베이스, 유연성 및 강력한 기능으로 현재 가장 인기) [1:11:06].
  • 인증/스토리지: Superbase (인증, 데이터베이스, 스토리지 등 백엔드 기능 통합 제공, 빠른 개발에 용이하나 높은 의존성) [1:13:47]. Superbase Auth (회원가입, 로그인 등 인증 기능) [1:20:17] [1:23:18].
  • 결제: Toss Payments Widget (안정적이고 고품질의 UI 제공) [1:26:31].
  • 배포/자동화: Vercel (Next.js에 최적화된 배포 플랫폼) [1:28:37], GitHub Actions (코드 업로드 시 자동 테스트 및 배포 등 CI/CD 자동화) [1:32:23].
  • 테스트/모니터링: Jest, Testing Library, Playwright (각각 단위, UI 컴포넌트, E2E 테스트 도구) [1:30:26], Sentry (실제 서비스의 에러 모니터링) [1:31:08].

정석몰 개발 데모 (3): 생성된 소스 코드 해부 및 에러 해결

AI가 완성한 정석몰 웹 서비스의 소스 코드를 Visual Studio Code(VS Code)를 이용해 해부한다 [1:56:07]. AI는 비개발자가 코드를 이해할 수 있도록 주석(코드 내 설명 텍스트)을 상세하게 추가하고 코드 리뷰 가이드를 제공한다 [1:55:17]. 주요 코드 파일과 구조는 다음과 같다:

  • page.tsx: 고객 또는 관리자에게 보이는 화면의 프런트엔드 코드. Next.js의 폴더 구조와 URL 경로가 일치하는 방식으로 구성된다 [2:16:01].
  • route.ts: 화면 뒤에서 주문 처리, 결제 등 서버 기능을 담당하는 API 코드 [2:19:03]. Next.js의 경우 API 기능도 프런트엔드 코드와 함께 한 프로젝트 내에서 관리된다.
  • Superbase/migration/*.sql: 데이터베이스의 테이블 생성, 수정, 삭제 이력을 관리하는 파일 [2:20:50].
  • .env, package.json: 환경 변수(DB 연결 키 등)와 프로젝트 의존성(설치된 패키지 목록)을 정의하는 파일이다 [2:07:00].
  • global.css: 전체 웹 서비스의 색상, 글꼴, 버튼 모양 등 스타일을 정의하는 파일 [2:37:19]. 또한, 강사는 시연 중 발생한 결제 버튼 에러를 AI와의 대화를 통해 원인을 파악하고 즉시 수정하여 문제를 해결하는 과정을 보여준다 [2:43:18].

정석몰 개발 데모 (4): 웹 서비스 온라인 배포

마지막 단계는 로컬 환경에서만 실행되던 정석몰 웹 서비스를 온라인에 배포하는 과정이다 [2:47:01]. Vercel에 로그인 후 pnpm deploy 명령을 통해 배포를 진행한다. Vercel은 Next.js에 최적화된 배포 플랫폼으로, 원클릭에 가까운 간편한 배포를 지원한다 [49:03]. 배포가 완료되면 온라인 주소(URL)를 통해 PC 웹브라우저뿐만 아니라 모바일에서도 서비스에 접속할 수 있음을 확인한다 [2:50:50].

실전 과제: 국내 서비스 모방 웹 서비스 구축

강의 마지막에는 수강생들이 스스로 학습한 내용을 적용해볼 수 있는 실전 과제를 제시한다. 당근마켓, 소모임, 스페이스클라우드, Flow, 뱅크샐러드, 채널톡 등 익숙한 국내 웹/모바일 서비스 중 하나를 선택하여, 기본적인 기능(예: 상품 등록, 채팅, 예약, 자산 관리 등)을 Vibe 코딩으로 구현하고 배포해보는 과제다 [2:53:43]. 이는 배운 지식을 실제 아이디어 구현으로 연결하고, AI가 생성한 결과물을 능동적으로 검증하며 문제를 해결하는 능력을 키우는 데 목적이 있다.

주요 통찰·논점

비개발자 Vibe 코더의 핵심 역량: AI 결과물 해독 능력

AI 기반 Vibe 코딩의 핵심은 AI 툴의 사용법을 아는 것이 아니라, AI가 생성한 결과물(코드, 문서, 시스템)을 비개발자가 '얼마나 깊이 이해하고 진단할 수 있는가'에 달렸다 [9:28]. AI는 학습된 데이터를 기반으로 '일반적인' 해결책을 제시하기 때문에, 특정 프로젝트의 고유한 요구 사항이나 잠재적 오류, 보안 취약점을 완벽하게 처리하지 못한다 [7:51]. 따라서 비개발자는 기획, 디자인, 개발, 프로젝트 관리 등 각 분야의 '언어와 기억'을 이해하여 AI의 결과물을 능동적으로 검토하고, 문제 발생 시 AI와 대화하며 수정하고, 최종적으로 서비스의 신뢰성을 판단할 수 있는 능력을 갖춰야 한다 [9:59]. 이는 단순히 AI에 의존하는 것을 넘어, AI를 효과적인 협력자로 활용하기 위한 필수 역량이다.

기술 스택 선택 기준: 맥락과 의존성 이해

기술 스택을 선택할 때는 각 기술의 개념, 장단점뿐만 아니라 프로젝트의 '맥락'과 '의존성'을 이해하는 것이 중요하다. 예를 들어, Next.js를 선택하면 React는 자연스럽게 따라오는 기반 기술이 되며, Vercel은 Next.js에 최적화된 배포 환경을 제공하여 긴밀한 의존 관계를 형성한다 [49:03]. Superbase는 인증, 데이터베이스, 스토리지 등 여러 기능을 통합하여 개발 속도를 높이지만, 특정 서비스에 대한 '의존성'이 높아 장기적인 프로젝트나 서비스 확장 시 제약이 될 수 있다 [1:14:40]. 강사는 이러한 의존성 문제를 인지하고, 실습 단계에서는 Superbase를 사용하되 향후 다른 강의에서는 더 자율성이 높은 Rail 등으로 전환할 계획임을 미리 밝힌다 [1:15:56]. 비개발자는 AI에게 단순히 '무엇을 만들라'고 지시하는 것을 넘어, 각 기술의 특징과 상호 관계, 그리고 프로젝트 규모에 따른 적절한 선택 기준을 이해해야 한다.

AI 기반 개발의 실용적 한계와 극복 방안

AI 기반 개발은 '만능'이 아니며, 특히 실제 운영 환경으로 갈수록 한계가 명확해진다.

  • 오류 및 보안: AI가 생성한 코드는 개발자의 의도와 다르게 작동하거나, API 키 유출과 같은 치명적인 보안 문제를 야기할 수 있다 [12:31]. 이를 위해 Sentry와 같은 에러 모니터링 툴, RLS (행 수준 보안), MFA (다단계 인증), 강력한 비밀번호 정책 등 보안 관련 기술 선택을 신중히 고려해야 한다 [1:41:34].
  • 사용성: '나만 쓰는' 시스템과 '다수가 쓰는' 시스템은 사용성 측면에서 큰 차이가 있다 [15:22]. 이를 해결하기 위해 Shard CN과 같이 재사용 가능한 UI 컴포넌트 세트를 활용하여 일관되고 안정적인 사용자 경험을 제공한다 [1:07:08].
  • 디버깅 능력: AI는 에러 발생 시 원인 분석과 해결책을 제시할 수 있지만, 이를 이해하고 적용하는 것은 결국 인간의 몫이다. 강사가 시연 중 발생한 결제 에러를 AI와 대화하며 해결하는 과정은 비개발자도 '진단' 능력을 통해 AI의 한계를 극복할 수 있음을 보여준다 [2:43:18].

자동화된 개발 환경과 CI/CD의 중요성

현대 소프트웨어 개발에서 CI/CD(지속적 통합/지속적 배포)는 선택이 아닌 필수다. CI/CD는 코드 변경 시 자동으로 테스트하고 빌드하여 배포하는 일련의 과정을 의미한다 [1:33:30]. GitHub Actions와 같은 툴을 활용하면 개발자가 코드를 수정하여 저장소에 올리는 것만으로, 미리 정의된 규칙에 따라 자동으로 배포 전 테스트를 수행하고 배포까지 완료할 수 있다 [1:32:23]. 이는 수동 작업에서 발생하는 실수를 방지하고, 개발 생산성을 크게 향상시킨다. 또한, Vercel과 같은 플랫폼은 이러한 CI/CD 환경 구축을 매우 용이하게 하여 비개발자도 손쉽게 배포 자동화를 구현할 수 있도록 돕는다 [1:28:37].

데이터 및 코드 관리의 기본 원칙

성공적인 웹 서비스 개발 및 유지보수를 위해서는 데이터와 코드의 체계적인 관리가 필수적이다.

  • 데이터베이스 마이그레이션: 데이터베이스의 구조 변경(테이블 생성, 수정, 삭제)은 단순한 작업이 아니다. SQL 마이그레이션은 이러한 변경 이력을 .sql 파일로 기록하고 순서대로 적용/되돌릴 수 있게 하여, 데이터베이스의 안정적인 버전 관리를 가능하게 한다 [1:17:29]. 이는 마치 코드 버전 관리와 유사하며, 문제가 발생했을 때 안전하게 이전 상태로 복구할 수 있는 기반이 된다.
  • 코드 버전 관리: Git은 소스 코드 변경 이력을 기록하고 관리하는 데 사용되는 필수 도구다 [1:36:29]. GitHub와 같은 서비스는 Git 기반의 원격 저장소를 제공하여 여러 개발자가 협업하거나 개인 프로젝트의 변경 이력을 체계적으로 관리할 수 있게 한다 [1:37:11].
  • 코드 스타일 및 품질: ESLint와 Prettier는 코드의 형식(띄어쓰기, 줄 바꿈 등)과 문법 오류를 자동으로 검사하고 수정하여, 코드의 일관성과 품질을 유지하는 데 기여한다 [1:34:44]. 이는 가독성을 높이고 협업 효율성을 증진하는 데 중요하다.

인상적인 지점

  • AI의 'A4 용지' 비유: LLM의 기억력 한계를 '한 장의 A4 용지'에 비유하여 비개발자도 직관적으로 AI의 한계를 이해할 수 있게 설명한 점이 인상 깊다 [7:06].
  • 사용자가 시스템을 '망치로 때려 부수는' 비유: 개발자가 의도한 행복 경로(Happy Pass) 외의 상황에서 사용자가 시스템을 무작위로 조작할 때 '망치로 때려 부수는' 것과 같다는 비유는 사용성 문제를 매우 현실적으로 와닿게 설명한다 [15:39].
  • 실시간 에러 진단 및 해결: 시연 도중 발생한 결제 에러를 AI와의 대화(프롬프트)를 통해 원인을 파악하고 해결하는 과정은 AI 기반 개발의 현실적인 모습과 비개발자의 능동적인 역할의 중요성을 극명하게 보여준다 [2:43:18]. 이는 강사가 강조한 '진단 능력'의 실제 적용 사례다.
  • '개발 지원자' 프롬프트의 수정: AI가 '개발 지원자에게 설치 요청'하라는 가이드를 제시했을 때, 강사가 '나는 개발 지원자가 없으니 스스로 할 수 있게 가이드하라'고 프롬프트를 수정하여 AI의 답변을 보정하는 모습은 AI와의 대화에서 비개발자의 명확한 지시가 얼마나 중요한지를 보여준다 [2:01:47].
