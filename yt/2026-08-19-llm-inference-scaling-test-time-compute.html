TL;DR

이 영상은 LLM(대규모 언어 모델)의 '추론 확장(inference scaling)' 개념을 탐구한다. 모델의 매개변수를 바꾸거나 미세 조정(fine-tuning)하지 않고도 추론 시 더 많은 연산을 투입하여 모델의 성능을 향상하는 방법을 제시한다. 특히 반복 샘플링(repeated sampling), 순차적 수정(sequential revisions), 과정 보상 모델(process reward models, PRM) 및 결과 보상 모델(outcome reward models, ORM) 같은 다양한 기법을 소개하며, '추론 아키텍처 탐색(Inference Architecture Search, Archon)' 프레임워크를 통해 이들을 최적화하여 오픈소스 모델이 최신 비공개 모델을 능가할 수 있음을 보여준다.

풀시청 판단

이 영상은 LLM의 추론 성능을 최적화하고 개선하는 방법에 관심 있는 연구자, 엔지니어, 대학원생에게 매우 유용하다. 전학습(pre-training)이나 미세 조정을 넘어선 추론 단계에서의 혁신적인 접근법과 그 효과를 구체적인 사례와 데이터로 설명한다.

특히 다음의 내용을 얻을 수 있다.

  • LLM 성능 향상 패러다임의 변화: 기존의 모델 크기나 학습 데이터 확장을 넘어 추론 시 연산 투입을 통한 성능 향상 가능성을 이해한다.
  • 다양한 추론 확장 기법: 반복 샘플링, 순차적 수정, 과정/결과 보상 모델, 그리고 Archon 프레임워크가 제안하는 융합(fusion), 비판(critic), 순위(ranker) 등의 기법을 배운다.
  • 검증기(verifier)의 중요성: 효과적인 추론 확장을 위해 자동화된 검증 메커니즘이 얼마나 필수적인지, 그리고 현재 '생성-검증 간극(generation-verification gap)'이 존재하는 이유를 파악한다.
  • 실험적 통찰: 문제 난이도에 따른 최적의 추론 전략, 추론 계층을 쌓아 올릴 때의 성능 개선 효과, 그리고 오픈소스 모델이 최신 비공개 모델을 능가할 수 있는 잠재력을 확인한다.

약점 및 한계:

  • 학술적 발표 형식: 학생들과의 질의응답 시간이 포함되어 있어 강의 흐름이 다소 끊길 수 있다. 또한, 발표자가 "um"이나 "uh" 같은 추임새를 자주 사용한다.
  • 시각 자료의 제한적 노출: 일부 그래프나 아키텍처 다이어그램이 영상에서는 명확하게 보이지 않거나 빠르게 지나가 브리핑만으로는 모든 세부 사항을 파악하기 어려울 수 있다.
  • 다소 높은 진입 장벽: LLM의 전학습, 미세 조정, 에이전트(agent) 등 기본적인 LLM 개발 및 연구 지식이 없으면 내용 이해가 어려울 수 있다.

핵심 내용

LLM 개발의 세 단계와 추론 확장(Inference Scaling)의 중요성

LLM 개발은 크게 세 단계로 나뉜다. 첫 번째는 전학습([0:18])으로, 수개월과 많은 GPU가 소요되는 가장 계산 집약적인 과정이다. 두 번째는 미세 조정([0:30])으로, 전학습에 비해 적은 데이터와 컴퓨팅 자원을 사용한다. 마지막 세 번째는 추론([0:50]) 단계로, 모델을 실제로 사용하는 시점이다. 이 강의는 추론 단계에서 모델 매개변수나 미세 조정을 변경하지 않고도 모델 성능을 향상하고 더욱 유용하게 만드는 다양한 방법을 다룬다.

Large Language Monkeys: 반복 샘플링으로 열등 모델 강화

'Large Language Monkeys' 논문은 LLM에 동일한 문제를 반복적으로 입력하여 여러 개의 응답을 생성하고, 이들 중 가장 정확한 응답을 선택하는 방식(반복 샘플링)을 제안한다([1:12]). 예를 들어 10번 또는 100번 반복 샘플링을 통해, 한 번의 시도로는 GPT-4o 같은 최신 모델에 비해 성능이 낮은 Llama 3 8B 같은 모델도 성능을 크게 향상할 수 있다. 이는 모델이 이미 정답을 알고 있지만 첫 시도에 이를 드러내지 않을 뿐이며, 반복 샘플링을 통해 숨겨진 능력을 끌어내는 것과 같다고 설명한다([2:53]). 이러한 방식은 수학, 코딩, 문제 해결 등 다양한 에이전트(agentic) 벤치마크에서 효과적임이 입증됐다([3:16]).

추론 단계 스케일링 법칙(Inference Scaling Laws)의 발견

전학습에서 모델의 성능(테스트 손실)이 데이터, 연산량, 매개변수 수에 따라 예측 가능하게 개선되는 스케일링 법칙이 존재하는 것처럼, 추론 단계에서도 유사한 스케일링 법칙이 발견됐다([5:17]). 이 법칙은 모델이 문제를 해결하는 비율인 커버리지(C)가 샘플 수(K)에 대해 지수적 멱법칙(exponential power law) 관계를 따른다는 것을 보여준다(C = A * K^B). Llama 3 8B부터 Gemma, Pythia에 이르는 다양한 모델과 7천만 개에서 7백억 개에 이르는 다양한 매개변수 크기에서 이러한 멱법칙 관계가 예측 가능하게 나타났다([6:03]). 이는 특정 커버리지를 달성하는 데 필요한 샘플 수와 자원 할당량을 예측할 수 있게 한다.

멱법칙의 근거: '꼬리가 긴' 어려운 문제의 존재

개별 문제에 대한 정답률(pass@1)이 주어졌을 때, K번의 샘플링에서 최소 한 번 정답이 나올 확률(pass@K)은 지수 함수를 따른다([8:01]). 그러나 여러 문제에 걸쳐서는 멱법칙 스케일링이 나타나는데, 이는 문제 세트 내에 '꼬리가 긴' 분포의 매우 어려운 문제들이 존재하기 때문으로 분석됐다([9:31]). 즉, 대부분의 문제는 한 번의 시도로도 쉽게 해결되지만, 소수의 극도로 어려운 문제들은 여러 번 샘플링해야 해결될 가능성이 높아지며, 이러한 문제들이 전체 커버리지 곡선에 멱법칙 형태를 부여한다는 것이다.

검증기(Verifier)의 중요성: 생성-검증 간극(Generation-Verification Gap)

반복 샘플링의 효과를 극대화하려면 생성된 여러 응답 중 올바른 것을 선택할 수 있는 자동화된 검증기가 필수적이다([12:23]). 코딩 문제의 단위 테스트([13:08])나 CUDA 코드 생성 같은 변환 작업([13:40])에서는 검증이 비교적 쉽다. 그러나 검증기가 없는 도메인에서는 다수결 투표(majority voting) 같은 단순한 방법으로는 성능 향상에 한계가 있으며, 완벽한 검증기가 있을 때 달성 가능한 잠재적 성능(커버리지)과의 큰 간극, 즉 '생성-검증 간극'이 존재한다([15:35]). 이 간극은 특히 어려운 문제에서 더욱 두드러진다.

추론 확장 기법: 병렬 샘플링을 넘어 순차적 수정(Sequential Revisions)과 과정/결과 보상 모델(Process/Outcome Reward Models)

추론 시 연산을 확장하는 방법에는 단순히 여러 답안을 병렬로 생성하는 '병렬 샘플링' 외에도 '순차적 수정'([27:35])이 있다. 순차적 수정은 모델이 하나의 초기 답안을 생성한 후, 이를 다양한 관점에서 계속 수정하고 개선해 나가는 방식이다. 또한, 답안의 품질을 평가하는 보상 모델(reward model)을 활용할 수 있다. '결과 보상 모델(Outcome Reward Model, ORM)'([28:57])은 최종 답안의 품질에 점수를 부여하며, '과정 보상 모델(Process Reward Model, PRM)'([29:25])은 답안 생성 과정의 각 단계에 점수를 부여한다. PRM은 빔 탐색(beam search)과 같은 탐색 알고리즘에 통합되어 모델의 샘플링 과정을 안내하고 유망한 경로를 선택하도록 돕는다([31:12]). ORM과 PRM을 병렬 샘플링 및 순차적 수정과 결합하면 더 나은 결과를 얻을 수 있다([33:14]).

난이도에 따른 최적 추론 전략

문제의 난이도에 따라 최적의 추론 확장 전략이 달라진다는 점이 관찰됐다([37:01]). 쉬운 및 중간 난이도 문제의 경우, 추가적인 추론 연산 투입이 모델의 전학습(pre-training) 규모를 늘리는 것보다 더 효율적일 수 있다([38:08]). 이는 오픈소스 모델이나 더 작은 모델들이 추론 시 충분한 연산을 받으면 매우 유용해질 수 있음을 시사한다. 그러나 매우 어려운 문제의 경우, 여전히 더 많은 전학습을 거친 크고 강력한 최신 모델(frontier models)이 더 나은 성능을 보인다([39:00]).

주요 통찰·논점

추론 아키텍처 탐색(Inference Architecture Search, Archon) 프레임워크

Archon([45:47])은 LLM의 추론 확장을 '추론 아키텍처 설계' 문제로 접근하는 프레임워크다. 주어진 벤치마크, 추론 예산, 사용 가능한 LLM, 그리고 다양한 추론 기법들을 조합하여 정확도 대 비용 최적화의 한계선을 탐색한다([46:43]). Itas(Inference Time Architecture Search)라는 최적화 도구를 사용하여, 병렬 샘플링, 순차적 수정 등의 기법과 여러 모델을 조합하는 최적의 아키텍처를 찾아낸다.

Archon의 핵심 추론 연산

Archon은 다음을 포함한 다양한 추론 시 연산(inference time operations)을 정의한다.

  • 생성(Generation): 모델로부터 여러 응답을 샘플링하는 기본적인 과정이다([48:10]).
  • 융합(Fusion): K개의 응답이 있을 때, 또 다른 LLM에 이 K개의 응답과 원래 질문을 입력하여 하나의 최종 응답을 합성하도록 요청하는 기법이다. 이 과정에서 LLM은 가능한 모든 응답 방식을 고려하여 최적의 답안을 생성한다([48:42]).
  • 비판(Critic): 주어진 응답의 강점과 약점을 모델이 평가하도록 요청하는 연산이다([49:53]).
  • 순위(Ranker): 여러 생성된 응답의 품질에 따라 순위를 매기도록 모델에 요청하는 연산이다([50:09]).
  • 단위 테스트 생성 및 평가: 모델이 코딩 문제나 추론 문제에 대한 단위 테스트를 직접 생성하고, 그 단위 테스트를 사용하여 생성된 답안을 평가하도록 요청하는 연산이다([55:01]).

추론 계층의 심화(Stacking Layers) 효과

Archon 연구는 여러 추론 연산 계층을 깊게 쌓아 올릴수록 정확도가 크게 향상된다는 흥미로운 특성을 발견했다([58:31]). 예를 들어, 생성, 비판, 순위, 융합 같은 연산들을 여러 층으로 조합한 복잡한 아키텍처는 단순히 모델을 한 번 사용하거나 융합 계층을 한 번만 사용하는 것보다 훨씬 뛰어난 성능을 보였다. 이는 딥러닝에서 신경망의 깊이가 성능에 영향을 미치는 것과 유사하게, 추론 아키텍처에서도 신중하게 추가된 계층들이 모델의 정확도를 점진적으로 높이는 데 기여한다는 의미다([59:20]).

오픈소스 모델로 프런티어 모델 능가

Archon 프레임워크를 통해 최적화된 추론 아키텍처를 사용함으로써, 오픈소스 모델만으로도 당시 최신 비공개 모델(예: GPT-4o, Claude 3.5 Sonnet)의 Pass@1 성능을 여러 태스크에서 평균 14.1%([1:02:45]) 능가하는 결과를 달성했다. 이는 추론 시 연산을 지능적으로 활용하는 방식이 모델 자체의 크기나 독점 기술만큼 강력할 수 있음을 보여주는 중요한 통찰이다([1:01:31]). 또한 Archon은 특정 태스크에 최적화되거나 범용적으로 활용되도록 훈련될 수 있으며, 범용 Archon도 매우 뛰어난 성능을 보였다.

인상적인 지점

  • "LLM들은 이미 정답을 알고 있지만, 첫 시도에 우리에게 말해주지 않을 뿐이다"라는 말은, 모델의 잠재력을 끌어내는 데 반복적 시도와 적절한 방법론이 얼마나 중요한지 직관적으로 보여준다([2:53]).
  • 여러 응답을 LLM에 입력하여 하나의 더 나은 응답을 합성하는 '융합(Fusion)' 기법이 완벽한 검증기(Oracle selection)보다도 뛰어난 성능을 낸다는 사실은 매우 놀랍다([53:03]). 이는 LLM이 단순히 답안을 걸러내는 것을 넘어, 여러 정보를 통합하고 추론하여 새로운 가치를 창출하는 능력을 보여준다.
  • 딥러닝 모델의 층을 쌓아 올리듯, '추론 계층'을 여러 번 중첩했을 때 모델의 정확도가 크게 향상된다는 관찰은, 추론 과정 자체를 깊이 있는 계산 그래프로 볼 수 있다는 새로운 시각을 제시한다([59:20]).
