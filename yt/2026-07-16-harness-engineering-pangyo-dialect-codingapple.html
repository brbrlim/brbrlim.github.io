요즘 판교사투리 1. "하네스 엔지니어링"

코딩애플5:26게시 2026-06-10
#ai#harness-engineering#agent#llm#prompt-engineering#codingapple

TL;DR

이 영상은 최근 AI 개발 분야에서 유행하는 '하네스 엔지니어링' 개념을 소개한다. 과거 프롬프트 엔지니어링이 AI의 질문 답변 능력을 향상하는 데 집중했다면, 하네스 엔지니어링은 도구와 가이드를 제공하여 강력해진 최신 AI 모델의 성능을 향상하고 안전하게 통제하는 기법이다. 에이전트나 스킬 등을 활용해 AI에게 '개목줄'을 채우고 교육하는 다양한 방법을 설명하며, 이를 통해 저렴한 AI 모델로도 높은 성능을 얻을 수 있음을 강조한다.

풀시청 판단

이 영상은 AI 에이전트 개발 및 활용에 관심 있는 개발자나 AI 프로덕트 매니저에게 유용하다. 과거 프롬프트 엔지니어링의 한계를 넘어 최신 AI 모델을 효과적으로 제어하고 활용하는 방법에 대한 직관적인 이해를 돕는다. 짧은 분량에도 불구하고 핵심 개념과 실제 적용 사례를 담고 있어, AI 기술의 최신 동향을 파악하려는 사람이라면 누구나 시청할 가치가 있다.

특히 핵심 내용 섹션의 ### 프롬프트 엔지니어링에서 하네스 엔지니어링으로, ### 하네스 엔지니어링의 핵심: 에이전트와 도구, ### 에이전트 직접 수정: 오마이파이(oh my pi) 사례 챕터를 통해 하네스 엔지니어링의 개념과 구체적인 적용 방식을 이해할 수 있다.

약점·한계: 영상은 하네스 엔지니어링의 개념과 중요성을 직관적으로 전달하지만, 구체적인 기술 구현 방법이나 심층적인 원리에 대한 설명은 부족하다. 짧은 시간 안에 많은 내용을 다루다 보니 각 사례의 깊이 있는 분석보다는 개괄적인 소개에 그친다. 또한, '판교 사투리'라는 유머 코드가 다소 가볍게 느껴질 수 있다.

핵심 내용

프롬프트 엔지니어링에서 하네스 엔지니어링으로

과거에는 AI가 주로 질문 답변에 특화되어 있었기에, 프롬프트를 다듬거나 검색 증강 생성(RAG)과 같은 기법으로 맥락을 제공하는 '프롬프트 엔지니어링'이 중요했다 [0:00]. 그러나 최근의 대규모 언어 모델(LLM)들은 훨씬 똑똑하고 다양한 작업을 수행할 수 있게 되었다. 이들은 마치 통제되지 않은 야생 동물처럼 강력하지만 예측 불가능한 행동을 할 수 있기에, AI에 '개목줄'을 채우고 교육하는 새로운 접근 방식이 필요해졌다 [0:14]. 이것이 바로 '하네스 엔지니어링'이다 [0:30]. 하네스 엔지니어링을 잘 활용하면 비싼 AI 모델 없이도 성능을 크게 향상시킬 수 있다는 연구 결과가 많다.

하네스 엔지니어링의 핵심: 에이전트와 도구

하네스 엔지니어링에서 가장 중요한 요소는 '에이전트'다 [0:46]. 에이전트는 AI가 파일 읽기, 수정, 웹 검색, 터미널 명령어 실행 등 다양한 '도구(tool)'를 자유롭게 사용할 수 있도록 돕는 프로그램이다 [0:52]. 즉, 에이전트는 AI가 사용할 도구를 붙여주고, AI가 이 도구들을 잘 활용하도록 가이드하는 역할을 한다.

하네스의 종류에는 에이전트 외에도 에이전트의 기능을 업그레이드하는 'MCP'(Mission Control Program)와 '스킬(skill)'이 있다 [1:50]. 예를 들어, GitHub MCP를 설치하면 AI가 GitHub에 직접 접속해 코드를 올리는 작업까지 수행할 수 있게 된다 [2:02]. 이처럼 AI를 통제하고 교육하는 모든 수단이 하네스의 범주에 포함된다.

에이전트 직접 수정: 오마이파이(oh my pi) 사례

하네스 엔지니어링을 하는 한 가지 방법은 Cursor 같은 에이전트를 직접 만들거나 수정하는 것이다 [2:14]. 처음부터 만들기 어렵다면 oh my pi처럼 기존 오픈소스 에이전트를 개조하는 방법도 있다 [2:31].

oh my pi는 pi라는 오픈소스 터미널용 에이전트를 가져와 코드 수정 방식을 개조한 사례다 [2:35]. 일반적인 에이전트는 AI에게 원본 코드와 수정 명령을 주고, AI가 출력한 수정 사항을 반영한다. 이때 git diff처럼 변경 사항을 출력하게 하거나, Claude Code처럼 변경 사항 전체를 출력하게 한 뒤 코드에서 찾아 교체하는 방식 등이 사용된다 [3:35].

하지만 oh my pi는 독자적인 방식을 택했다. 각 행에 무작위 문자를 강제로 넣은 후, LLM에게 코드를 어떻게 수정할지 출력하게 했다 [3:51]. 이렇게 AI가 뱉어낸 수정 사항을 파일에 반영하는 에이전트를 만들었더니, 놀랍게도 성능이 좋지 않은 LLM 모델을 사용해도 코딩 성능이 크게 향상되었다 [4:49]. 이는 하네스 엔지니어링이 LLM 자체의 성능을 뛰어넘는 효과를 낼 수 있음을 보여준다.

여러 에이전트 협업: Claude 에이전트 SDK 사례

Claude 역시 에이전트 개조를 적극적으로 활용한다 [4:57]. Claude 에이전트 SDK를 사용해 여러 에이전트가 각기 다른 역할을 수행하도록 만들어본 결과, 길고 복잡한 작업을 수행할 수 있었고, 실제 프로젝트에서도 만족스러운 결과가 나왔다 [5:00].

그러나 이런 식의 하네스 엔지니어링은 몇 가지 단점이 있다. 에이전트 구조와 코딩 지식이 필요하고 [5:14], 만든 하네스를 평가하려면 많은 실험 과정과 고성능 GPU 또는 상당한 비용이 필요하다 [5:22]. 또한, LLM 모델에 따라 특정 하네스와의 호환성이 떨어질 수 있다 (예: Claude의 LLM은 Claude Code 외의 하네스에서는 잘 작동하지 않을 수 있다) [5:26].

가벼운 하네스 엔지니어링: MCP, 스킬, 마크다운(MD) 파일

일상에서 더 가볍게 시도할 수 있는 하네스 엔지니어링도 있다. 기존 에이전트의 MCP나 스킬을 부분적으로 수정하는 방식이다 [5:39]. 예를 들어, OpenAI의 Codex에 크롬 개발자 도구 MCP를 부착하여 AI가 직접 브라우저를 조작하며 기능 작동 여부를 확인하게 만들 수 있다 [5:49].

또 다른 방법은 스킬(SKILL.md)이나 에이전트(AGENTS.md) 마크다운(MD) 파일을 활용해 AI에게 행동 지침을 교육하는 것이다 [6:40]. 예를 들어, PPT를 만들 때 특정 폰트 크기를 사용하지 말라고 지시하거나, 프로젝트 구조를 MD 파일에 정리하여 AI가 컨텍스트를 파악하기 쉽게 만들 수 있다 [6:48]. 에이전트가 동작하는 모든 단계에서 MD 파일을 통해 교육이 가능하다 [7:16].

그러나 MD 파일을 이용한 교육은 프롬프트에 길게 들어가는 방식이므로, 개에게 말로 복잡한 명령을 내리는 것과 같다 [7:21]. 간단한 명령은 잘 알아듣지만, 복잡해지면 AI가 중간에 잊거나 무시할 수 있다는 한계가 있다 [7:29].

주요 통찰·논점

AI 활용 패러다임의 변화: 통제와 확장

AI 활용 패러다임이 단순히 입력(프롬프트)을 잘 다루는 것을 넘어, 강력해진 AI 자체에 '개목줄'을 채워 통제하고, 도구(하네스)를 제공하여 능력을 확장하는 방식으로 변화하고 있다. 이는 AI 모델 자체의 성능을 높이는 것만큼이나 AI를 사용하는 '환경'과 '방법'의 중요성을 부각한다.

하네스 엔지니어링의 비용 효율성

하네스 엔지니어링은 비싼 고성능 LLM 모델에만 의존하지 않고도 AI의 작업 수행 능력을 크게 향상시킬 수 있는 방법을 제시한다. oh my pi 사례처럼 낮은 성능의 LLM도 효과적인 하네스와 결합하면 뛰어난 결과를 낼 수 있어, AI 개발 및 활용의 비용 효율성을 높이는 중요한 접근법이 된다.

두 가지 하네스 엔지니어링 접근법의 이해

하네스 엔지니어링은 에이전트 코드를 직접 수정하는 고난도 방식과, MCP/스킬/MD 파일 등을 활용하는 비교적 가벼운 방식 두 가지로 나눌 수 있다. 전자는 높은 자유도와 성능 개선 잠재력을 가지지만, 기술적 지식과 자원이 많이 필요하다. 후자는 접근성이 좋지만, 긴 프롬프트의 한계(망각, 무시)를 가질 수 있다. 각 방식의 장단점을 이해하고 프로젝트에 맞춰 선택하는 것이 중요하다.

인상적인 지점

  • "AI 강형욱이 되고 싶으면 뭘 어떻게 하는 건지 구체적으로 알아보도록 합시다." [0:41] — AI를 통제하고 교육하는 전문가라는 비유가 흥미롭다.
  • oh my pi 사례에서 "쓰레기 같은 LLM 모델을 가져와도 oh my pi를 갖다 쓰면 코딩 성능이 이만큼 향상된다"는 점 [4:49] — 하네스 엔지니어링의 강력한 효과를 직관적으로 보여준다.
  • "판교 용어 느낌으로 쓰시면 AI 시대를 선도하는 전문가 같아 보일 수 있구요. 내가 AI를 써 봤는데 별로다 이런 소리 하는 분들한테 니가 하네스를 못 다뤄서 그래 이런 식으로 유저 탓을 하면서 키보드 배틀을 이길 수도 있을 것 같구요." [5:02] — '하네스 엔지니어링'이라는 용어의 트렌디한 활용법을 유머러스하게 제시하여 인상적이다.
