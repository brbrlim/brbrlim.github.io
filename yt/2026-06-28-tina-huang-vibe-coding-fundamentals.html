TL;DR

이 영상은 AI 기반 개발 방식인 'vibe 코딩'의 기본 원칙을 소개한다. OpenAI 창립 멤버 Andrej Karpathy가 처음 사용한 이 용어는 거대 언어 모델(LLM)에 원하는 기능을 자연어로 지시하여 코드를 생성하는 방식이다. 영상은 효과적인 vibe 코딩을 위한 다섯 가지 핵심 원칙(철저한 사고, 틀의 이해, 버전 관리, 문제 해결, 맥락 제공)을 설명하고, Replit과 Windsurf를 활용한 실제 개발 사례를 보여주며 실용적인 개발 조언을 제시한다.

풀시청 판단

이 영상은 AI를 활용한 코딩, 즉 'vibe 코딩'에 관심 있는 개발 초심자나 기존 개발자 모두에게 유익하다.

  • 초심자: 코딩 경험이 없거나 적은 사람들은 AI를 활용한 개발 방식이 무엇인지, 그리고 이 과정에서 필요한 기본적인 개발 지식(예: 버전 관리, 파일 구조, 문제 해결 방식)을 배울 수 있다. AI 도구를 사용하여 아이디어를 실제 애플리케이션으로 구현하는 과정을 단계별로 시연하는 부분이 특히 도움이 된다.
  • 기존 개발자: AI를 개발 과정에 통합하는 방법에 대한 통찰력을 얻을 수 있다. 특히, AI가 구현에 탁월하다는 점을 인지하고 개발자는 더 높은 수준의 사고와 문제 정의, 그리고 맥락 제공에 집중해야 한다는 메시지는 의미가 있다. MVP(최소 기능 제품) 접근 방식과 '기능 구현' 및 '오류 문제 해결'이라는 두 가지 개발 모드에 대한 프레임워크는 효율적인 개발 습관을 구축하는 데 도움이 된다.

다만, 영상은 vibe 코딩의 '기본 원칙'에 중점을 두기 때문에 각 원칙이나 AI 도구 사용법에 대한 깊이 있는 기술적 설명은 기대하기 어렵다. Git/GitHub 사용법이나 프롬프트 작성 방법 등은 간략하게 소개될 뿐이므로, 심화 학습을 위해서는 별도의 자료를 찾아봐야 한다. 또한, 27분 36초부터는 스폰서 광고(Brilliant)가 시작되어 실제 콘텐츠는 27분경에 마무리된다.

핵심 내용

Vibe 코딩이란? Andrej Karpathy의 정의 [1:14]

vibe 코딩은 OpenAI의 창립 멤버인 Andrej Karpathy가 만든 용어이다. 그는 2025년 2월 3일 X(구 트위터)에 "Vibe 코딩이라는 새로운 코딩 방식이 있다. 당신은 기분(vibe)에 완전히 몸을 맡기고, 기하급수적 발전을 수용하며, 코드의 존재 자체를 잊어버린다"고 게시했다. 이는 거대 언어 모델(LLM)의 성능이 매우 향상되어, 개발자가 AI에게 무엇을 만들고 싶은지 자연어로 말하면 AI가 스스로 코드를 생성하는 방식이다. 예를 들어, "Daily Vibes라는 간단한 React 웹 앱을 만들어줘. 사용자는 이모지 목록에서 기분을 선택하고, 선택적으로 짧은 메모를 작성해 제출할 수 있어. 아래에는 날짜와 메모가 포함된 과거 기분 기록 목록을 보여줘"와 같이 명령하면 AI가 코드를 생성해준다 [1:51]. 이 방식은 개발 패러다임을 근본적으로 바꾸지만, AI가 모든 것을 마법처럼 해결하는 것은 아니며, 여전히 특정 원칙과 질서가 필요하다.

Vibe 코딩의 5가지 핵심 원칙 [2:45]

Replet의 'Vibe Coding 101' 강의에서는 vibe 코딩의 다섯 가지 기본 역량을 강조한다. 이는 사고, 틀(framework), 체크포인트, 문제 해결(debugging), 맥락(context)이다.

1. 철저한 사고: 4단계 사고를 통해 목표를 명확히 정의한다 [2:50]

무엇을 만들고 싶은지 철저히 생각하고 AI와 소통하는 것이 중요하다. 철저한 사고는 네 가지 단계로 구성된다.

  • 논리적 사고(Logical thinking): 무엇을 만들 것인가? (예: 체스 게임) [3:06]
  • 분석적 사고(Analytical thinking): 어떻게 플레이할 것인가? 주된 목표는 무엇인가? (예: 게임 목표) [3:10]
  • 계산적 사고(Computational thinking): 게임의 논리를 복잡한 문제 세트와 환경(예: 체스판 구성)에 어떻게 적용하고 규칙을 강제할 것인가? [3:17]
  • 절차적 사고(Procedural thinking): 어떻게 게임에서 탁월한 성과를 낼 것인가? (예: 전략 구상, 한계 돌파) [3:28]

대부분의 vibe 코더는 자연어를 사용하기 때문에 최종 제품에 대해 충분히 생각하지 않는 경향이 있어 이 부분에서 개선의 여지가 많다. 이 네 가지 사고 단계를 명확히 하고 AI에 명확하게 전달하는 가장 좋은 방법은 **제품 요구사항 문서(PRD, Product Requirements Document)**를 작성하는 것이다 [4:27]. 예를 들어, AI 기반 당뇨병 개인 맞춤형 영양 계획 앱을 만드는 PRD를 통해 각 사고 단계를 구체화할 수 있다. 논리적 사고는 프로젝트 개요에, 분석적 사고는 필요한 기술 목록에, 계산적 사고는 핵심 기능(예: 마일스톤)에, 절차적 사고는 대상 고객과 최적의 사용자 경험을 위한 세부 사항에 반영된다. ChatGPT를 활용하여 PRD를 작성하는 프롬프트도 제공된다 [6:47].

2. 틀(Framework)의 이해: AI에 올바른 방향을 제시한다 [7:09]

만들고자 하는 앱과 유사한 앱이 이미 존재할 가능성이 높고, AI는 기존 솔루션을 학습했기 때문에, AI에 올바른 틀이나 패키지를 지정해주면 훨씬 좋은 결과를 얻을 수 있다 [7:18]. 예를 들어, 웹 앱의 경우 React 백엔드와 Tailwind CSS를 사용한 프런트엔드를 지정하거나, 애니메이션 제작 시 3.js 패키지를 사용하라고 명시할 수 있다. 어떤 틀을 사용해야 할지 모를 때는 AI에게 먼저 물어보고 도움을 받을 수도 있다 [8:12]. vibe 코딩에서는 모든 구현 세부 사항을 알 필요는 없지만, 프런트엔드, 백엔드, 상호 통신 방식 등 프로젝트의 상위 수준 구조에 대한 이해는 필수적이다.

3. 버전 관리와 체크포인트: 예상치 못한 문제에 대비한다 [9:04]

개발 과정에서 문제는 필연적으로 발생하므로, 버전 관리(version control)와 체크포인트를 상시 유지하는 것이 중요하다. 모든 작업이 손실되는 최악의 상황을 피하기 위해 Git과 GitHub 같은 도구를 사용한다 [9:44]. Git은 버전 관리 소프트웨어 자체이며, GitHub는 코드를 클라우드에 저장하고 공유할 수 있는 웹사이트이다. 영상에서는 Git 초기화(git init), 파일 추적(git add .), 변경 사항 저장(git commit -m "..."), 변경 이력 확인(git log), 이전 버전 되돌리기(git reset) 등의 기본 명령어를 설명하고, GitHub에 로컬 저장소를 연결하고 푸시하는 방법도 간략히 소개한다 [9:49]. AI 코드 편집기를 사용하면 이러한 명령어를 자연어로 직접 AI에게 지시할 수 있으므로, 핵심은 이 상위 수준 구조와 흐름을 이해하는 것이다.

4. 문제 해결(Debugging): AI와 협력하여 문제를 진단하고 해결한다 [12:50]

코드를 작성하는 것만큼이나 문제를 해결하는 능력 또한 중요하다. 체계적이고 철저한 문제 해결 방식은 문제의 위치와 원인을 파악한 뒤 다양한 해결책을 적용하는 것이다. vibe 코딩에서는 문제가 발생했을 때 AI에게 직접 오류를 지적하고, AI가 해결책을 제시하도록 하는 것이 가장 효과적이다 [13:34]. 단순히 "작동하지 않아"라고 말하기보다는 오류 메시지를 복사하여 붙여 넣거나, 문제가 발생한 화면의 스크린샷을 제공하는 것이 좋다. AI가 즉시 문제를 해결하지 못하더라도 인내심을 갖고 여러 번 시도하게 해야 한다. 또한, 파일 구조와 파일 간의 상호작용 등 프로젝트의 기본 구조를 이해하고 있다면, AI에게 어떤 파일이나 섹션에서 문제가 발생했는지 정확히 알려주어 해결 속도를 높일 수 있다 [14:15].

5. 맥락 제공: AI에 충분한 정보를 제공하여 결과 품질을 높인다 [15:01]

AI에 더 많은 정보와 세부 사항, 즉 맥락을 제공할수록 더 나은 결과를 얻을 수 있다. 맥락은 다양한 형태로 제공될 수 있다 [15:13].

  • 상세한 초기 프롬프트 또는 PRD: 프로젝트의 목표, 기능, 기술 스택 등을 명확하게 정의한다.
  • 목업(Mockup): 원하는 앱의 시각적 형태를 보여주는 예시를 제공한다.
  • 예시 및 추가 데이터: AI가 애플리케이션을 구축하는 데 도움이 되는 구체적인 예시나 데이터를 준다.
  • 앱, 환경, 선호도 관련 세부 정보: 앱의 특징, 개발 환경, 선호하는 디자인이나 기능 등에 대한 정보를 제공한다.
  • 오류 보고: 단순히 "작동하지 않아"라고 말하는 대신, 전체 오류 메시지와 문제가 발생한 화면의 스크린샷을 함께 제공한다.

이 다섯 가지 원칙을 기억하기 위한 기억술로 "The friendly cat dances constantly (친근한 고양이가 끊임없이 춤춘다)"가 제시된다. 이는 각각 Thinking, Frameworks, Checkpoints, Debugging, Context를 의미한다 [15:41].

Vibe 코딩 도구 실습: Replit과 Windsurf [16:05]

영상은 Replit과 Windsurf 두 가지 도구를 사용하여 vibe 코딩 과정을 시연한다. 두 도구 모두 SEO 메타 태그를 시각적으로 확인하는 웹 앱을 만드는 예시를 사용한다.

Replit (리플릿) [16:05] Replit은 AI를 사용하여 다양한 애플리케이션을 빠르게 개발하고 배포할 수 있는 클라우드 기반 플랫폼이다. 초심자에게 매우 친숙하며 무료 크레딧을 제공한다.

  1. PRD 생성: 먼저 ChatGPT를 사용하여 SEO 태그 시각 검사기 앱의 PRD를 생성한다. 웹사이트의 HTML을 가져와 SEO 최적화 모범 사례에 따라 피드백과 태그를 제공하고, Google 및 소셜 미디어 미리보기를 보여주는 앱이다 [16:28].
  2. Replit에 프롬프트 입력: ChatGPT가 생성한 프롬프트와 이미지 목업(mockup)을 Replit에 입력하여 빌드를 시작한다 [18:24]. Replit은 파일 구조를 생성하고 시각적 요소를 디자인한다. Replit에는 자체 버전 관리 기능이 있지만, 최적의 방법은 Git을 사용하는 것이다 [19:01].
  3. 파일 구조 이해: Replit의 AI 어시스턴트에게 프로젝트의 파일 구조를 설명해달라고 요청하여, 클라이언트 측(React 앱)과 서버 측(index.ts, 라우트) 파일들이 어떻게 상호작용하는지 파악한다 [19:10]. 코드를 더 깊이 이해하고 싶다면 특정 코드 라인을 선택하여 설명을 요청할 수도 있다.
  4. 테스트 및 문제 해결: 완성된 앱을 테스트하며 오류를 발견한다. lonelyoctopus.com을 입력했을 때 오류가 발생하자, AI에 오류를 보고하고 자체적으로 해결하도록 맡긴다 [20:21]. 수정된 후에는 SEO 점수가 웹사이트에 따라 바뀌는지 확인하고, UI 디자인(예: 색상, 아이콘) 개선을 요청한다 [21:12]. 여러 변경 사항을 한 번에 요청하기보다는 하나씩 처리하는 것이 AI를 혼란시키지 않는 데 도움이 된다. 개발 URL을 통해 다른 기기에서 모바일 경험을 미리 확인할 수도 있다 [22:00].

Windsurf (윈드서프) (for Cursor) [22:27] Replit이 초심자에게 적합하고 빠른 개발 및 배포에 유리한 반면, Windsurf for Cursor 같은 AI 코드 편집기는 더 복잡하고 확장성 있는 개발에 적합하다. 더 많은 기능을 제공하지만, 환경 설정 및 배포 과정의 학습 곡선이 높다.

  1. 환경 설정: Windsurf 환경에서 Claude 3.7 Sonnet 모델을 사용한다. Replit과 동일한 프롬프트와 이미지를 입력하면, 로컬 개발 환경에서 필요한 파일과 패키지를 설정하는 데 시간이 더 오래 걸린다 [23:42]. 로컬 환경에서 실행되기 때문에 AI의 터미널 명령을 수동으로 수락하는 것이 안전하다.
  2. 테스트 및 개선: 앱이 빌드된 후 브라우저 미리보기에서 lonelyoctopus.com을 테스트한다 [24:40]. Windsurf가 생성한 첫 번째 버전이 Replit보다 시각적으로 더 유사한 결과물을 만들었다는 점을 언급한다. URL 입력 시 https://를 자동으로 추가하도록 AI에 요청하고, 이어서 복사-붙여넣기 기능도 활성화하도록 요청한다 [25:56].
  3. 버전 관리: Windsurf에서도 AI에게 git 초기화를 요청하여 버전 관리를 시작한다 [26:45]. AI가 자동으로 파일을 add하고 commit하는 과정을 보여주며, GitHub로 푸시할 준비를 마친다.

주요 통찰·논점

점진적 개발: 작게 시작하여 반복적으로 개선한다 (MVP) [27:36]

개발은 항상 '최소 기능 제품(MVP, Minimal Viable Product)'으로 작게 시작하고 점진적으로 확장해야 한다는 사고방식이 중요하다. 모든 기능을 한 번에 구현하려고 하기보다는, 가장 핵심적인 기능만으로 앱이 작동하게 만든 다음, 추가 기능과 세부 사항을 반복적으로 더해나가야 한다. 이는 오류를 줄이고 문제 해결 과정을 간소화하여 개발자의 좌절감을 막는 데 도움이 된다. 이는 비기술적 배경을 가진 사람들에게 특히 중요한 접근 방식이다.

두 가지 개발 모드: 기능 구현과 문제 해결 [28:24]

vibe 코딩 과정에서 개발자는 두 가지 모드 중 하나에 있다고 볼 수 있다.

  1. 새로운 기능 구현 모드: 이 모드에서는 새로운 기능과 관련된 맥락(context)을 충분히 제공해야 한다. 사용할 틀(framework)을 명시하고, 문서와 상세한 정보를 제공하며, 점진적인 변경과 버전 관리를 통해 진행한다.
  2. 오류 문제 해결 모드: 이 모드에서는 먼저 프로젝트의 구조를 잘 이해하고 있는지 확인해야 한다. 문제가 발생한 원인을 파악한 뒤, AI가 문제 해결에 도움이 되는 충분한 맥락(스크린샷, 오류 메시지, 특정 파일 지적 등)을 제공하여 AI가 해결책을 찾도록 돕는다.

이 프레임워크는 개발 과정에서 혼란스럽거나 답답할 때 현재 자신의 모드를 인지하고 적절한 조치를 취하는 데 도움을 준다.

시스템 규칙(Rule) 문서화: AI의 행동을 제어하고 보안을 강화한다 [29:34]

AI 코딩 에이전트에게 **시스템 프롬프트(system prompt)**와 같은 규칙 또는 문서(rules/documentation)를 제공하는 것이 유용하다. 여기에 AI가 해야 할 일과 하지 말아야 할 일을 명시할 수 있다. 예를 들어, 새로운 기능 구현이나 문제 해결 시 코드 변경을 최소화하도록 지시할 수 있는데, 이는 AI가 불필요하게 많은 파일을 변경하여 다른 문제를 유발하는 경향을 막기 위함이다 [29:48]. 또한, API 종단점(endpoint) 호출 횟수 제한, 모든 인증 및 가입 페이지에 캡차(CAPTCHA) 활성화 등 보안 및 비용 효율성을 위한 모범 사례를 규칙에 포함할 수 있다 [30:03]. 개발자는 이러한 규칙을 직접 작성하거나, 온라인에서 특정 앱 유형이나 언어에 특화된 규칙 파일을 찾아 활용할 수 있다. 특히 비기술적 배경을 가진 개발자는 API 키 노출 금지와 같은 기본적인 보안 원칙을 학습하고 이를 규칙 파일에 추가하여 AI가 보안 모범 사례를 따르도록 지시하는 것이 중요하다.
